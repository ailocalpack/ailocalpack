# Publishing

Publishing packs to the registry and the player's GitHub account: sign-in, the keychain, and later (tasks 59–63) the publish client, the publish flow and PR tracking. Part of the product spec in `CLAUDE.md` (_Publishing_): keep it current; record settled decisions in the matching section here.

## GitHub sign-in

(task 58, `Core/GitHub`) **OAuth App** in the `ailocalpack` organization with Device Flow on; its client ID is baked in (`GitHubOAuthApp.DefaultClientId`, public by design), there is no client secret anywhere. Scope **`public_repo`**: fork the registry, push a branch, open the PR, comment and react in Discussions (tasks 60–63); the narrowest classic scope that can push, nothing private is reachable. An OAuth App over a GitHub App: a GitHub App's user token can only write where the app is installed, so every player would have to install it on their own account for the fork. `GitHubDeviceFlow`: `StartAsync` posts `client_id` + `scope` to `<web>/login/device/code` (`Accept: application/json`) and returns `DeviceAuthorization` (device code, user code, verification URI, expiry from `expires_in` or 15 min, interval from `interval` or 5 s, never under 1 s; `ToString` hides the device code) or `Failed` (`Network`, `DeviceFlowDisabled`, `UnknownClient` for 404 / 401 / `incorrect_client_credentials`, `Unexpected`; a verification URI must be https). `WaitForTokenAsync` waits the interval before every poll of `<web>/login/oauth/access_token` (`grant_type=urn:ietf:params:oauth:grant-type:device_code`): `authorization_pending` → again; `slow_down` → the interval it names, else +5 s (never less than +5 s); `expired_token` or the clock past the expiry → `Expired`; `access_denied` → `Denied`; any other error → `Failed`; a network error, 5xx, 408 or 429 → logged and polled again until expiry; `Granted(token, scopes)` (`ToString` hides the token). The wait takes a delay function (default `Task.Delay` on the `TimeProvider`) so tests move a `FakeClock`. `GitHubUserClient.GetUserAsync(token)`: `GET <api>/user` with `Bearer`, `application/vnd.github+json` and `X-GitHub-Api-Version: 2022-11-28` (`CreateRequest`, the convention for every GitHub REST call) → `Found(GitHubUser(login, name or null, avatar, profile URL), scopes from X-OAuth-Scopes)`, `Unauthorized` (401), `Failed(isNetwork)`. `GitHubSession` ties them together: `StartSignInAsync`, `FinishSignInAsync` (wait → `/user` → token into the keychain as secret `github-token` → account into `<data>/github-account.json` → `Changed`; `Expired` / `Denied` / `Failed` / `NotSaved(user, keychain result)` when the keychain can't keep the token: the app stays signed out rather than keep it in plain text), `Account` (the remembered account, no network, no keychain), `CheckAsync` (`SignedIn` with the account refreshed from GitHub, `Unverified(remembered, detail)` when GitHub can't be reached, `SignedOut`, `Revoked(login)` when GitHub answers 401: token and account deleted, `KeychainProblem`; a token removed from the keychain by hand signs out), `GetTokenAsync` for the publish client, `SignOutAsync` (deletes the token, then the account; the account stays when the keychain refuses). **No revoke on sign-out**: GitHub's revoke API needs the client secret, so sign-out deletes the token here and points to `GitHubOAuthApp.ConnectionsPage` (`<web>/settings/connections/applications/<client id>`). `github-account.json`: machine-local like the token (`data`, not the roaming `config`), `schemaVersion` 1, `login`, `name`, `avatarUrl`, `profileUrl`, `scopes`, `signedInAt`; atomic; damaged → `.<utc>.bak` and signed out; a newer format reads as signed out and is never overwritten or deleted. Dev: `AILOCALPACK_GITHUB_CLIENT_ID` (a test OAuth App), `AILOCALPACK_GITHUB_URL=<url>` (a fake GitHub: `<url>/login/...`, API under `<url>/api/`). CLI: `github login [--no-browser]` (prints `Open <uri> and enter the code: <code>`, the scope and the code's lifetime, opens the browser unless `--no-browser`, waits; already signed in is a no-op, exit 0), `github whoami [--json]` (asks GitHub; prints login (name), profile, scopes, where the token is; exit 0 signed in, also unverified with a warning on stderr; 1 signed out, revoked (signed out) or a keychain problem; JSON `{state: signedIn|unverified|signedOut|revoked|keychainProblem, login, name, avatarUrl, profileUrl, scopes, keychain, problem}`), `github logout` (deletes the token, prints the connections page). Tests: Device Flow, `/user` and the session against `FakeHttpHandler` + `FakeClock` + `FakeSecretStore` (TestKit); the CLI end to end against `FakeGitHubServer` (an `HttpListener` on loopback) with `AILOCALPACK_SECRETS_FILE`.

## Keychain

(task 58, `Core/Secrets`) `ISecretStore` (`ReadAsync` / `WriteAsync` (create or replace) / `DeleteAsync` (Ok also when missing) by name → `SecretResult(Ok | NotFound | Unavailable | Failed, value, problem)`, never throws for store problems) with `Kind` for the Settings note. `SecretStores.Create(env)` picks the OS's store; the service name is `ailocalpack`, or `ailocalpack (<full AILOCALPACK_HOME>)` with a dev / test home so it never reads or replaces the player's real sign-in. Own code over a library: `Devlooped.CredentialManager` (GCM's stores repackaged) carries an OSMF EULA with a maintenance fee and a SponsorLink analyzer, wrong for an Apache-2.0 app; the OS calls are few. **Windows**: Credential Manager through `advapi32` (`CredReadW` / `CredWriteW` / `CredDeleteW`), generic credential `<service>:<name>`, UTF-8 blob, `CRED_PERSIST_LOCAL_MACHINE` (not roamed), no logon session → `Unavailable`. **macOS**: Security.framework generic passwords (`SecKeychainFindGenericPassword` / `Add` / `ItemModifyAttributesAndData` / `ItemDelete`: service + account = name) in the default keychain; finding an item for update or delete doesn't read its data (no prompt); the item's access list names the program that made it, so another build (an update, the CLI vs the app) gets the system's "allow access" prompt once; a locked keychain without a GUI (`errSecInteractionNotAllowed`) or no default keychain → `Unavailable`. **Linux**: the freedesktop Secret Service over the session D-Bus with Tmds.DBus.Protocol (the library Avalonia uses; no libsecret needed): `plain` session, items in the `default` alias collection with attributes `service` + `account`, label `<service> <name>`, `CreateItem` with replace; a locked item or collection is unlocked through the service's own prompt (`Prompt` + its `Completed` signal, at most 5 min; dismissed → `Failed`); no session bus, no Secret Service on the bus (`ServiceUnknown`, activation failed) or no default collection → `Unavailable` with how to get one (GNOME Keyring, KWallet, KeePassXC); a secret is never written to a file instead. `AILOCALPACK_SECRETS_FILE=<path>`: a plain-text JSON file store (`{service: {name: secret}}`, atomic) for dev and tests only; the app never sets it. Tests: `FakeSecretStore` (TestKit, in memory, `FailWith`), the file store, store selection; `KeychainSmokeTests` (explicit: `dotnet test --project tests/AiLocalPack.Core.Tests -- --filter-class *KeychainSmokeTests --explicit only`) writes, replaces, reads and deletes in the machine's real keychain under a throwaway service; run by hand on macOS and in a Debian container with gnome-keyring (also: no Secret Service → `Unavailable`, no bus → `Unavailable`, a locked keyring without a prompter → `Failed`); in CI from task 70.

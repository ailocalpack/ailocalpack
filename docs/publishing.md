# Publishing

Publishing packs to the registry and the player's GitHub account: sign-in, the keychain, the publish client (task 60), and later (tasks 61–63) the publish flow and PR tracking. Part of the product spec in `CLAUDE.md` (_Publishing_): keep it current; record settled decisions in the matching section here.

## GitHub sign-in

(task 58, `Core/GitHub`) **OAuth App** in the `ailocalpack` organization with Device Flow on; its client ID is baked in (`GitHubOAuthApp.DefaultClientId`, public by design), there is no client secret anywhere. Scope **`public_repo`**: fork the registry, push a branch, open the PR, comment and react in Discussions (tasks 60–63); the narrowest classic scope that can push, nothing private is reachable. An OAuth App over a GitHub App: a GitHub App's user token can only write where the app is installed, so every player would have to install it on their own account for the fork. `GitHubDeviceFlow`: `StartAsync` posts `client_id` + `scope` to `<web>/login/device/code` (`Accept: application/json`) and returns `DeviceAuthorization` (device code, user code, verification URI, expiry from `expires_in` or 15 min, interval from `interval` or 5 s, never under 1 s; `ToString` hides the device code) or `Failed` (`Network`, `DeviceFlowDisabled`, `UnknownClient` for 404 / 401 / `incorrect_client_credentials`, `Unexpected`; a verification URI must be https). `WaitForTokenAsync` waits the interval before every poll of `<web>/login/oauth/access_token` (`grant_type=urn:ietf:params:oauth:grant-type:device_code`): `authorization_pending` → again; `slow_down` → the interval it names, else +5 s (never less than +5 s); `expired_token` or the clock past the expiry → `Expired`; `access_denied` → `Denied`; any other error → `Failed`; a network error, 5xx, 408 or 429 → logged and polled again until expiry; `Granted(token, scopes)` (`ToString` hides the token). The wait takes a delay function (default `Task.Delay` on the `TimeProvider`) so tests move a `FakeClock`. `GitHubUserClient.GetUserAsync(token)`: `GET <api>/user` with `Bearer`, `application/vnd.github+json` and `X-GitHub-Api-Version: 2022-11-28` (`CreateRequest`, the convention for every GitHub REST call) → `Found(GitHubUser(login, name or null, avatar, profile URL), scopes from X-OAuth-Scopes)`, `Unauthorized` (401), `Failed(isNetwork)`. `GitHubSession` ties them together: `StartSignInAsync`, `FinishSignInAsync` (wait → `/user` → token into the keychain as secret `github-token` → account into `<data>/github-account.json` → `Changed`; `Expired` / `Denied` / `Failed` / `NotSaved(user, keychain result)` when the keychain can't keep the token: the app stays signed out rather than keep it in plain text), `Account` (the remembered account, no network, no keychain), `CheckAsync` (`SignedIn` with the account refreshed from GitHub, `Unverified(remembered, detail)` when GitHub can't be reached, `SignedOut`, `Revoked(login)` when GitHub answers 401: token and account deleted, `KeychainProblem`; a token removed from the keychain by hand signs out), `GetTokenAsync` for the publish client (the desktop app reaches the session through `IGitHubHost`, see _Settings → GitHub_ in `docs/desktop-app.md`), `SignOutAsync` (deletes the token, then the account; the account stays when the keychain refuses). **No revoke on sign-out**: GitHub's revoke API needs the client secret, so sign-out deletes the token here and points to `GitHubOAuthApp.ConnectionsPage` (`<web>/settings/connections/applications/<client id>`). `github-account.json`: machine-local like the token (`data`, not the roaming `config`), `schemaVersion` 1, `login`, `name`, `avatarUrl`, `profileUrl`, `scopes`, `signedInAt`; atomic; damaged → `.<utc>.bak` and signed out; a newer format reads as signed out and is never overwritten or deleted. Dev: `AILOCALPACK_GITHUB_CLIENT_ID` (a test OAuth App), `AILOCALPACK_GITHUB_URL=<url>` (a fake GitHub: `<url>/login/...`, API under `<url>/api/`). CLI: `github login [--no-browser]` (prints `Open <uri> and enter the code: <code>`, the scope and the code's lifetime, opens the browser unless `--no-browser`, waits; already signed in is a no-op, exit 0), `github whoami [--json]` (asks GitHub; prints login (name), profile, scopes, where the token is; exit 0 signed in, also unverified with a warning on stderr; 1 signed out, revoked (signed out) or a keychain problem; JSON `{state: signedIn|unverified|signedOut|revoked|keychainProblem, login, name, avatarUrl, profileUrl, scopes, keychain, problem}`), `github logout` (deletes the token, prints the connections page). Tests: Device Flow, `/user` and the session against `FakeHttpHandler` + `FakeClock` + `FakeSecretStore` (TestKit); the CLI end to end against `FakeGitHubServer` (an `HttpListener` on loopback) with `AILOCALPACK_SECRETS_FILE`.

## Keychain

(task 58, `Core/Secrets`) `ISecretStore` (`ReadAsync` / `WriteAsync` (create or replace) / `DeleteAsync` (Ok also when missing) by name → `SecretResult(Ok | NotFound | Unavailable | Failed, value, problem)`, never throws for store problems) with `Kind` for the Settings note. `SecretStores.Create(env)` picks the OS's store; the service name is `ailocalpack`, or `ailocalpack (<full AILOCALPACK_HOME>)` with a dev / test home so it never reads or replaces the player's real sign-in. Own code over a library: `Devlooped.CredentialManager` (GCM's stores repackaged) carries an OSMF EULA with a maintenance fee and a SponsorLink analyzer, wrong for an Apache-2.0 app; the OS calls are few. **Windows**: Credential Manager through `advapi32` (`CredReadW` / `CredWriteW` / `CredDeleteW`), generic credential `<service>:<name>`, UTF-8 blob, `CRED_PERSIST_LOCAL_MACHINE` (not roamed), no logon session → `Unavailable`. **macOS**: Security.framework generic passwords (`SecKeychainFindGenericPassword` / `Add` / `ItemModifyAttributesAndData` / `ItemDelete`: service + account = name) in the default keychain; finding an item for update or delete doesn't read its data (no prompt); the item's access list names the program that made it, so another build (an update, the CLI vs the app) gets the system's "allow access" prompt once; a locked keychain without a GUI (`errSecInteractionNotAllowed`) or no default keychain → `Unavailable`. **Linux**: the freedesktop Secret Service over the session D-Bus with Tmds.DBus.Protocol (the library Avalonia uses; no libsecret needed): `plain` session, items in the `default` alias collection with attributes `service` + `account`, label `<service> <name>`, `CreateItem` with replace; a locked item or collection is unlocked through the service's own prompt (`Prompt` + its `Completed` signal, at most 5 min; dismissed → `Failed`); no session bus, no Secret Service on the bus (`ServiceUnknown`, activation failed) or no default collection → `Unavailable` with how to get one (GNOME Keyring, KWallet, KeePassXC); a secret is never written to a file instead. `AILOCALPACK_SECRETS_FILE=<path>`: a plain-text JSON file store (`{service: {name: secret}}`, atomic) for dev and tests only; the app never sets it. Tests: `FakeSecretStore` (TestKit, in memory, `FailWith`), the file store, store selection; `KeychainSmokeTests` (explicit: `dotnet test --project tests/AiLocalPack.Core.Tests -- --filter-class *KeychainSmokeTests --explicit only`) writes, replaces, reads and deletes in the machine's real keychain under a throwaway service; run by hand on macOS and in a Debian container with gnome-keyring (also: no Secret Service → `Unavailable`, no bus → `Unavailable`, a locked keyring without a prompter → `Failed`); in CI from task 70.

## Publish client

(task 60, `Core/Publishing`) **`PackPublisher.PublishAsync(PublishRequest(local pack, target, registry, index?, game name?), IProgress<PublishStep>)`** submits a local pack (`LocalPackStore`) as a pull request from the player's fork, with the token from `GitHubSession.GetTokenAsync` and the player's login from `/user`; never throws except for cancellation, every step is idempotent, so publishing again after a failure continues where it stopped. Steps (`PublishStep`, the publish strip's mini-steps): **Fork**: `GET /repos/<registry>` (default branch), `POST /repos/<registry>/forks` with `default_branch_only` (GitHub answers with the existing fork, whatever its name: `registry-1`…), wait until the fork's default branch reads (404 / 409 → wait 1, 2, 4… ≤ 10 s, at most `ForkWait` = 3 min → `ForkNotReady`), `merge-upstream` (best effort: 409 / 422 logged); the base is the registry's default branch head. **Commit**: the target is resolved against the registry at that commit through the contents API: `PublishTarget.NewPack` → the local ID, else the first free `<id>-2`… among the language folder's packs (`PublishPayloads.FreeId`, ≤ 64); `PublishTarget.RevisionOf(id)` → its `manifest.json` read raw (`application/vnd.github.raw+json`); not there → `TargetGone`. The manifest (`PublishPayloads`, pure, decided): the content is the local pack's (agent, builds, recipe or patch, string table, fonts, dependencies, coverage), status `alpha`, dates in whole UTC seconds; **new pack** = revision 1 by the player, authors = the player (login + GitHub name when set) then the local pack's other authors (an update's base authors stay credited), created = updated = now; **new revision** = the existing pack's ID, title, created date and authors (the original author stays first), the player appended when not listed (case-insensitive logins), its revisions + one by the player (the local update's notes, "Update for build N: …"), dated now but never before the last one. The folder is staged under `<cache>/publish/` in the registry layout and checked with `PackValidator` (a failure → `Invalid` with the problems; nothing is sent). **Patch archives** (decided: they travel through the player's fork, since a pack PR may only touch its folder and the validator refuses ZIPs): the local archive (size + SHA-256 checked against the manifest) becomes an asset of the fork's Release tagged `patches` (made as a prerelease when missing; an asset of the same name is kept when its `digest` matches, else deleted and uploaded again), named `<game folder>-<language>-<id>-<revision>.zip` for the **published** ID and revision; the manifest's `patch.url` names the registry's own copy (`RegistryRepo.PatchUrl`, `https://github.com/<registry>/releases/download/patches/<name>`), which registry CI makes when it merges (_Registry CI and layout details_ in `docs/packs-and-registry.md`); the PR body links the fork's asset. Then the Git Data API on the fork: branch **`pack/<game folder>/<language>/<id>/rev-<N>`**; with an **open PR** from it (`GET /pulls?head=<login>:<branch>&state=open`) the commit goes **on top of the branch** (a fix: the same PR, `PATCH` the ref without force); without one (an earlier try, a closed PR) the branch is **reset** to a commit on the registry's head (force); blobs (base64) → tree on the parent's tree with the pack files and the folder's old files that are no longer in the pack deleted (`sha: null`; old files listed through the contents API) → commit (`<title>: new pack (<language>, <game>)` / `<title>: revision N (…)`) → ref (`POST /git/refs`; "already exists" → `PATCH`); a tree equal to the branch head's commits nothing (`Unchanged`). **Pull request**: the open one reused (`Resubmitted`), else `POST /pulls` against the default branch with `maintainer_can_modify` (422 "already exists" → the open one): title `New pack «<title>» · <language> · <game>` / `Revision N of «<title>» · …`, body = a table (pack folder, revision + notes, kind, coverage, agent, game build, test run, tried in game, fonts, dependencies), the patch archive's place and the license line (CC BY-SA 4.0; translations and a recipe only). The local report records `published {registry, packId, revision, pullRequest, pullRequestUrl, fork, branch, at}` (task 62 follows it). **Errors** (`GitHubRestClient`, conventions of `GitHubUserClient.CreateRequest`; `GitHubApiError(problem, status, GitHub's message + errors[].message, retryAt)`): 401 → `Unauthorized` ("sign in to GitHub again"); 403 / 429 with `x-ratelimit-remaining: 0` (until `x-ratelimit-reset`), a `retry-after` (now + seconds) or a "rate limit" message → `RateLimited` ("used up until HH:mm UTC; publish again after that"); other 403 → `Forbidden` (sign out and in again for `public_repo`); 404 (`NotFound`; at the fork step "The registry … isn't on GitHub"), 409 `Conflict`, 422 `Rejected` (GitHub's reasons), 5xx / 408 / no answer → `Network`; also `NotSignedIn`, `Keychain`, `OptedOut` (the index flags the game), `Invalid`, `TargetGone`, `ForkNotReady`, `Unexpected`; `PackPublisher.Explain` words each with the step. **Duplicate check** (`SimilarPacks.Find(index, local pack)`, for the similar-pack dialog, task 61): the index's packs of the game + language, the pack an update was made from first, then by 👍; a new revision is **recommended** (decided) for the update's base, for a pack that doesn't list the player's Steam build, or one that translates a smaller share. `RegistryRepo` = `ailocalpack/registry` or a test registry. CLI `pack publish <local pack folder | game/language/id> [--registry <owner/repo>] [--new | --revision-of <id>]`: warns when the pack wasn't tried in game; reads the index (`AILOCALPACK_INDEX_URL`; unreadable → warning, no duplicate check); similar packs and no choice → lists them (author, revision, status, coverage, builds, likes, "recommended: --revision-of <id>") and exits 1; prints `Forking <registry>...`, `Committing the pack...`, `Opening the pull request...`, then `Opened PR #N for <id> rev N: <url>` / `Pushed … to the open PR #N` / `PR #N already has …` and the branch (exit 0), or the message (+ validator problems) on stderr (exit 1). Tests: `FakeGitHubApi` (TestKit: an in-memory GitHub, repos sharing one object store, refs, Git Data API, contents, forks, merge-upstream, Releases and uploads, pulls, injected failures) behind `PackPublisherTests` (happy path, existing fork, fork not ready, stale branch, open PR fix, unchanged, PR made meanwhile, 403 rate limit, secondary rate limit, 422, retry after 502, missing registry, signed out, keychain, revoked, taken ID, revision credits and deleted files, gone target, invalid pack, opt-out, patch upload / URL / digest reuse), `PublishPayloadsTests`, `SimilarPacksTests`, `GitHubRestClientTests`; the CLI end to end through `FakeGitHubServer` (its `/api/` forwards to a `FakeGitHubApi`). Checked 2026-11-10 against the test registry `ailocalpack/registry-test` (default branch `main`, kept for tasks 61–62): without a choice the similar pack from the sample index was listed (exit 1); `--new` forked it into the player's account and opened PR #1 with only the pack folder, the player as author and `maintainer_can_modify`; publishing again pushed a second commit to PR #1; after merging it, `--revision-of full` opened PR #2 with rev 2 (the player already an author, not listed twice; `created` kept).

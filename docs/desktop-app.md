# Desktop app: screens and services

App structure, settings screen and sections, library, game page, packs tab, dialogs, add game folder, covers, startup, install flow, activity panel, tray and background. Part of the product spec in `CLAUDE.md`: keep it current; record settled decisions in the matching section here.

## Desktop app structure

MVVM with CommunityToolkit.Mvvm, `Microsoft.Extensions.DependencyInjection` (graph in `Composition`), view-model-first navigation (`INavigationService` back stack with Library as root; a page leaving the stack, or never shown because the same page is current, gets `PageViewModel.OnClosed` to unsubscribe from services; page views mapped by `DataTemplate`s in `App.axaml`, no reflection view locator). Back: chrome button, Esc (the page gets it first via `PageViewModel.TryHandleEscape`, e.g. to clear a search), Alt+←, mouse back button. Theme: Fluent + own tokens (`Styles/Theme.axaml`, colors from `design/drafts`); setting `System / Dark / Light`, default System (follows the OS, live).

## Settings screen

sections are DI singletons (`SettingsSection`, registered in `Composition` in list order; one without rows shows "coming in a later version"), each with groups of rows (`DropdownSettingRow`, `SegmentedSettingRow`, `ToggleSettingRow`) that edit `AppSettings` through `SettingsStore` and carry search keywords (`*_Keywords` resources). Search (`SettingsSearch`) is a case- and diacritics-insensitive substring match on label, keywords, group and section titles, in the UI language and in English. Deep link: `pages.Create<SettingsViewModel>(SettingsSectionId.X)`. A failed save logs and shows the stored value again. `SettingRow` texts (`Label`, `Help`, `SearchTexts`) are virtual, so rows can show data (paths, game names); rows a section creates at run time call `Detach()` when dropped. Preloaded at startup (`SettingsPreloader`, after the main window opens): language names and their sort order (ICU data, ~0.5 s on first use) load on a pool thread, then the section singletons are created on the UI thread, so the first visit has no pause. A section's own problems are `SettingsSection.Alerts` (`SettingsAlert`: tone card on top of the page with the fixing button), and the section keeps `BadgeCount` in step.

## Library screen

(`LibraryViewModel`, `Views/LibraryView`): `GameLibrary` (Desktop) refreshes the catalog in the background at startup (Steam scan with the settings' library choices → `GameCatalog.Refresh` → engine + anti-cheat `UpdateCatalog`; one at a time, a request during a refresh queues one more; never throws; keeps `LastScan` / `LastScanAt`); Steam games of an unavailable library are hidden from the grid (manual games with a missing folder stay, dimmed); the saved catalog shows at once, skeletons only while the first scan runs with an empty catalog. Grid = `CardGrid` panel (min 176 px, 18/22 spacing; 6 columns at 1280×800), 2:3 covers via `AspectBox`. Search uses `TextSearch` (same matching as Settings); sort `Important first` (default) / Recently played / By name. **Statuses** (task 21): `LocalizationStatuses.Resolve` (`Core/Library`, pure) per game and language, in order: registry `optOut` → blocked (opt-out); policy anti-cheat block not lifted by the registry's `antiCheatAllowed` → blocked (anti-cheat); a generation job (task 47) → generating / paused; an installed pack (task 29) → needs update when an update broke it (task 33), else installed; no index at all (first fetch running, registry never answered) → unknown (no badge, engine line, counted only in All); a pack in the exact language tag → pack available; else no pack. *Pack available* is decided from `index.json` alone (any pack of the language, whatever its builds): the manifest + hash check (`PackCompatibilityChecker`) runs on the Packs tab and at install (tasks 24, 29), not for every card. Packs rank (`Rank`, also the quick action's pick): made for the game's Steam build, `verified`, likes, works − doesn't work, newest update, ID. `Importance`: needs update → paused → generating → pack available → installed → no pack / unknown → blocked; ties by last played, then name. Card: badge (icon + text on a solid plate, tone per status; faded while the index is the saved copy), progress bar while a job exists, context line = 👍 likes of the best pack (when > 0, the Packs tab's measure; no ★ score exists) · pack count or its `verified` / `alpha`, ETA / pause reason, block reason (anti-cheat name, "Studio opted out"), else engine; quick action on hover / keyboard focus (Install, Update, View, Resume, Generate with AI; none for installed, blocked, unknown; off while any install operation runs): Install installs the best compatible pack in place (badge "Installing · N%" / "Uninstalling…" in accent with a bar along the cover; no installable pack → the game page's Packs tab), Update does the header's action in place (installs the later revision, or `Re-apply` (card label) for a pack that still fits; else the Generation tab), the others open the Generation tab until task 52 gives them their flows. "Translate to" picker = `AppSettings.GameLanguage` (System + every `GameLanguages` tag; edits the setting, follows changes made in Settings → General). Filter chips (All, Installed, Pack available, No pack, Needs update, Generating incl. paused) count over the whole library (search not applied), single choice, hidden without games; filter and search apply together; *Nothing found* says which hid the games and `Reset search and filter` clears both. Registry banner (warn, `Retry` = `PackIndex.RefreshAsync`) when the last fetch wasn't fresh: saved copy ("Showing data saved on <date>"), no copy ("Pack statuses appear once it answers"), newer format ("update the app"), invalid address. Avalonia objects (the placeholder brush, `PlaceholderColors.CreateBrush`) are made lazily on the UI thread: one created on a pool thread while a headless test sets Avalonia up takes the UI dispatcher from it. Covers: `CoverResolver` = Steam `appcache/librarycache/<id>/[<hash>/]library_600x900.jpg`, old flat `<id>_library_600x900.jpg`, our `<cache>/covers/steam-<id>.jpg`, then the Steam CDN (CDN miss remembered 7 days in `steam-<id>.miss`, network errors not); `CoverLoader` decodes off the UI thread, 4 at a time. VM updates from background events go through `IUiDispatcher`; folders open through `ISystemShell`. Tests: `TestServices.Build(steam: fixture => ...)` (fake Steam, no covers, immediate dispatcher, `FakeShell`).

## Game page

(`GamePageViewModel`, `Views/GamePageView`, design §3; task 22): opened with `pages.Create<GamePageViewModel>(game[, GamePageTab])`; the status comes from `GameStatuses` (Desktop singleton: anti-cheat policy + latest pack list + `GameLanguage` + `IInstalledPacks` = `StoreInstalledPacks` over `InstalledPackStore`: a game's one record counts for its own language only, its `InstalledPackProblem` from `InstalledPackMonitor` (see _Game update re-check_); `InstalledChanged` tells pages and cards to recompute; the library cards use the same, and jobs join there). Header: backdrop = the cover's colors (`CoverPalette`: ~4 000 opaque samples bucketed by 4 bits per channel; dominant = biggest bucket, darkened; two radial glows = buckets scoring best on size × saturation, ≥ 2 % of samples and ≥ 64 RGB apart; read through `Bitmap.CopyPixels` into a BGRA framebuffer; placeholder gradient until the cover loads), opacity per theme (`HeroBackdropOpacity` 0.55 dark / 0.22 light) and a fade into the page; cover 132 px; chips engine (hidden until detected), store (Steam / Added manually), version (`build 14,882,031` grouped, or `files hash <8 hex>` = SHA-256 over the sorted `path hash` lines). Primary action (`GamePrimaryActions.Resolve`, Core, pure): blocked / unknown → none; job → View progress (teal, caption % · ETA or pause reason); broken installed pack → Update to rev N when the registry has a later revision of the same pack (`InstalledPackState.Revision`), else Translate new strings; installed → Play (via Steam · with «…»; launches through `GameSessions`, then reads `Starting…` until the game's process shows up and `Running` with the caption "running since <time>" until it ends, disabled meanwhile; a launch problem shows as an amber line under the caption, cleared by the next press); pack available → Install best pack («title» · verified/alpha · "made for your version" when the index lists the game's build; file check is the Packs tab's); else Generate translation with AI. Words in `PrimaryActionTexts`. Install runs the install flow on the best compatible pack (see _Install flow_); Update to rev N installs the later revision through the install flow, Re-apply (`GamePrimaryActionKind.Reapply`: NeedsUpdate with a pack that still fits and no later revision; caption "Writes «…» rev N again from your files") re-applies; until their flows exist Generate / Translate / View progress open the Generation tab; library quick actions open the page on the same tabs (Install runs in place). The primary action is off while any install operation runs. Installed pack block (green / amber when broken; while an operation runs on the game: spinner, "Installing «…» · step N of M", the step, a bar; ⋯ menu: Re-apply, Show in Packs (Packs tab, the pack's language, the pack selected), Uninstall (restore originals); Rate joins with task 63; label "Installed · incompatible with the new version" / "Installed · not applied after the game update"), update banner (NeedsUpdate, worded per problem: incompatible "The game updated (build N)…", wiped "…put back the original files: «…» still fits but isn't applied…", re-apply failed + the reason; `Translate new strings` (incompatible) or `Re-apply` (fits) only when the header offers the update, `Details` after a failed automatic re-apply), rating prompt slot (task 63). Tabs: Packs (count; see _Packs tab_; hidden for blocked games), Generation (% while a job runs; content tasks 52–55), Audio / Textures muted with a "soon" pill but selectable, showing the coming-soon illustration. Default tab: Generation while a job exists, else Packs. Sticky bar: a copy of the tab bar with mini cover, name and the primary action, shown once the in-flow tab bar scrolls under the top (`IsTabBarStuck`, set by the view). The page follows the catalog, pack list, target and UI language while open. **Blocked game** (task 23, design §3a): `GameBlocks.Resolve` (Core, pure; also used by `LocalizationStatuses`) = registry opt-out, else a policy anti-cheat block not lifted by the registry's `antiCheatAllowed` → `GameBlock` (reason, anti-cheat ID and name); the page keeps the header with a greyscale cover, placeholder and backdrop (`BitmapPixels`, Rec. 601 luma; the grey copy is made with the palette so a block arriving later needs no reload), no action, no installed block, and shows the red panel (anti-cheat name or opt-out text) instead of the tabs and the sticky bar. `Report` opens `BlockReport.IssueUri` (new issue in `ailocalpack/registry`, English title + body percent-encoded: game, ID, store, reason, anti-cheat + the file `AntiCheatDetector` finds when clicked, app version) through `ISystemShell.OpenUrl` (https only). Guard: install (tasks 27, 29) and generation (task 47) services call `GameBlocks.EnsureAllowed(game, policy, index, BlockedOperation)` first, which throws `GameBlockedException` (game, operation, block) for a blocked game whatever the UI showed.

## Packs tab

(`PacksTabViewModel` + `PackRowViewModel` in `ViewModels/GamePage`, `Views/PacksTabView`, design §4; task 24): list of registry packs of the game in one language + details panel of the selected one (first selected by default). Toolbar: language popover (search on native name, English name, tag; every `GameLanguages` tag with this game's pack count or "—", languages with packs first by count, current highlighted; picking one changes only the tab, not `GameLanguage`; the tab follows the setting while the player hasn't picked another language), sort `Status, rating` (= `LocalizationStatuses.Rank`, default) / `Newest` (updated) / `Coverage` (ratio), ties in rank order, selection kept; count "Русский: 3 packs". Row: title, Installed tag (amber `rev N · rev M available` when broken), author · verified/alpha · 👍 · compatibility (icon + text; "checking…", "not checked" on a failed manifest), incompatible rows dimmed. Manifests are fetched only once the tab is shown (never for a blocked game): the selected pack first, then the rest of the list one at a time, each checked with `PackCompatibilityChecker` off the UI thread (file hashes saved); a game change (build, availability, folder) checks again. `PackManifestClient` (Core/Registry): manifest path resolved against the index location (local folder or https only, else refused), one GET (15 s, no retries, 8 MB cap); `PackManifestProblem`: Offline / Timeout / HttpError (may pass), FileMissing (local file absent, HTTP 404 / 410), Invalid (with the format errors), NewerFormat, Mismatch (ID, game or language differ from the index entry). Desktop `PackManifests` caches loaded manifests per session by index URL + path + revision (failures not kept). Details: status · rev · 👍, compatibility box (green / amber / red, neutral while checking; words in `PackCompatibilityTexts` from the reason and its data), or the failure box with `Retry` (offline, server error, missing; not for damaged / newer); author, made with (agent name + model, or "By hand"), coverage (rounded down) with a bar, reports (works / doesn't work), updated, fonts (whitelist name + "(bundled)" / "(downloaded when installing)", an unknown ID as is) and requires (the whitelist's name + version "(downloaded from the official release)", one off the whitelist "(not on the registry's list of allowed components)"), revisions N ▸ expanding newest first; `Install` enabled only for a checked compatible / probably compatible pack while the list is current, no install operation runs and it isn't the installed one (that one shows `Installed ✓` + `Uninstall (restore originals)`; the pack being installed shows an accent `installing` tag and `Installing…`); hint: incompatible → "Install is unavailable…" + `Translate with AI` (Generation tab), offline → available once the registry is reachable, another installed → "Replaces the installed «…»"; `Reviews on GitHub ↗` when the index has a discussion. `Install` raises `PacksTabViewModel.InstallRequested` (the row, with its manifest and check), `Uninstall` `UninstallRequested`; the game page runs the install flow; `SetInstallState(busy, installingPackId)` / `ShowPack(language, id)`. States: no pack list ("hasn't loaded yet"), no packs in the language (dashed empty state, `Generate with AI`, "Available in other languages: Deutsch (1)" links switching the language), saved list (warn banner with the save date and `Retry`, list faded, install off). The Mine section comes with task 55.

## Dialogs

(`Dialogs/`): one modal dialog at a time, `IDialogService.Show<T>(args)` (created with `ActivatorUtilities`) / `Close`; `MainWindow` draws it over a scrim, the page and chrome are disabled meanwhile, back is off; Esc goes to `DialogViewModel.TryHandleEscape`, else closes; `OnClosed` stops background work. Each dialog view model maps to its view by a `DataTemplate` in `App.axaml`. OS pickers go through `IFilePicker` (tests: `FakeFilePicker`). Destructive actions confirm with `ConfirmDialogViewModel` (`ConfirmRequest`: question, what stays, red confirm button; Cancel has the focus).

## Add game folder

(`AddGameDialogViewModel`, `Views/AddGameDialogView`, design §2): opened by `+ Folder` (step 1) or by dropping a folder (a dropped file stands for its folder) on the library (dashed overlay, straight to the search). `GameFolderAnalyzer` (Desktop, off the UI thread): `FolderRecognizer.Scan`, then per game anti-cheat detection, `FolderRecognizer.ListExecutables`, `FolderSize`, `GameIconExtractor`, version then fingerprint (hashes saved to the cache). The search starts in the one-game checklist (executables, engine, fingerprint N of M files, registry lookup "in a later version" until tasks 21 / 29) and switches to *Scanning* when a second game turns up (folders scanned N of M, games streaming in, `Stop and show` ends the search and keeps what was found; then each game is analyzed, "Checking game 2 of 5"). Progress posts from the worker are queued while the final result comes back inline, so late posts must not move the step back. No games → step 1 with an error and the hint open; too large (no games) / missing / unreadable → step 1 with an error. One game: its summary (`GameSummaryViewModel`, one per game, so edits survive Previous / Next): cover (icon or picked image), name with ✎ rename, chips (engine, main executable, files · size), path + `Other folder` (one game only), notices (game in a subfolder, already in the library / added, anti-cheat, engine unknown, registry note), *Edit game details* (name, engine with detected / not detected, main executable, cover; open by itself when the engine is unknown). Already in the library = same fingerprint or same folder (any source) → `Open game page`; anti-cheat → `Add as unavailable` (stored anti-cheat ID, the card shows blocked). The fingerprint always uses the detected engine (same ID on every machine); a chosen engine is only stored in `Game.Engine`; another main executable is hashed again on Add. Add → `GameCatalog.AddManual` (cover saved first) → dialog closes → the game page. Several games ("Add games"): *Overview* (step 2 of 3) = "Found N games in «X»", tally by `FolderGameKind` (new / with anti-cheat / already in the library / can't be read; pack statuses come with tasks 21 / 29), notices (stopped, size limit, Steam library), cover strip numbered in review order (only new and anti-cheat games are reviewed; others are dimmed and skipped automatically; clicking a cover starts there), the "one game at a time" note, collapsed skipped folders with their reason; `Back` / `Start adding` (from the first game not reviewed yet). *Review* ("Game 2 of 5") = the summary plus a segmented progress bar (added / skipped / current), `‹ All games` (keeps the choices), `Previous` / `Skip` / `Add ›` (or `Add as unavailable ›`; a game already added or found in the library on Add shows `Next ›`); adding moves to the next game, after the last one comes the *Result* (step 3 of 3): "Added N games" / "No games added", a line per game (added, added as unavailable, skipped, already in the library, can't be read), `To library` (closes the dialog on the root page). Closing midway keeps what was added. Library cards of manual games have "Remove from library" (catalog + stored cover; the folder stays).

No drive label (volume names aren't portable); origin is shown instead.

## Manual game covers

(`ManualCoverStore`): `<data>/covers/<id with : → ->.cover|icon.<ext>` (`AppPaths.GameCovers`; data, not cache, since a picked image can't be fetched again), one per game, picked image wins. `CoverLoader` reads it before the Steam resolver; an icon (`CoverImage.IsIcon`) is drawn small on the placeholder gradient with the name, not cropped to 2:3.

## Startup

(`Desktop/Startup`, design §9): `AppStartup` runs the steps and reports them as `StartupProgress` (`StartupStep`: ID, phase `Blocking` / `Background`, status Waiting / Running / Done / Skipped, tone Ok / Warn, localized label and result line). Blocking, in order, files read on the thread pool: settings (`SettingsStore.Load`, then `SettingsApplier.Start`; result = UI language · theme), game catalog (`GameCatalog.Load`; `LoadOutcome` Missing → skipped, Corrupted / Unreadable → warning). Background, after the main window opens: pack list (`PackIndex.RefreshAsync`: fresh → "N packs"; stale → warning "Offline: showing the saved list from <date>"; else a warning for unreachable / newer format / invalid address), Steam scan and engine + anti-cheat detection, both from one `GameLibrary` refresh (`GameLibrary.Progressed`: `GameLibraryScanned` → `GameLibraryDetected(n)`, or `GameLibraryRefreshFailed`); no libraries → "Steam not found" (skipped), new games named unless every game is new, nothing to detect → skipped. A failing step logs and ends as a warning; the app goes on. `App` keeps `ShutdownMode.OnExplicitShutdown` until the main window opens; the `SplashWindow` (`SplashViewModel`) shows only if the blocking phase takes over 0.2 s, stays ≥ 0.7 s, opens its details after 3 s on one step; closing it quits. Chrome: `Checking for changes…` + spinning ring on 🔔 while a background step runs, the Activity panel lists the background steps under *Running* while they run (see _Activity panel_). Library banner for a corrupted catalog (`GameCatalog.CorruptedBackupPath`), dismissible. Blocking step *Finishing an interrupted install* (task 27) between settings and catalog, present only when a journal exists (`PackInstaller.HasInterruptedTransaction`, checked when `AppStartup` is built): running line "Don't close the app"; rolled back → warning, completed / uninstall finished → ok, failed → warning "retried on the next start". Background step *Checking installed packs* (`PacksStep`) starts once the library refresh and the pack list are both done: no packs → skipped, a pack needing the player → warning naming the games, re-applied → ok naming them, else "N packs in place". Background step *Checking generation jobs* (task 47, see _Generation jobs_). Steps of later tasks (app updates 67) join `AppStartup` with their task.

## Install flow

(Desktop `Install/`, design §4a; task 29): `PackInstallService` (singleton, one operation at a time, never throws; `Current` = `InstallOperation` (game, kind Install / Reapply / Uninstall, pack, title, steps, step index, fraction, `Percent`), `Changed` from a pool thread) runs **Install**: `GameBlocks.EnsureAllowed` → Download (`PackFetcher` into the cache) → recipe tool must be supported (a patch pack needs none) → Dependency (step added only when the manifest names one: `DependencyPreparer` looks each up in the index's whitelist (off it → `DependencyUnknown`), picks the release file for the game build's platform (no file → `DependencyPlatform`), downloads it into the cache and unpacks it into staging (`DependencyFetch` / `DependencyArchive`); one installed already in the version is shared, not downloaded; all before anything is removed, so a failed download leaves the installed pack) → RemovePrevious (the game's other pack is uninstalled first, whatever its language: one pack per game; dependencies the new pack names are kept for it, and removed again if the new pack then fails) → Check (`PackCompatibilityChecker` on the cached manifest, against the originals; incompatible stops) → Rebuild (`IRecipeTool.Rebuild` in the table's language from the player's own files into `<cache>/staging/<random>`, deleted afterwards; a patch pack: Patch, `PatchApplier` into the same staging, see _Binary patches_) → BackUp / Write / Verify (`PackInstaller.Install` with the changed files and the rebuild's generated files; its stages map onto the steps). **Re-apply** = the installed revision from the cache (else the registry while it lists that revision) rebuilt from the current files, its dependencies unpacked again → `PackInstaller.Reapply`. **Uninstall** = `PackInstaller.Uninstall` (step Restore). Result `InstallOutcome` (error `InstallError`: kind Busy / Blocked / NotInRegistry / Fetch / Incompatible / Patch / DependencyUnknown / DependencyPlatform / DependencyFetch / DependencyArchive / InvalidStrings / Recipe / Font / Transaction / Unexpected with the fetch problem, check, transaction failure, file, OS detail; `FilesRestored`, `CanRetry`) carries a log in the UI language (timestamped lines; the OS detail indented). `InstallFlow` (singleton, events on the UI thread; `IsBusy` also covers the check before an install): `InstallAsync(game, pack[, manifest, check])` checks when not given (`PackManifests`), builds the risk list (`InstallRisks.For`, Core, pure: alpha, probably compatible, each dependency, replaces the installed pack of any other ID or language; empty = no dialog) and shows `InstallConfirmDialogViewModel` (risk lines, amber for alpha / probably compatible, "Original files are backed up; you can uninstall.", Cancel focused) or installs at once; `InstallBestAsync(game, noPack)` = `BestPack.PickAsync` (Core: ranked packs checked in order, first compatible wins and stops the checks, else the first probably compatible, unreadable skipped; none → `noPack`); `Uninstall(game)` asks with `ConfirmDialogViewModel` (original files restored, pack stays in the registry, saves untouched); `ReapplyAsync(game)`. Toasts (`ToastService`, bottom right of the main window, newest last, at most 3, one per game key, stay until closed; actions close the toast, then run): done "Installed: «…»." (+ "In the game, choose English as the language." when the rebuild gave `InGameLanguage`, also logged; native language name) `▶ Play` (`GameSessions.LaunchAsync`; a launch problem becomes a toast) · `Undo` (uninstall without asking); uninstalled / re-applied info; failure "Couldn't install; files restored." (or "…restoring files failed. The app retries on the next start.") `Retry` (when it may help; repeats the confirmed operation without asking again) · `Details` (`InstallDetailsDialogViewModel`: plain reason from `InstallTexts.Reason`, e.g. "<file> is in use; the game seems to be running. Close it and retry.", whether files were restored, the log, Close / Retry). Every outcome is also recorded in the Activity panel (see _Activity panel_).

## Activity panel

(task 38, design §5): Core `Core/Activity`: `ActivityEvent` (ID, `ActivityEventKind`: PackInstalled / PackUninstalled / PackReapplied / PackAutoReapplied / InstallFailed / UninstallFailed / ReapplyFailed = feed; AutoReapplyFailed / PackIncompatible / PackNotApplied = decisions; game ID + name, pack ID, title, revision, failure `Detail` (reason in the UI language of the moment) + `Log` + `FilesRestored` + `CanRetry`, `Key`, `IsDecision`, `IsRead`, `IsHidden`; tone from the kind: Ok / Info / Attention / Bad; texts are worded by the app from kind + data, so they follow the UI language). `ActivityStore` (thread-safe, `Changed`): events in `<data>/activity.json` (`AppPaths.ActivityFile`, `{schemaVersion: 1, events: [...]}`, kind camelCase; unknown kinds and broken entries skipped; damaged → `.bak` + empty; unreadable or newer → not written this session; atomic; failed save logged), newest first, feed capped at 200 (decisions never dropped); `Add` refuses an event whose `Key` is known whatever happened to it (set aside, hidden), so a finding found again at every start is added once (key = problem + game + pack + revision + install time of the record); `MarkRead`, `MarkAllRead` (feed only, never decisions), `Hide` (feed only; kept as hidden for its key), `DecideLater` / `Resolve` (decision → feed, read), `ResolveGame(game, which)`; running `ActivityTask`s (kind, game, title, step, fraction, started, `Pause` / `Cancel` hooks) in memory only. `ActivityBadge.Of(decisions, running, unread)`: amber with the decisions when any, else running + unread, else none. `ActivityFeed.ByDay(events, now, zone)`: local calendar days of the zone (`TimeProvider.LocalTimeZone`), Today / Yesterday / Earlier, newest first, a future event counts as today. Desktop `ActivityRecorder` (singleton, resolved before the background checks start): `PackInstallService.Current` → the one running task (title "Installing «…» · step N of M", step, percent); `InstallFlow` records every outcome of an operation the player started (a Busy refusal isn't; failures go to the feed: the player saw their toast); `InstalledPackMonitor.Rechecked` (every re-check result): re-applied by itself → feed, re-apply failed → decision (`Retry` when it may help, `Log`), incompatible → decision (`Update to rev N` when the registry has a later revision of the same pack, else `Translate new strings` → Generation tab), wiped with re-apply off → decision (`Re-apply`); any successful operation on a game, or a re-check finding its pack intact, settles that game's pack decisions. ## Tray and background

(task 39, `Desktop/Background`, Core `Core/Background`): all of it follows `AppSettings.RunInBackground` (default on). **Autostart** (`IAutostart`, `Autostart.For(env, IWindowsRegistryWriter)`, `Autostart.Sync(entry, enabled, command)` writes only when the stored text differs, so a moved app is fixed, and removes when off): Windows `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` value `ailocalpack` (executable quoted, arguments quoted as `CommandLineToArgvW` splits them); macOS LaunchAgent `~/Library/LaunchAgents/io.github.ailocalpack.plist` (`RunAtLoad`, no keep-alive; decided over `SMAppService`, which needs a signed bundle); Linux `$XDG_CONFIG_HOME/autostart/ailocalpack.desktop` (absolute XDG value, else `~/.config`; `Exec` quoted and escaped per the Desktop Entry spec). Command (`AutostartCommand.ForCurrentProcess` over `AppLaunch.ForCurrentProcess`) = `$APPIMAGE` when set, `dotnet <dll>` for a framework-dependent run, else the process's own executable, plus `--background`; with `AILOCALPACK_HOME` set (dev, tests, portable) the entry is never touched (`AutostartTarget(null)`). **Start** with `--background`: no splash, the window stays hidden while the tray is on (else it shows). **Single instance** (`SingleInstance`, before Avalonia starts): `<data>/app.lock` held exclusively + a Unix socket `<temp>/ailocalpack-<16 hex of SHA-256 of the data path>.sock`; a later start sends `show` (not when it was started with `--background`) and exits 0, so a throwaway home runs beside the real app. **Tray** (`TrayHost`, Avalonia `TrayIcon`, icon `Assets/tray.png`): menu Open ailocalpack / Check for game updates / Quit, a click opens the window; shown while the setting is on and the desktop has a tray (Linux: `org.kde.StatusNotifierWatcher` owned on the session bus, KDE incl. Steam Deck; GNOME needs the AppIndicator extension; without one closing quits); while shown `ShutdownMode.OnExplicitShutdown` and closing the window by the player (`WindowCloseReason.WindowClosing`, not programmatic) hides it (`CloseToTray.ShouldHide`); the macOS Dock icon (`IActivatableLifetime` Reopen) reopens it; turning the setting off brings a hidden window back. **Background re-check** (`BackgroundChecks`, only while the setting is on, else packs are checked at start only): `RecheckScheduler` (Core, clock from `TimeProvider`, ticked every 30 s by a `PeriodicTimer`) runs a `GameLibrary` refresh (which re-checks the packs, see _Game update re-check_) every 6 h since the last run and 2 min after the last change reported by `SteamManifestWatcher` (Core/Steam: `FileSystemWatcher` on each available library's `steamapps`, `appmanifest_*.acf` written / created / renamed / deleted; re-pointed after every scan); runs never overlap, a change during a run makes one more after it; tray menu *Check for game updates* runs at once. **OS notifications** (`ISystemNotifications`, `SystemNotifications.Create`; never throw): Windows 10+ toast through WinRT over raw COM vtables (no Windows SDK projection, one cross-platform target framework), identity `io.github.ailocalpack` registered under `HKCU\Software\Classes\AppUserModelId` (display name + `<data>/notification-icon.png`) + `SetCurrentProcessExplicitAppUserModelID`, click = the toast's `Activated` while the app runs (no COM activator: a toast clicked after the app quit does nothing); macOS `UNUserNotificationCenter` through the Objective-C runtime (permission asked at start while the window shows and the tray is on, `ISystemNotifications.Prepare`, since macOS prompts only an app in front; `ActivityNotifier` on `ActivityStore.Added`): a new, not hidden event while the window isn't active (hidden in the tray, minimized, another app in front) and the tray setting is on, by category: decision → `NotifyNeedsDecision`, feed (done or failed) → `NotifyTaskFinished`, `NotifyCommunity` for tasks 62–64; title = the panel title, body = game · detail line; a click shows the window and opens the event like its panel row (`ActivityPanelViewModel.OpenEvent`).

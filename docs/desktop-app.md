# Desktop app: screens and services

App structure, settings screen and sections, release packages, library, game page, packs tab, dialogs, add game folder, covers, startup, install flow, activity panel, app icon, tray and background. Part of the product spec in `CLAUDE.md`: keep it current; record settled decisions in the matching section here.

## Desktop app structure

MVVM with CommunityToolkit.Mvvm, `Microsoft.Extensions.DependencyInjection` (graph in `Composition`), view-model-first navigation (`INavigationService` back stack with Library as root; a page leaving the stack, or never shown because the same page is current, gets `PageViewModel.OnClosed` to unsubscribe from services; page views mapped by `DataTemplate`s in `App.axaml`, no reflection view locator). Back: chrome button, Esc (the page gets it first via `PageViewModel.TryHandleEscape`, e.g. to clear a search), Alt+←, mouse back button. Theme: Fluent + own tokens (`Styles/Theme.axaml`, colors from `design/drafts`); setting `System / Dark / Light`, default System (follows the OS, live).

## Settings screen

sections are DI singletons (`SettingsSection`, registered in `Composition` in list order; one without rows shows "coming in a later version"), each with groups of rows (`DropdownSettingRow`, `SegmentedSettingRow`, `ToggleSettingRow`) that edit `AppSettings` through `SettingsStore` and carry search keywords (`*_Keywords` resources). Search (`SettingsSearch`) is a case- and diacritics-insensitive substring match on label, keywords, group and section titles, in the UI language and in English. Deep link: `pages.Create<SettingsViewModel>(SettingsSectionId.X)`. A failed save logs and shows the stored value again. `SettingRow` texts (`Label`, `Help`, `SearchTexts`) are virtual, so rows can show data (paths, game names); rows a section creates at run time call `Detach()` when dropped. Preloaded at startup (`SettingsPreloader`, after the main window opens): language names and their sort order (ICU data, ~0.5 s on first use) load on a pool thread, then the section singletons are created on the UI thread, so the first visit has no pause. A section's own problems are `SettingsSection.Alerts` (`SettingsAlert`: tone card on top of the page with the fixing button), and the section keeps `BadgeCount` in step.

## Library screen

(`LibraryViewModel`, `Views/LibraryView`): `GameLibrary` (Desktop) refreshes the catalog in the background at startup (Steam scan with the settings' library choices → `GameCatalog.Refresh` → engine + anti-cheat `UpdateCatalog`; one at a time, a request during a refresh queues one more; never throws; keeps `LastScan` / `LastScanAt`); Steam games of an unavailable library are hidden from the grid (manual games with a missing folder stay, dimmed); the saved catalog shows at once, skeletons only while the first scan runs with an empty catalog. Grid = `CardGrid` panel (min 176 px, 18/22 spacing; 6 columns at 1280×800), 2:3 covers via `AspectBox`. Search uses `TextSearch` (same matching as Settings); sort `Important first` (default) / Recently played / By name. **Statuses** (task 21): `LocalizationStatuses.Resolve` (`Core/Library`, pure) per game and language, in order: registry `optOut` → blocked (opt-out); policy anti-cheat block not lifted by the registry's `antiCheatAllowed` → blocked (anti-cheat); a generation job (task 47) → generating / paused; an installed pack (task 29) → needs update when an update broke it (task 33), else installed; no index at all (first fetch running, registry never answered) → unknown (no badge, engine line, counted only in All); a pack in the exact language tag → pack available; else no pack. *Pack available* is decided from `index.json` alone (any pack of the language, whatever its builds): the manifest + hash check (`PackCompatibilityChecker`) runs on the Packs tab and at install (tasks 24, 29), not for every card. Packs rank (`Rank`, also the quick action's pick): made for the game's Steam build, `verified`, likes, works − doesn't work, newest update, ID. `Importance`: needs update → paused → generating → pack available → installed → no pack / unknown → blocked; ties by last played, then name. Card: badge (icon + text on a solid plate, tone per status; faded while the index is the saved copy), progress bar while a job exists, context line = 👍 likes of the best pack (when > 0, the Packs tab's measure; no ★ score exists) · pack count or its `verified` / `alpha`, ETA / pause reason, block reason (anti-cheat name, "Studio opted out"), else engine; quick action on hover / keyboard focus (Install, Update, View, Resume, Generate with AI; none for installed, blocked, unknown; off while any install operation runs): Install installs the best compatible pack in place (badge "Installing · N%" / "Uninstalling…" in accent with a bar along the cover; no installable pack → the game page's Packs tab), Update does the header's action in place (installs the later revision, or `Re-apply` (card label) for a pack that still fits; else the Generation tab), the others open the Generation tab (its start form or the job's progress). "Translate to" picker = `AppSettings.GameLanguage` (System + every `GameLanguages` tag; edits the setting, follows changes made in Settings → General). Filter chips (All, Installed, Pack available, No pack, Needs update, Generating incl. paused) count over the whole library (search not applied), single choice, hidden without games; filter and search apply together; *Nothing found* says which hid the games and `Reset search and filter` clears both. Registry banner (warn, `Retry` = `PackIndex.RefreshAsync`) when the last fetch wasn't fresh: saved copy ("Showing data saved on <date>"), no copy ("Pack statuses appear once it answers"), newer format ("update the app"), invalid address. Avalonia objects (the placeholder brush, `PlaceholderColors.CreateBrush`) are made lazily on the UI thread: one created on a pool thread while a headless test sets Avalonia up takes the UI dispatcher from it. Covers: `CoverResolver` = Steam `appcache/librarycache/<id>/[<hash>/]library_600x900.jpg`, old flat `<id>_library_600x900.jpg`, our `<cache>/covers/steam-<id>.jpg`, then the Steam CDN (CDN miss remembered 7 days in `steam-<id>.miss`, network errors not); `CoverLoader` decodes off the UI thread, 4 at a time. VM updates from background events go through `IUiDispatcher`; folders open through `ISystemShell`. Tests: `TestServices.Build(steam: fixture => ...)` (fake Steam, no covers, immediate dispatcher, `FakeShell`). Card quick action hover / pressed: Fluent's translucent pointer-over fill made the label vanish into the cover art, so every variant keeps an opaque fill (the plain one turns `AppSurface3Brush` with a thin `AppBorderStrongBrush` ring; primary, warn, gen keep their colour).

## Game page

(`GamePageViewModel`, `Views/GamePageView`, design §3; task 22): opened with `pages.Create<GamePageViewModel>(game[, GamePageTab])`; the status comes from `GameStatuses` (Desktop singleton: anti-cheat policy + latest pack list + `GameLanguage` + `IInstalledPacks` = `StoreInstalledPacks` over `InstalledPackStore`: a game's one record counts for its own language only, its `InstalledPackProblem` from `InstalledPackMonitor` (see _Game update re-check_) and `ForOtherVersion` from `PackFit` over the installed revision's manifest (task 56, once per install record); `InstalledChanged` tells pages and cards to recompute; the library cards use the same; open generation jobs join through `GenerationService.StateOf` and `JobChanged`, see _Generation tab_). Header: backdrop = the cover's colors (`CoverPalette`: ~4 000 opaque samples bucketed by 4 bits per channel; dominant = biggest bucket, darkened; two radial glows = buckets scoring best on size × saturation, ≥ 2 % of samples and ≥ 64 RGB apart; read through `Bitmap.CopyPixels` into a BGRA framebuffer; placeholder gradient until the cover loads), opacity per theme (`HeroBackdropOpacity` 0.55 dark / 0.22 light) and a fade into the page; cover 132 px; chips engine (hidden until detected), store (Steam / Added manually), version (`build 14,882,031` grouped, or `files hash <8 hex>` = SHA-256 over the sorted `path hash` lines). Primary action (`GamePrimaryActions.Resolve`, Core, pure): blocked / unknown → none; job → View progress (teal, caption % · ETA or pause reason); broken installed pack → Update to rev N when the registry has a later revision of the same pack (`InstalledPackState.Revision`), else Translate new strings; installed → Play (via Steam · with «…»; launches through `GameSessions`, then reads `Starting…` until the game's process shows up and `Running` with the caption "running since <time>" until it ends, disabled meanwhile; a launch problem shows as an amber line under the caption, cleared by the next press); pack available → Install best pack («title» · verified/alpha · "made for your version" when the index lists the game's build; file check is the Packs tab's); else Generate translation with AI. Words in `PrimaryActionTexts`. Install runs the install flow on the best compatible pack (see _Install flow_); Update to rev N installs the later revision through the install flow, Re-apply (`GamePrimaryActionKind.Reapply`: NeedsUpdate with a pack that still fits and no later revision; caption "Writes «…» rev N again from your files") re-applies; until their flows exist Generate / Translate / View progress open the Generation tab; library quick actions open the page on the same tabs (Install runs in place). The primary action is off while any install operation runs. Installed pack block (green / amber when broken; while an operation runs on the game: spinner, "Installing «…» · step N of M", the step, a bar; ⋯ menu: Re-apply, Show in Packs (Packs tab, the pack's language, the pack selected), Uninstall (restore originals); Rate joins with task 63; label "Installed · incompatible with the new version" / "Installed · not applied after the game update"), update banner (NeedsUpdate, or an installed pack made for another version with `Translate new strings`, task 56; worded per problem: incompatible "The game updated (build N)…", wiped "…put back the original files: «…» still fits but isn't applied…", re-apply failed + the reason; `Translate new strings` (incompatible) or `Re-apply` (fits) only when the header offers the update, `Details` after a failed automatic re-apply), rating prompt slot (task 63). Tabs: Packs (count; see _Packs tab_; hidden for blocked games), Generation (% while a job runs; see _Generation tab_; progress, review and result tasks 53–55), Audio / Textures muted with a "soon" pill but selectable, showing the coming-soon illustration. Default tab: Generation while a job exists, else Packs. Sticky bar: a copy of the tab bar with mini cover, name and the primary action, shown once the in-flow tab bar scrolls under the top (`IsTabBarStuck`, set by the view). The page follows the catalog, pack list, target and UI language while open. **Blocked game** (task 23, design §3a): `GameBlocks.Resolve` (Core, pure; also used by `LocalizationStatuses`) = registry opt-out, else a policy anti-cheat block not lifted by the registry's `antiCheatAllowed` → `GameBlock` (reason, anti-cheat ID and name); the page keeps the header with a greyscale cover, placeholder and backdrop (`BitmapPixels`, Rec. 601 luma; the grey copy is made with the palette so a block arriving later needs no reload), no action, no installed block, and shows the red panel (anti-cheat name or opt-out text) instead of the tabs and the sticky bar. `Report` opens `BlockReport.IssueUri` (new issue in `ailocalpack/registry`, English title + body percent-encoded: game, ID, store, reason, anti-cheat + the file `AntiCheatDetector` finds when clicked, app version) through `ISystemShell.OpenUrl` (https only). Guard: install (tasks 27, 29) and generation (task 47) services call `GameBlocks.EnsureAllowed(game, policy, index, BlockedOperation)` first, which throws `GameBlockedException` (game, operation, block) for a blocked game whatever the UI showed. **Rating prompt** (task 63): a strip in the update banner's place (never next to it) once the player played with a newly installed registry pack (`RatingRules.ShowPrompt`): "How is «…»? Your answer helps other players." `👍 Works` / `👎 Doesn't work` (the report without text; buttons off while sending; a failure in red under the text) / `Later` (hidden until the next session ends; after two, never again for that revision); a sent report thanks with a toast with `Add details` (the Packs tab on the pack's rating block) and `Open`. The installed block's ⋯ menu has `Rate` (the Packs tab on the installed pack) while the rating block would show.

**Tab bar in two groups** (design §3, split tabs): `GamePageViewModel.Tabs` in order Text (`GamePageTab.Packs`), Voice (`Audio`), Textures, Create with AI (`Generation`); `LocalizationTabs` (captioned "Localization") on the left and `ToolTabs` ("Tools", `GameTabViewModel.IsTool`) on the right behind a divider (`Border.tabToolGroup`); every tab has an icon (`GameTabViewModel.Icon`: `IconType`, `IconMic`, `IconImage`, `IconSparkles`), the tool tab's icon and underline are teal (`Button.pageTab.tool`); the sticky copy hides the captions (`ContentControl.stickyTabs`). The header never offers `Generate` (`HasPrimaryAction` is false for it), so a game without a translation has no header action: the Text tab's empty state offers `Create with AI` as a teal outline button (`Button.ghost.gen`), and under the registry list a link "None of these suits you? Create your own with AI" (`PacksTabViewModel.ShowCreateOwn`: rows and no Mine) opens the Create with AI tab. UI text calls a pack a *translation* everywhere (see _Naming_ in `CLAUDE.md`); code, CLI and these docs keep "pack".

## Packs tab

(`PacksTabViewModel` + `PackRowViewModel` in `ViewModels/GamePage`, `Views/PacksTabView`, design §4; task 24): list of registry packs of the game in one language + details panel of the selected one (first selected by default). Toolbar: language popover (search on native name, English name, tag; every `GameLanguages` tag with this game's pack count or "—", languages with packs first by count, current highlighted; picking one changes only the tab, not `GameLanguage`; the tab follows the setting while the player hasn't picked another language), sort `Status, rating` (= `LocalizationStatuses.Rank`, default) / `Newest` (updated) / `Coverage` (ratio), ties in rank order, selection kept; count "Русский: 3 packs". Row: title, Installed tag (amber `rev N · rev M available` when broken), author · verified/alpha · 👍 · compatibility (icon + text; "checking…", "not checked" on a failed manifest), incompatible rows dimmed. Manifests are fetched only once the tab is shown (never for a blocked game): the selected pack first, then the rest of the list one at a time, each checked with `PackCompatibilityChecker` off the UI thread (file hashes saved); a game change (build, availability, folder) checks again. `PackManifestClient` (Core/Registry): manifest path resolved against the index location (local folder or https only, else refused), one GET (15 s, no retries, 8 MB cap); `PackManifestProblem`: Offline / Timeout / HttpError (may pass), FileMissing (local file absent, HTTP 404 / 410), Invalid (with the format errors), NewerFormat, Mismatch (ID, game or language differ from the index entry). A selected Mine row replaces the details panel (`SelectedMine`, `ShowMineDetails` / `ShowPackDetails`): "local · created <date>", the Tested in game box (green) or "Not tried in game yet", made with (agent + model), coverage with a bar, test run, fonts, validator (`LocalPackTexts`, the result tiles' words), size, the note that publishing compares it with the registry's packs first, `Install` (→ `InstallFlow.InstallLocalAsync`, no launch) / `Installed ✓` + `Uninstall (restore originals)`, `Publish` (off until task 61: hint "Try it in game first…" before it was tried, then "…comes with GitHub sign-in…"), `Delete` (asks; off while installed: "uninstall it before deleting"; `GenerationService.DeleteLocalPackAsync` deletes the pack and the job folder that made it). Library banner for a corrupted catalog (`GameCatalog.CorruptedBackupPath`), dismissible. Blocking step *Finishing an interrupted install* (task 27) between settings and catalog, present only when a journal exists (`PackInstaller.HasInterruptedTransaction`, checked when `AppStartup` is built): running line "Don't close the app"; rolled back → warning, completed / uninstall finished → ok, failed → warning "retried on the next start". Background step *Checking installed packs* (`PacksStep`) starts once the library refresh and the pack list are both done: no packs → skipped, a pack needing the player → warning naming the games, re-applied → ok naming them, else "N packs in place". Background step *Checking generation jobs* (task 47, see _Generation jobs_). Background step *Checking for app updates* (task 67, see _Settings → About_).

## Install flow

(Desktop `Install/`, design §4a; task 29): `PackInstallService` (singleton, one operation at a time, never throws; `Current` = `InstallOperation` (game, kind Install / Reapply / Uninstall, pack, title, steps, step index, fraction, `Percent`), `Changed` from a pool thread) runs **Install**: `GameBlocks.EnsureAllowed` → Download (`PackFetcher` into the cache) → recipe tool must be supported (a patch pack needs none) → Dependency (step added only when the manifest names one: `DependencyPreparer` looks each up in the index's whitelist (off it → `DependencyUnknown`), picks the release file for the game build's platform (no file → `DependencyPlatform`), downloads it into the cache and unpacks it into staging (`DependencyFetch` / `DependencyArchive`); one installed already in the version is shared, not downloaded; all before anything is removed, so a failed download leaves the installed pack) → RemovePrevious (the game's other pack is uninstalled first, whatever its language: one pack per game; dependencies the new pack names are kept for it, and removed again if the new pack then fails) → Check (`PackCompatibilityChecker` on the cached manifest, against the originals; incompatible stops) → Rebuild (`IRecipeTool.Rebuild` in the table's language from the player's own files into `<cache>/staging/<random>`, deleted afterwards; a patch pack: Patch, `PatchApplier` into the same staging, see _Binary patches_) → BackUp / Write / Verify (`PackInstaller.Install` with the changed files and the rebuild's generated files; its stages map onto the steps). **Re-apply** = the installed revision from the cache (else the registry while it lists that revision) rebuilt from the current files, its dependencies unpacked again → `PackInstaller.Reapply`. **Uninstall** = `PackInstaller.Uninstall` (step Restore). Result `InstallOutcome` (error `InstallError`: kind Busy / Blocked / NotInRegistry / Fetch / Incompatible / Patch / DependencyUnknown / DependencyPlatform / DependencyFetch / DependencyArchive / InvalidStrings / Recipe / Font / Transaction / Unexpected with the fetch problem, check, transaction failure, file, OS detail; `FilesRestored`, `CanRetry`) carries a log in the UI language (timestamped lines; the OS detail indented). `InstallFlow` (singleton, events on the UI thread; `IsBusy` also covers the check before an install): `InstallAsync(game, pack[, manifest, check])` checks when not given (`PackManifests`), builds the risk list (`InstallRisks.For`, Core, pure: alpha, probably compatible, each dependency, replaces the installed pack of any other ID or language; empty = no dialog) and shows `InstallConfirmDialogViewModel` (risk lines, amber for alpha / probably compatible, "Original files are backed up; you can uninstall.", Cancel focused) or installs at once; `InstallBestAsync(game, noPack)` = `BestPack.PickAsync` (Core: ranked packs checked in order, first compatible wins and stops the checks, else the first probably compatible, unreadable skipped; none → `noPack`); `Uninstall(game)` asks with `ConfirmDialogViewModel` (original files restored, pack stays in the registry, saves untouched); `ReapplyAsync(game)`. Toasts (`ToastService`, bottom right of the main window, newest last, at most 3, one per game key, stay until closed; actions close the toast, then run): done "Installed: «…»." (+ "In the game, choose English as the language." when the rebuild gave `InGameLanguage`, also logged; native language name) `▶ Play` (`GameSessions.LaunchAsync`; a launch problem becomes a toast) · `Undo` (uninstall without asking); uninstalled / re-applied info; failure "Couldn't install; files restored." (or "…restoring files failed. The app retries on the next start.") `Retry` (when it may help; repeats the confirmed operation without asking again) · `Details` (`InstallDetailsDialogViewModel`: plain reason from `InstallTexts.Reason`, e.g. "<file> is in use; the game seems to be running. Close it and retry.", whether files were restored, the log, Close / Retry). Every outcome is also recorded in the Activity panel (see _Activity panel_).

## Activity panel

Desktop `ActivityRecorder` (singleton, resolved before the background checks start): `PackInstallService.Current` → the one running task (title "Installing «…» · step N of M", step, percent); `InstallFlow` records every outcome of an operation the player started (a Busy refusal isn't; failures go to the feed: the player saw their toast); `InstalledPackMonitor.Rechecked` (every re-check result): re-applied by itself → feed, re-apply failed → decision (`Retry` when it may help, `Log`), incompatible → decision (`Update to rev N` when the registry has a later revision of the same pack, else `Translate new strings` → Generation tab), wiped with re-apply off → decision (`Re-apply`); any successful operation on a game, or a re-check finding its pack intact, settles that game's pack decisions. The details dialog takes `InstallDetails` (kind, title, reason, restored, log, can retry): from an outcome now (`InstallDetails.Of`) or from a saved event. ## Controls and colours

One family of controls on one palette (`Styles/Theme.axaml` tokens, `Styles/Controls.axaml` classes); views never set colours or corner radii of controls inline.

- **Corner radius scale**: 6 tags, badges, chips of facts, the text-only `link` button · 8 controls up to 36 px (`sm` buttons, `icon.sm`, the menu button, list items, segmented options; also Fluent's `ControlCornerRadius`, so stock text boxes, combo boxes, radio buttons, progress bars round the same) · 10 controls of 40 px (`accent`, `ghost`, `danger`, `icon`, search box, toolbar combo box, language picker) · 12 large buttons (`primaryAction`, 48 px), blocks inside a page (notices, banners, pack rows; also `OverlayCornerRadius` for flyouts, drop-downs, tooltips) · 14–18 cards, dialogs. Filter chips and counters are pills (height / 2). A check box is 5 (its 20 px box).
- **Button kinds** (heights 32 `sm` · 40 · 48 `primaryAction`): `accent` primary (accent fill, white text, darker fill on hover / pressed: Fluent's `AccentButton*` keys set from the palette), `ghost` secondary (transparent, `AppBorderStrongBrush` border, `AppSurface2` on hover, `AppSurface3` pressed), `bare` quiet (no chrome until hovered, same hover / pressed), `link` (accent text, accent-soft hover), `danger` (`AppBadFillBrush`), `genAction` / `primaryAction.gen` (teal, `AppOnGenBrush` text), `icon` (transparent, hover `AppSurface2`), `icon.overlay` over a picture (dark plate, white icon in both themes). - **Keyboard focus**: one ring for every control: 2 px `AppFocusBrush`, 3 px outside the control, its corners the control's own radius + 3 (`FocusRingCornerRadiusConverter` reading `AdornerLayer.AdornedElement`), not clipped to the control (`AdornerLayer.IsClipEnabled="False"`). - **Contrast** (WCAG 2.1, checked for both themes by `ThemeContrastTests`): text tokens (`AppText`, `AppMuted`, `AppFaint`, accent and tone colours) ≥ 4.5:1 on the background, surface and surface 2; a tone on its own soft tint ≥ 4.5:1; text on every filled control state ≥ 4.5:1 (`AppOnWarnBrush`, `AppOnGenBrush` are dark in the dark theme and white in the light one, where amber and teal are deep); icons and the focus ring ≥ 3:1. A new token or a new text-on-fill pair gets a row in that test.

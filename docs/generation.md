# Generation: agents, MCP server, jobs, pipeline

Agent adapters (Claude Code, Codex, fake), agent install and sign-in, toolkit MCP server, working copies and size estimate, generation jobs, pipeline stages, translate stage, build stage and local packs, update mode, unknown engines. Part of the product spec in `CLAUDE.md`: keep it current; record settled decisions in the matching section here.

## Agent adapters

(`AiLocalPack.Agents`, task 40): `IAgentAdapter` = `Id` (`claude`, `codex`, `fake`; stored in jobs), `DisplayName`, `DetectAsync` → `AgentInstallation` (agent ID, executable, version, `AgentSource` Path / Managed / Configured, leading `Arguments`) or `null`, `GetAuthStatusAsync` → `AgentAuthStatus` (SignedIn / SignedOut / Unknown, account, detail; never reads tokens), `RunAsync(installation, AgentRunRequest, ct)` → `IAsyncEnumerable<AgentEvent>`. Request = prompt (on standard input where the agent allows it: no command-line limit), working folder (the only one file tools may touch), system prompt appended, `AgentMcpServer`s (name, command, args, env; all their tools allowed), `AgentBuiltinTool`s (ReadFiles / EditFiles / RunCommands, none by default), model, session to resume. **Normalized events**: `AgentSessionStarted` (session ID, model), `AgentMessage`, `AgentToolCall` (ID, name, input JSON), `AgentToolResult` (call ID, output, error), `AgentUsage` (input / output / cache read / cache write tokens, cost USD?), `AgentLimitReached` (reset time?, message), `AgentError` (`Malformed` / `SignedOut` / `StartFailed` / `Reported`), `AgentDiagnostic` (a standard error line), `AgentDone` (outcome `Succeeded` / `Failed` / `LimitReached` / `SignedOut` / `Cancelled`, result, message, exit code). **Contract** (decided; `AgentAdapterContractTests` in Agents.Tests, every adapter subclasses it with its own transcripts of the `AgentContractScenario`s): the stream never throws, not even for cancellation, and ends with exactly one `AgentDone`; final outcome = cancelled (token or kill) → a limit event seen → a `SignedOut` error seen → the agent's own verdict (a success with a non-zero exit code becomes Failed) → Failed "ended without a result" / "exited with code N", with the last 20 standard error lines (≤ 2 000 chars); a line that can't be read → `Malformed` and the run goes on; a second verdict is ignored; stopping the enumeration kills the process tree. `ProcessAgentAdapter` (base of process-driven agents) keeps it: an adapter gives the `ProcessSpec` of a run and a fresh `IAgentOutputParser` per run (`ParseLine` for standard output, `ParseErrorLine` → diagnostic by default). **Process runner** (`Agents/Processes`): `IProcessRunner.Start(ProcessSpec, ct)` (file + argument list, no shell, working folder, environment changes (`null` removes), standard input text then closed; missing program / folder → `ProcessStartException`) → `IRunningProcess` (`ReadLinesAsync` = standard output and error lines as they arrive, `ProcessLine` with stream and `Truncated`; `Exit` → `ProcessExit(code, killed)`; `Kill` = whole tree through `Process.Kill(entireProcessTree: true)` on every OS; disposing kills a live process). `ProcessRunner`: UTF-8 (no BOM) both ways, lines cut at 8 Mi characters (`ProcessRunnerOptions.MaxLineLength`), the output ends 2 s after the process exited even if a left-over grandchild still holds the pipes (`OutputGrace`), cancellation kills the tree. `RunToEndAsync(spec, timeout)` → `ProcessResult` (exit code or `null` = timed out and killed, stdout, stderr) for `--version` / sign-in probes. **Fake agent**: `AgentEventJson` writes / reads events as one JSON object per line with a `type` (`session`, `message`, `toolCall` with `input` as JSON, `toolResult`, `usage`, `limit` with UTC `resetsAt`, `error`, `diagnostic`, `done`; enums camelCase, unknown properties ignored; a bad line → the reason). `FakeAgentReplay` = the fake program: writes a recording's lines to standard output as they are, except control lines `{"control": "delay" (ms) / "stderr" (text) / "prompt" (message with standard input) / "cwd" (message with the working folder) / "write" (path relative to the working folder + text: a file such as `../glossary.json`, standing in for what a real agent stores through MCP tools) / "exit" (code) / "hang" / "child" (recording: starts another replayer sharing the outputs, `child-pid N` on standard error)}`; end of file = exit 0; an unreadable recording or bad control = exit 2. Hosted by the test program `tests/AiLocalPack.FakeAgent` (Agents.Tests run it through the `dotnet` host) and by the hidden CLI command `agent replay <recording>`. `FakeAgentAdapter(runner, FakeAgentReplayer, recording, authState)` runs it with the prompt on standard input and reads `AgentEventJson` lines (MCP servers, tools, model ignored). CLI `agent run --fake <recording.jsonl> [prompt] [--cwd <dir>] [--json]` / `agent run <agent> <prompt> [--cwd] [--allow read|edit|run]… (default read) [--model] [--resume <session>] [--system-prompt <text>] [--json]`: one line per event (`session`, `message`, `tool`, `result`, `usage`, `limit`, `error`, `stderr`, `done`) or `AgentEventJson` lines; exit 0 = succeeded, else 1; Ctrl+C / SIGTERM kills the agent's tree and ends `Cancelled`. `agent probe <agent> [--json]`: program (+ found on PATH / installed by the app), version (+ too old), sign-in; JSON `{agent, name, found, executable, source, version, supported, auth (signedIn|signedOut|unknown), account, detail}`; exit 0 = found, supported and signed in. `AgentAdapters` = the real adapters by ID (`claude`, `codex`). **Programs** (`Processes/AgentPrograms`, shared by both): `Candidates(AgentProgramLayout)` = every `PATH` folder (Windows `<name>.exe` before npm's `<name>.cmd`; quoted entries unquoted, relative ones ignored), then the installers' folders, because an app started from the desktop doesn't get the shell's `PATH`: the layout's home folders, on Unix its Unix ones + `/opt/homebrew/bin`, `/usr/local/bin`, `~/.npm-global/bin`, on Windows `%APPDATA%\npm`; then the app-managed folder (task 43, `AgentSource.Managed`); a file counts with an execute bit on Unix; `DetectAsync` = the first answering `--version` (10 s; first `major.minor.patch[-pre]` of the output), else the first found without a version. `Process` = the program with its argument list, its own folder put first on the process's `PATH` (an npm install is a `#!/usr/bin/env node` script or a `.cmd` shim and node sits next to it: found by checking Homebrew's `codex` from an app without `/opt/homebrew/bin` on its `PATH`), a Windows batch file through `cmd.exe /d /s /c "…"` with a raw line, each argument quoted for the C runtime then every cmd metacharacter `^`-escaped twice (`WindowsCommandLine`, npm cross-spawn's scheme; not yet checked on a Windows machine). **Commands** (`AgentSandbox`, task 57): a run with `RunCommands` gets `TMPDIR` / `TMP` / `TEMP` = `<working folder>/.tmp` (made before the run), so scripts' temporary files stay in the only folder the agent may write. `AgentRunProcess` = a run's `ProcessSpec` + `ScratchDirectory` (files made for the run, deleted after it; failing to write them ends the run as `StartFailed`). `ProcessSpec.RawArguments` (Windows) = a command line passed as is instead of the argument list.

## Claude Code adapter

(`Agents/Claude`, task 41; flags checked against the CLI reference and `claude --help` of 2.1.319, 2026-11-08): **minimum version 2.1.259** (`ClaudeCodeCommandLine.MinimumVersion`; `--restricted` 2.1.248, `--permission-prompts` 2.1.259), older = not supported. **Detect** (`ClaudeCodeLocations.Layout`): `AgentPrograms` with `~/.local/bin` (native installer, every OS) and Unix `~/.claude/local`; `--version` = `2.1.319 (Claude Code)`. **Sign-in** (decided probe): `claude auth status --json` (15 s; local, no API call, no token read by the app): exit 0 + `loggedIn` → signed in (account = `email`, else "API key" / "Cloud provider"), `loggedIn: false` → signed out, anything else (no such command, timeout) → unknown with its words. **Run**: `claude -p --output-format stream-json --verbose --input-format text --restricted --disable-slash-commands --permission-mode dontAsk --permission-prompts none --strict-mcp-config [--mcp-config <file>] --tools <list> [--allowedTools <list>] [--append-system-prompt-file <file>] [--model] [--resume]`, the prompt on standard input, in the working folder. `--restricted` confines the file tools to the working folder (checked: a Read of `/etc/hosts` is refused) and ignores the player's user / project settings (hooks, plugins, permission rules); `--safe-mode` is not used: it also drops `--mcp-config` servers (checked). `--tools` = Read, Glob, Grep (ReadFiles) / Edit, Write (EditFiles) / Bash (RunCommands), `""` = none; `--allowedTools` = those + `mcp__<server>` per MCP server (all its tools); anything else is denied without asking. **Commands** (task 57, checked with 2.1.322 on macOS 2026-11-10): a run with `RunCommands` gets `--settings <file>` = `{sandbox: {enabled: true, failIfUnavailable: true, autoAllowBashIfSandboxed: true, allowUnsandboxedCommands: false, network: {allowedDomains: [], strictAllowlist: true}}}` (`ClaudeCodeCommandLine.SandboxSettings`): Bash runs in Claude Code's sandbox (Seatbelt on macOS, bubblewrap on Linux), writes only in the working folder and `$TMPDIR` (moved into it), no network (a write to `../game` and to `/tmp` refused, `curl` refused, writes in the folder worked); without `failIfUnavailable` + `allowUnsandboxedCommands: false` a sandbox that failed to start (a missing `$TMPDIR`) ran the commands **unconfined**, with them the agent refuses to run them; reads stay open (the game copy is read with shell commands); `--restricted` still confines Read / Edit / Write to the working folder. MCP config `{mcpServers: {name: {type: stdio, command, args, env}}}` (names `[A-Za-z0-9_-]`, unique, else `StartFailed`) and the system prompt are files in a scratch folder under the temp folder (no quoting or length limits), deleted after the run. **Parser** (`ClaudeCodeParser`): `system/init` → session (ID, model); `assistant` text → message, `tool_use` → tool call (input as raw JSON), thinking left out; an assistant `error` (Agent SDK `SDKAssistantMessageError`): `authentication_failed` / `oauth_org_not_allowed` → `SignedOut`, `rate_limit` → limit, else `Reported`, in its text; `user` `tool_result` → tool result (text or text blocks joined, `is_error`); `rate_limit_event` `rejected` → limit at `resetsAt` (`allowed` / `allowed_warning` → `AgentLimitStatus`: the used share of the event's window, `unifiedWindows[rateLimitType].utilization`, else `utilization`; task 53) (Unix seconds; `credits_required` worded apart), `allowed` / `allowed_warning` left out; the limit is reported once (the event's reset time wins, else old `…|<unix seconds>` text); `result` → usage of the whole run (input, output, cache read, cache creation tokens, `total_cost_usd`) then the verdict (`success` without `is_error` → succeeded with `result`, else failed with its text or `errors`); unknown types left out, a line without a JSON object `type` → `Malformed`. Transcripts recorded from Claude Code 2.1.319 in `tests/fixtures/agents/claude` (paths shortened; the limit one made by hand from the SDK reference, see its README); the contract tests run on them.

## Codex adapter

(`Agents/Codex`, task 42; flags checked against `codex exec --help` of 0.167.0, the config reference and `codex-rs/exec/src/exec_events.rs`, 2026-11-08; no minimum version enforced, `CodexAdapter.CheckedVersion`): **Detect**: `AgentPrograms` with `~/.local/bin`; `--version` = `codex-cli 0.167.0`. **Sign-in**: `codex login status` (15 s, writes to standard error): exit 0 + `Logged in using ChatGPT` / `…an API key…` → signed in (account ChatGPT / API key), `Not logged in` → signed out, else unknown with its words. **Config** (decided): `-c` overrides with `--ignore-user-config --ignore-rules` (the player's `config.toml` and `.rules` ignored, sign-in still from the player's `CODEX_HOME`), not a generated `CODEX_HOME` (it holds the sign-in too); features off through `-c features.<x>=false`, which an older Codex ignores with a notice, while `--disable <x>` refuses an unknown name. **Run**: `codex exec --json --skip-git-repo-check --ignore-user-config --ignore-rules --color never --cd <dir> --sandbox read-only|workspace-write -c approval_policy="never" -c web_search="disabled" -c features.<x>=false… [-c sandbox_workspace_write.network_access=false -c …exclude_slash_tmp=true -c …exclude_tmpdir_env_var=true] [-c mcp_servers.<name>.command|args|env|default_tools_approval_mode="approve"|required=true] [-c developer_instructions="<system prompt>"] [--model] [resume <session>] -`, the prompt on standard input. Always off (`CodexCommandLine.DisabledFeatures`): apps, plugins, remote plugins, hooks, browser use (+ external), computer use, in-app browser, image generation, sub-agents, memories, skill dependency installs, tool suggestions. Sandbox: Codex sandboxes **writes and the network, not reads**; no edit / command tools → `read-only`, EditFiles or RunCommands → `workspace-write` with only the working folder writable (checked: a write outside it failed, the edit inside worked), no network; Codex reads through its shell, so ReadFiles keeps the shell tools (read-only commands), and with neither reading nor commands `features.shell_tool` / `unified_exec` are off and only MCP tools remain. MCP tools need `default_tools_approval_mode="approve"` (else "requires approval, but approval policy is never", checked); MCP server names must be bare TOML keys (`[A-Za-z0-9_-]`, unique, else `StartFailed`); values are TOML basic strings (`CodexCommandLine.Toml`). The system prompt goes on the command line (`developer_instructions`): cmd.exe's 8 191-character limit applies to an npm `codex.cmd` on Windows. Commands (task 57) need nothing more: `workspace-write` confines them to the working folder without network, and `AgentSandbox` moves the temporary folder inside it (Codex's sandbox excludes `/tmp` and `$TMPDIR`). **Parser** (`CodexParser`): `thread.started` → session (thread ID, the requested model: Codex doesn't name it); items: `agent_message` → message (the last = the result), `command_execution` → tool `command` `{command}` (result = output, error when exit code ≠ 0 or failed / declined), `file_change` → tool `file_change` `{changes}` (result = `kind path` lines), `mcp_tool_call` → tool `mcp__<server>__<tool>` with its arguments (result = text blocks or error), `web_search` → tool `web_search`; a call reported when its item first shows up (a completed item without a start reports both); `error` items → diagnostic; reasoning, to-do lists, updates left out. `turn.completed` → usage (input **without** the cached part, so it means the same as Claude Code's; output; cached input = cache read; cache writes; no cost) then succeeded with the last message; `turn.failed` → failed with its message. Top-level `error`: `Reconnecting... n/5` → diagnostic; `hit your usage limit` → limit, reset time from Codex's own wording (`Try again at 6:10 PM.` = today, `Nov 9th, 2026 6:10 PM`, both in the machine's time zone, `TimeProvider.LocalTimeZone`; `Try again later.` → none); `401 Unauthorized` / `sign in again` / `Not logged in` → `SignedOut` (a signed-out run retries ~10 times over ~30 s first, so the pipeline checks the sign-in before starting); else `Reported`; limit and sign-in each reported once. Transcripts recorded from Codex 0.167.0 in `tests/fixtures/agents/codex` (the limit one made by hand from `UsageLimitReachedError`'s wording); the contract tests run on them.

## Agent install and sign-in

(`Agents/Install`, task 43): `AgentInstaller` puts an agent's **official build** into `<data>/agents/<id>/<version>/` (`AppPaths.Agents`; no Node.js, no admin): Claude Code's program, Codex's whole unpacked package; `<id>/installed.json` (`{schemaVersion, version, executable (relative), installedAt, url, sha256, verification}`) is written last (commit point), so a half-done install is never used; `Find` / `ManagedDirectory` give the folder of the program, which the adapters try last (`AgentSource.Managed`: the player's own copy on `PATH` or in the installers' folders wins, `AgentPrograms.Candidates`). Release per agent from an `IAgentDistribution` for the `AgentPlatform` (OS + `RuntimeInformation.OSArchitecture` x64 / arm64, Linux musl by `/lib/ld-musl-*`). **Claude Code** (`ClaudeCodeDistribution`, decided): Anthropic's own installer source `https://downloads.claude.ai/claude-code-releases`, channel **`stable`** (not `latest`) or the version asked for, `<v>/manifest.json` (per platform `darwin-arm64|x64`, `linux-x64|arm64[-musl]`, `win32-x64|arm64`: `binary` `claude[.exe]` only, `checksum`, `size`), trusted only with a valid detached signature `<v>/manifest.json.sig` by Anthropic's release key **pinned in the app** (`Claude/Files/claude-code-release-key.asc`, fingerprint `31DD DE24 DDFA B679 F42D 7BD2 BAA9 29FF 1A7E CACE`, provenance in its README; checked by our own `OpenPgpSignature`: v4, binary-document type, RSA PKCS#1 v1.5, SHA-256/384/512, issuer = the pinned key, unknown critical subpackets and expired signatures refused, armor CRC-24 checked); versions under `MinimumVersion` refused (`TooOld`). The app's copy runs with `DISABLE_AUTOUPDATER=1` (the app updates it). **Codex** (`CodexDistribution`, decided): what OpenAI's `install.sh` does: GitHub release of `openai/codex` (`releases/latest` or tag `rust-v<v>` via the REST API, `User-Agent: ailocalpack`; unauthenticated, 60 requests / h), asset `codex-package-<rust target>.tar.gz` (Linux = musl builds), program `bin/codex[.exe]`, helpers (`codex-path/rg`, `codex-resources/`) kept in place; OpenAI signs nothing the app could pin (Sigstore bundles for Linux only), so the SHA-256 must be the same in GitHub's asset `digest` and the release's `codex-package_SHA256SUMS`, and both URLs must be that release's `github.com/openai/codex/releases/download/rust-v<v>/` files. **Install** (`InstallAsync(id, version?, progress, ct)`, never throws but for cancellation and unknown IDs): resolve → same version installed → `AlreadyInstalled`, nothing downloaded → download into `<id>/downloads/<sha256[..16]>-<file>` through Core's `VerifiedDownloader` (resumable `.part`, 3 tries, size + SHA-256 checked, mismatch deleted; a cancel keeps the part) → `Unpacking` into `<id>/.staging-<random>` (binary: copied + `rwxr-xr-x`; package: `AgentPackageArchive`, every name checked first: relative, no `..` / drive / backslash, no duplicates ignoring case, only folders and regular files, ≤ 20 000 entries, ≤ 4 GiB, Unix rwx bits kept, never set-ID; a package without the program → `ArchiveInvalid`, the download deleted) → moved to `<id>/<version>` → state written → older versions, stagings and downloads removed (one still running on Windows stays until the next install). **Update** = installing a newer release (`FindReleaseAsync` tells what is current). One install per agent (`<id>/install.lock`, `Busy`). `Uninstall(id)` deletes the state file, then the folder. Progress `AgentInstallProgress(stage Resolving / Downloading / Unpacking, done, total)`. `AgentInstallProblem`: Offline / Timeout / HttpError (may pass, incl. GitHub's rate limit), NotFound, BadVersion, TooOld, NoBuild (no build for this OS / CPU), InvalidMetadata, BadSignature, HashMismatch, ArchiveInvalid, DiskError, Busy. **Sign-in** (`IAgentAccount`, both adapters; the app never reads a token): `SignInAsync` = `AgentSignIn.RunAsync`: status first (signed in → `AlreadySignedIn`, nothing started), then the agent's own login (`claude auth login`, `codex login`: they open the browser and print the URL), its lines passed on, the status asked every 2 s and when the login exits; signed in → done (a login still running 5 s later is killed); exited first → `Exited` with its exit code and last lines; 10 min → `TimedOut`, cancel → `Cancelled` (tree killed); start failure → `StartFailed`. `SignOutAsync` = `claude auth logout` / `codex logout`, then the status. Limit: the login gets a closed standard input, so Claude Code's fallback "paste the code here" (when the browser can't reach its localhost callback) isn't supported; the normal browser flow is. CLI: `agent install <agent> [--version <v>] [--force]` (the player's own copy found → "already installed by you…", exit 0, unless `--force`; prints download progress per 10 %, `Installed <name> <v> into <folder>: downloaded N bytes, <verification>, SHA-256 checked.` + `program:`; failure → one sentence on stderr, exit 1), `agent uninstall <agent>`, `agent login <agent>` (lines indented, `Signed in (<account>).` / `Already signed in…`, Ctrl+C / SIGTERM stops it, exit 1 unless signed in), `agent logout <agent>`; `probe` / `run` look in the app's folder too. Checked on macOS arm64 (2026-11-08): Claude Code 2.1.311 (stable, signature + hash) and Codex 0.167.0 installed under a throwaway home, both run `--version`; `agent probe` with no `claude` on `PATH` reports the app's copy, Codex from Homebrew still wins over the app's.

## Toolkit MCP server

(`AiLocalPack.Mcp`, task 45; official SDK `ModelContextProtocol.Core`, stdio, no hosting package): **entry point** (decided 2026-11-08): an agent starts stdio servers itself, so the **desktop app runs itself in a hidden mode** `<app> --mcp-server --root <working copy> --job <job folder> [--lang <tag>]` (`ToolkitServerLaunch`: handled first in `Program.Main`, before logging, the single-instance check and Avalonia; only the protocol on standard output, refusals on standard error, exit 1), so players need no second program; `ToolkitServerLaunch.Command(AppLaunch, root, job, lang)` = the command line for `AgentMcpServer` (name `ailocalpack`, tools `mcp__ailocalpack__…`), `AppLaunch.ForCurrentProcess` (Core, shared with autostart: `$APPIMAGE`, `dotnet <dll>`, else the process's executable). The CLI's `ailocalpack mcp --root --job [--lang]` serves the same, for development and manual checks; the separate project is shared by both. A WinExe served over redirected pipes is not yet checked on Windows. **Confinement** (`WorkingCopy.Resolve`): paths relative to the copy, `/` or `\`; absolute, rooted, UNC, drive (any `:`) and any `..` part refused; each component that is a link is followed to its final target, which must exist and lie inside the copy's real path (case rules of `PathNames`), else refused (`PathOutsideRootException`); listings show links as `link` and never descend into them. **Job folder** (`Core/Generation/GenerationFiles`, outside the copy, checked at start): `strings.json` = the string store (plain JSON `StringTable`: translations + the extractor's context notes, atomic), `glossary.json` (`Glossary`: `{schemaVersion: 1, language, tone?, formOfAddress? ("informal" / "formal": the player's choice, task 54; unknown → none), entries: [{term, translation, note?, partOfSpeech?, gender?, keepAsIs?, edited? (the player changed it in the review)}]}`, terms unique ignoring case, a `keepAsIs` term translates to itself, texts ≤ 2 000 chars; task 49 may extend it), `build/` = the latest rebuild. Target language = `--lang`, else the store's (a store in another language refuses to start; with neither, writes are refused). **Tools** (calls serialized, extraction cached per server, `refresh` re-reads): `detect_engine` (engine, confidence, marker, executable, candidates, recipe tool + version or the reason the toolkit can't: unknown, switched off on this OS, no tool), `list_files` (folder, `*`/`?` pattern on file names, recursive ≤ 200 000 entries walked, ordinal order, ≤ 500 per page), `read_file_snippet` (text = numbered lines, ≤ 400, lines cut at 1 000 chars, total lines for files ≤ 32 MB; a NUL in the first 8 000 bytes = binary → hex dump ≤ 4 096 bytes), `extract_strings` (key prefix / search filters; key, original, context, length limit, placeholders, stored translation), `get_strings` (keys asked, else all / translated / untranslated), `put_translations` (unknown keys listed, each validated: errors refused with the issues, warnings stored and reported, empty text removes), `validate_strings` (given texts without storing, else stored ones), `get_glossary` / `put_glossary` (upsert by term, remove, tone; task 54: an entry the player edited is never replaced or removed, listed in `keptByPlayer`, and the player's `formOfAddress` is kept and shown by `get_glossary`), `rebuild` (stored translations → `build/` cleared first; changed / generated files, applied, unknown keys, in-game language; no font swap: task 51). **Unknown engines** (task 57): when the toolkit can't read the copy's engine, the string tools read the agent extractor's `agent/strings.json` of the job folder instead (`AgentScriptTool`, tool `agent-script`, read again on `refresh`); before it exists they say "Write your own extractor: it must write strings.json in your workspace."; `rebuild` refuses ("run your own rebuild script"); `detect_engine` names the `agent-script` tool once the file is there. Results are camelCase JSON, nulls left out, paged by `offset` / `limit` → `total` + `nextOffset` (`null` = last), string and glossary pages also stop at ~20 000 characters. Tool errors are `McpException`s; the SDK sends them as `An error occurred invoking '<tool>': <message>`. The validator is _String validator_ (task 48), with the tool's markup. Checked (2026-11-08) with Claude Code 2.1.319 (`--strict-mcp-config`, only `mcp__ailocalpack` allowed) on a copy of the RPG Maker fixture through the desktop app's hidden mode: detect, extract, put, rebuild into `job/build/data/Items.json`.

## Working copies and size estimate

(task 46, `Core/Generation/WorkingCopies`, `GenerationEstimate`, Toolkit `Generation/GenerationEstimator`): **layout** `<data>/work/<game folder>/<job id>/` = the job folder (task 47's `job.json`, `GenerationFiles`), its `game/` = the working copy (the MCP server's root; the job folder is its parent, so never inside it); job ID = UTC `yyyyMMdd-HHmmss-<6 hex>` (`NewJobId`; IDs with `/ \ :` or `..` refused). **Scope** (`WorkingCopyScope`): `WithoutMedia` (default when the toolkit reads the game) leaves out movies, audio / sound banks and Unity streamed resources (`.resS`, `.resource`), which no recipe reads (`WorkingCopies.IsMedia`); `AllFiles` (unknown engine, switched-off engine, toolkit failure, or asked for). `Plan` walks the folder (ordinal order, empty folders kept; links listed with their stored target, never followed). **Clones** (decided): `IFileCloner` = macOS APFS `clonefile` (`CLONE_NOFOLLOW`), Linux `ioctl(FICLONE)` (Btrfs, XFS reflink, bcachefs); Windows none: files go through `File.Copy` (`CopyFileEx`, which block-clones on ReFS / Dev Drive from Windows 11 24H2 by itself, unseen by the app, so the disk check counts a full copy there); a clone never overwrites a file. Whether clones work is probed by cloning one game file next to the working copies and removing it (game and data on different volumes → copy). **Space** (`CheckSpace`): needed = the copy (0 when cloned) + reserve (the size of the files the strings come from: the job's rebuilt files; Brotato's whole pack) + `Margin` 64 MiB, against the free space of the data drive (`IDiskSpace`, nearest existing folder, longest mount point); `Create` refuses with `WorkingCopyException` `DiskFull` (+ `Space`) **before writing anything**; other problems `GameMissing`, `AlreadyExists` (the job has a `game/`), `SourceUnreadable`, `DiskError`. Copying (not cloning) streams 1 MiB blocks with progress in bytes (`WorkingCopyProgress`: bytes and files done of total; a clone counts its size at once), keeps the last write time and Unix mode (+ owner read / write; Windows clears read-only); links are recreated as links (one the OS refuses, Windows without the privilege, is skipped and listed). A failure or cancel deletes the copy, and the job folder when the call created it (an existing one keeps its other files). `Delete(job folder)` (only inside `work/`) removes it with read-only files, never following links, then the empty game folder. **Estimate** (`GenerationEstimator.Estimate(game folder, stored engine?, scope?)`, reads the game only): text = `TextSize` (strings, words, characters of the originals; word = run of letters / digits, an apostrophe or hyphen between letters kept, each CJK character a word) from the toolkit's extract (`TextSizeSource.Toolkit`), else a guess from file sizes (`UnknownEngine` / `EngineDisabled` / `NoTool` / `ToolkitFailed` with the message): 1 % of the bytes of text files (JSON, CSV, XML, scripts, `.rpy`, `.tscn`…) + 0.02 % of other data files (not media, images, programs, fonts) capped at 0.5 M characters, 40 characters a string, 6 a word (within ~2× of the toolkit's counts on Brotato, EVERSPACE and Nepenthe, ~8× over on Golfing in Aether). Cost (`GenerationEstimateModel`, pure, every constant commented as a guess to tune with real jobs): tokens = source characters / 4; output = 1.6 × source + 25 per string + 500 per chunk + setup 15 k; input = source + 40 per string + 12 k per chunk (prompt, glossary, tools) + setup 150 k; chunks of 50 strings (`StringsPerChunk`, task 50 uses it); an unknown format multiplies setup tokens and time by 4. Time = output / 60 tokens/s + 20 s per chunk + 10 min; limits = (0.1 × input + output) / 300 k weighted tokens per 5-hour window of an entry-level plan (Claude Pro, ChatGPT Plus), days = windows / 3; low = × 0.7, high = × 1.6. CLI `gen estimate <game> [--all-files] [--json]` (finds the game like `pack check`; unavailable → exit 1): engine and source line, `strings:` N (words, characters), `copy:` size in files (+ movies and audio left out), `disk:` needed (cloned: "the copy takes no space"), free, enough / NOT ENOUGH, `agent time:` low to high, `subscription:` windows (days), `tokens:` in / out / chunks; JSON `{game, name, engine, source (kebab-case), tool, toolVersion, toolkitError, strings, words, characters, copy {scope, files, bytes, skippedFiles, skippedBytes}, disk {neededBytes, freeBytes, canClone, enough, reserveBytes}, estimate {chunks, inputTokens, outputTokens, timeLowSeconds, timeHighSeconds, limitWindowsLow/High, limitDaysLow/High}}`; exit 0 even when space is short. `gen copy <game> [--all-files] [--job <id>]` makes the copy: `Copied N files of <name> into <folder>: X cloned, Y copied.` Checked on the real test games (2026-11-08, macOS APFS): estimates for Brotato 1 778 strings / 35 min–1.3 h, DDLC 10 888 / 2.8–6.4 h, EVERSPACE 4 758, Emily is Away 80, Nepenthe guessed (RPG Maker off on macOS); `gen copy` of Brotato cloned 405 MB in 0.5 s, every file's SHA-256 the same as the game's.

One open job per game (`Create` → `AlreadyExists`). **Crash recovery** (`Recover`, at app start and before every CLI `gen` command): a Running job whose lock is free → Interrupted. **Runner** (`GenerationRunner`, never throws): calls the `IGenerationStage` handler of the job's stage one **step** at a time (a whole stage, or one Translate chunk; Translate is completed by the runner once no chunk is left), applies its `GenerationStepResult` (`StageDone(counters?)`, `ChunkDone(translated)` with the measured time, `LimitReached(resetsAt?)` → paused until the reset, `GenerationRunner.DefaultLimitWait` = 1 h when the agent didn't say, `Failed(kind, message)`), writes `job.json` and reports after every step; a handler exception → failed (unexpected), a result the state doesn't allow → failed; the player's `GenerationRun.Pause` / `Cancel` stop the running step (it runs again from its start on resume, so a step must be safe to repeat) → paused / cancelled; the caller's cancellation (app quits, Ctrl+C / SIGTERM) → interrupted; a failed write → failed (disk), kept in memory. `GenerationStepContext` = job, job folder, working copy, `GenerationFiles`, clock, `Log`. **Service** (`GenerationJobs`): `Start` (`GameBlocks.EnsureAllowed(…, Generate)` first, then create + lock + run in the background → `GenerationRun`: latest job, `Changed`, `Completion`), `Resume` (blocked check again; Paused / Interrupted → resumed, Failed → retried, WaitingForReview → approved, Running without a runner → interrupted then resumed; busy, not found, closed → `GenerationJobException`), `RegenerateGlossary` (task 54: a job waiting for review only; the glossary cut to `GlossaryReview.ForRegenerate` (the player's edited entries and form of address; the agent's entries and tone go) before the Glossary stage runs again, after which the job waits for the review again), `EditGlossary(folder, change)` (task 54: under the job lock, a job waiting for review only, saved at once), `Cancel` (a job not running). Stage handlers are given per job by the caller (tasks 49–51). **Progress** (`GenerationProgress.Of`, pure): percent from stage weights (Setup 5 %, Extract 5, Glossary 10, Translate 70 by chunks, Build 10; < 100 until completed), the Translate chunk counter, ETA = mean time per finished chunk × chunks left + 5 min for Build, else the estimate × the share left, else none. **Auto-resume** (`GenerationResumeSchedule` pure: due = paused by the limit with `ResumeAt` ≤ now; `GenerationResumeScheduler.TickAsync` resumes them, a busy / blocked one is tried on the next tick). **Activity** (`GenerationActivity.Follow(run)`): a running job is the panel's running task (`ActivityTaskKind.Generation`, words from the host, `Pause` / `Cancel` hooks), ended when it stops running; `GenerationJobStates.Of(job)` → the library's `GenerationJobState`. Agents: `AgentStepRun.RunAsync` runs an agent for a step and maps its end (succeeded → the stage decides; limit → `LimitReached` with the reset; signed out / failed / program missing → `Failed`; cancelled → `OperationCanceledException`). Desktop: background startup step *Checking generation jobs* (`AppStartup.JobsStep`: recovery; interrupted → warning naming the games, none → skipped, else "N generation jobs in progress"); the Generation tab's start form, the header action, the tab % and the library's job state come with task 52 (see _Generation tab_ in `docs/desktop-app.md`: `GenerationService` starts and follows the app's jobs); Activity rows and the app's resume timer with task 53: `GenerationService.StartAutoResume` (at app start) runs `GenerationResumeScheduler` now and every 30 s (`ResumeDueAsync`; a game that left the library is skipped), `Pause` / `ResumeAsync` / `CancelAsync(deleteFolder)` (a running job is cancelled through its run, then `WorkingCopies.Delete`), `Recover` (start-up crash recovery, which re-reads the open jobs and tells the pages, so a job read before recovery doesn't stay "running"), `ReadDetails` (`progress.json` + `GenerationJobLog.Tail`: the last lines, read from the end ≤ 64 KiB, a cut line left out); Core `GenerationJobState` carries the job's phase, its resume time and failed stage (see _Generation tab_ in `docs/desktop-app.md`). CLI (see _Generation pipeline_ for the stages): `gen run <game> [--agent claude|codex (default: `AppSettings.DefaultAgent`, else claude) | --fake-agent <recording>] [--lang] [--review-glossary] [--all-files] [--model] [--update (task 56, see _Update mode_)] [--until setup|extract|glossary|translate] [--workers 1–8 (Translate chunks at once; default `AppSettings.TranslateWorkers`, see _Translate stage_)] [--wait]` (a line per change: `55% running Translate (chunk 2 of 2), 50 of 64 strings, about 5 min left`; after each chunk the strings it just translated, `  <original> → <translation>`, when new, and `  agent so far: N runs, X input + Y cached, Z output tokens[, $c]`; a completed job ends with `Local pack <id>: <folder>` and its coverage, test run, fonts, validator warnings, in-game language and size lines, as `pack local` prints them), `gen resume <game> [--fake-agent <recording> (required for a fake-agent job)] [--until] [--workers] [--wait]` (the job's own agent; `--wait`: a limit pause is waited out through the scheduler, then the job goes on), `gen status [<game>]`, `gen cancel <game> [--delete]`; exit 1 = failed, interrupted, refused (blocked game, an open job already, none to resume). ## Generation pipeline

(task 49, `AiLocalPack.Pipeline` = Core + Toolkit + Agents + Mcp, used by the CLI and, with task 52, the app): `GenerationPipeline.Create(PipelineServices(game, PipelineAgent, RecipeTools, GenerationEstimator, WorkingCopies, budget?, BuildServices?), later stages, pauseBefore)` = the stage handlers Setup, Extract, Glossary, Translate, Build (when `BuildServices` is given, see _Build stage_) + the caller's later ones. `GenerationStages.PauseBefore` (Core): once the job reaches that stage the runner pauses it as if by the player, before running it (CLI `--until`; not before Setup). **Setup** (`SetupStage`): the working copy again from scratch (task 46; disk full → failure kind Disk). **Extract** (`ExtractStage`, decided): the recipe tool of the copy's engine extracts directly and **no agent runs** for a known engine (its extraction is complete by construction and the glossary agent reads every string anyway); an unknown engine, one switched off on this OS or without a tool: the agent writes its own extractor (see _Unknown engines_; without an agent, in tests, the stage fails, Toolkit kind); no strings → failed; the result goes to the job folder's `source.json` (`SourceStringsFile`, `GenerationFiles.SourcePath`: `{schemaVersion: 1, engine, tool, toolVersion, files, strings: [{key, original, context?, maxLength?, maxLengthUnit? (`ToneForPrompt`, pronoun pairs per language in `FormsOfAddress`; the template is unchanged, so no new prompt version). **Agent runs** (`PipelineAgent`): program found (else AgentMissing) and sign-in checked first (signed out → SignedOut, nothing run; unknown → runs), then headless in the working copy with **only the toolkit server** (no built-in file, edit or shell tools), the system prompt appended, the job's model; limit / failure / cancel as `AgentStepRun`; every event appended to `logs/agent-<stage>.jsonl` (`AgentEventJson`) and a line per message (≤ 400 chars), tool call, tool error, usage and the end to `logs/job.log`, plus the agent's version and the prompt versions used. **Toolkit server** (`ToolkitServerProgram`): the desktop app's hidden mode (`DesktopApp(AppLaunch)`) or the CLI's `mcp` command (`Cli`), `--root <copy> --job <job folder> --lang <tag>`, with `AILOCALPACK_HOME` and `AILOCALPACK_TOOLKIT_ALL_ENGINES` passed on in the server's environment (agents don't pass every variable to their servers). **Prompts** (decided): versioned resource files `src/AiLocalPack.Pipeline/Prompts/<name>.v<N>.md` (embedded), plain text with `{{field}}`s and no logic (`PromptTemplate`: a missing value or a value with no field throws; `Label` = `glossary v1`); a change that alters what the agent does is a new version file; `system.v1` (headless: never ask, decide; only the `ailocalpack` tools, never change game files; target language + tag; short summary at the end) and `glossary.v1` (read every string up to 3,000, else the first 3,000 + interface texts + `search`; names, world terms, recurring interface words, typically 20–150 entries; term as written, base-form translation, `keepAsIs`, note with gender / speech, part of speech and gender for inflecting languages; tone and form of address in one or two sentences; `put_glossary` ≤ 50 entries a call; don't translate yet). Field values (`PromptValues`): game name, engine display name, language English name (`CultureInfo.EnglishName`, the tag when unknown), tag, string and file counts (`1,234`). Rendered prompts are snapshot-tested (`tests/AiLocalPack.Pipeline.Tests/Snapshots`, `AILOCALPACK_UPDATE_SNAPSHOTS=1` rewrites them). ## Translate stage

(task 50, `Pipeline/TranslateStage`, `TranslationChunks`, `GlossaryFilter`, `PipelineProgress`): **chunks** are planned once, by the Extract stage (`ChunkPlanner.Plan(tool, strings, ChunkBudget)`), and stored in the job folder's `chunks.json` (`{schemaVersion: 1, chunks: [{keys: [key]}]}`; a key in one chunk only), so a resumed job keeps the same chunks and `counters.chunks` = their number. Order = keys compared with digit runs as numbers (`NaturalKeyComparer`: `…/list/2` before `…/list/10`, the game's order); groups = the file or scene of a key per tool (`ChunkPlanner.Group`: RPG Maker / Unity the file, Ren'Py dialogue its label (`say:start_1a2b3c4d` → `say:start`) and string translations one group, Godot the scene / translation keys one group, Unreal resource + namespace, else before the last `:`); a chunk ends at a group boundary when the next group doesn't fit and it is at least half full, a larger group is cut into consecutive pieces. **Budget** (`ChunkBudget.Default`, a guess to tune): ≤ 50 strings (`GenerationEstimateModel.StringsPerChunk`) and ≤ 4 000 estimated tokens (original + context / 4 + 20 per string); a single larger string gets its own chunk. **A step** = the next `TranslateOptions.Workers` chunks from `counters.chunksDone` on, **side by side** (decided 2026-11-13: one agent run each, so each starts its own toolkit server; `Workers` = Settings → AI agents → *Chunks translated at once*, `AppSettings.TranslateWorkers`, default **2** so a player's PC isn't loaded much, 1–8, read when the job starts or resumes; the CLI's `--workers` overrides it; `TranslateOptions.Default` = 1 in tests). The step waits for all of them; a chunk that stops (limit, sign-out, failure) ends the step with the first stop in chunk order once the others are over, the others' translations stored, so on resume their chunks need no agent run; else `ChunkDone(translated, chunks)` advances `chunksDone` by the window. Concurrent writes: `put_translations` reads, changes and writes `strings.json` under the store's lock (`GenerationFiles.LockStrings`: `strings.lock` in the job folder opened `FileShare.None`, waits up to 30 s), as does the stage removing refused texts; `progress.json`, `logs/job.log` and the transcript are written one at a time in the app's process; side by side, each agent log line starts with `Chunk N of M: `. **Each chunk**: its strings without a stored translation (already translated ones, e.g. before a limit or a crash, are never asked again; none left → no agent run), each as one JSON line (`key, original, context, maxLength (+ "display width…" unit), placeholders`) in the `translate.v1` prompt with the tone and only the glossary entries its originals mention (`GlossaryFilter`: case-insensitive, the term must start a word in spaced scripts so plurals / inflections match, any occurrence in Chinese / Japanese / Thai); the agent stores through `put_translations` (which refuses errors). Then every stored text of the chunk is checked again with `StringValidator`; missing or refused strings go back with `translate-retry.v1` (each with its `problem`: "no translation was stored for it" or the refusal) up to `TranslateOptions.MaxAttempts` = 3 runs in all; warnings are kept; strings still missing after that stay untranslated (logged, the job goes on), a stored translation still with errors is removed; a chunk where the agent stored nothing at all fails the stage (Agent kind). `ChunkDone(translated)` = the store's translated source keys − the job's count (so a re-run step never counts twice). A limit / sign-out / failure stops the step as `AgentStepRun` maps it (the stored part kept). **Progress** (`progress.json`, best effort, display only: `{schemaVersion: 1, recent: [{key, original, translation, warning?}] (last 3 the step translated, with the first validator warning's rule), usage: {runs, inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens, costUsd?}, agent?: {version?, model?}, warnings?: [{key, rule, original, translation}] (every stored translation with a warning; a step replaces its chunk's), limit?: {used 0–1, window?, resetsAt?} (the agent's last `AgentLimitStatus`, written at once), build?: {step (checking, rebuilding, fonts, testRun, packing; an unknown one reads as none), files, swappedFonts?, replacement?} (the Build stage's step, task 53)}`; every `PipelineAgent` run adds its usage events, so the glossary run counts too, and the agent program's version and the model of its last session (`AgentSessionStarted`, else the job's model option), which the Build stage puts in the manifest) feeds the CLI and the Generation tab's progress card (task 53). Checked (2026-11-08) with Claude Code 2.1.319 on the RPG Maker MZ fixture (`ru`): 64 strings in 2 chunks of 32, ~13 s each, all placeholders kept (`\C[1]Эш\C[0]`), ~$0.29 in all; SIGTERM mid-chunk → interrupted, the agent's tree stopped, `gen resume` redid chunk 1 and went on to Build.

## Build stage

(task 51, `Pipeline/BuildStage`, `LocalPackBuilder`, `GameTestRun`; Core `Packs/LocalPackStore`, `Generation/TestRun`): **one step, no agent** (`BuildServices(FontFixer, LocalPackStore, IGameTestRunner)`). (1) An overlay a crash left in the working copy is undone (`TestRunOverlay.Recover`), so the step is safe to repeat. (2) **Translations** (`LocalPackBuilder.Collect`, pure): every extracted string against `strings.json`, in source order: missing / empty → untranslated; a stored text the validator now refuses (an error) → left out (logged) and untranslated; warnings kept with original and translation (the `untranslated` rule left out: a text equal to the original is counted as *kept as is* and **counts as translated**, names and "HP" are deliberate); none accepted → failed (Agent kind). **Coverage** = accepted / every extracted string. (3) **Rebuild** from the working copy (it stays the game as extracted) by the source's recipe tool into the job's `build/` (emptied first), then the font swap (`FontFixer.ApplyAsync`, no preferred fonts: the language's whitelist order) into the same folder; a font that can't be downloaded fails the stage (Toolkit kind, retry when online); a `RecipeException` → Toolkit, a disk error → Disk; touched files = `tool.TouchedFiles(copy, accepted keys)` hashed in the copy. A Steam game without a build ID fails before rebuilding (the manifest must name its build). (4) **Test run** (`GameTestRunner`, decided): the program = `GameLaunchPlanner.PlanProgram(copy, os, candidates, watchable: true)` with candidates as for a manual game (the engine's main executable, else the catalog's, then `FolderRecognizer.ListExecutables`), never through a store; watchable = a macOS bundle starts its own binary (`MacBundles.Executable`: `CFBundleExecutable` of an XML `Info.plist`, else the only file in `Contents/MacOS`) since `open` returns at once. **Skipped** (recorded, the pack is saved untested; `TestRunSkip`): no program (`NoExecutable`), a program for another OS (`OtherPlatform`: the RPG Maker / Godot fixtures' `Game.exe` stub off Windows), a Windows program with SteamStub's `.bind` PE section (`SteamDrm`: it only runs when Steam starts the installed game), the OS refusing to start it (`StartFailed`), test runs off (`TestRunOptions.Enabled`, `TurnedOff`). Otherwise the rebuilt files are laid over the copy (`TestRunOverlay`: the job folder's `test-run/added.txt` lists the files the run adds before they are written, `test-run/originals/` holds the copy's files moved aside; undone in `finally`, so the copy is the game as it was) and the program runs with standard output / error to `logs/test-run.log` (≤ 5 000 lines; the last 10 error lines are the detail) for `TestRunOptions.Watch` = **15 s**: still running → **passed** (the process tree is closed); closed earlier → the **untranslated copy** is run the same way: it keeps running → **crashed** (stage failed, `GenerationFailureKind.TestRun`, "Test run failed: the game closed with exit code N X s after start, while the untranslated copy kept running: <error lines>"; no pack saved; `gen resume` retries the stage), it closes too → skipped (`ClosesUntranslated`: the game needs its store, or the movies and audio the `WithoutMedia` copy leaves out). A **Steam game** gets `steam_appid.txt` (its app ID) next to the program and `SteamAppId` / `SteamGameId` in its environment, so the Steam API doesn't restart it through Steam (which would start the installed game, not the copy); the file is removed with the overlay. Not handled: a launcher that exits while a child it started keeps running (reads as closed, then skipped; the child is left running); the game writes its settings and saves where the installed game does. (5) **Local pack** (`LocalPackBuilder.Manifest`, pure, + `LocalPackStore.Save`): ID = the job's earlier local pack of the same language (a stage run again replaces it), else the agent's manifest ID made free among local packs of the game + language (`claude-code`, `claude-code-2`…; `LocalPackStore.FreeId`); title `<agent name> translation`; author and revision 1 by `local-author` (`LocalPackStore.PlaceholderAuthor`, decided: a valid login a manifest needs until GitHub sign-in, task 58; publishing puts the player's login, task 60); status `alpha`; agent = manifest ID (`claude` → `claude-code`, `codex`) + version + model from `progress.json`; one build (Steam build ID; none for an `fp:` game) with the touched files' hashes; recipe = the tool + this app's version of it; fonts = the swapped-in whitelist font; no dependencies (no toolkit tool needs one); coverage; created = updated = now in whole UTC seconds; string table = the accepted translations (gzip). The saved folder is checked with `PackValidator` (a failure deletes nothing but fails the stage as unexpected). Counters: translated = accepted translations. **Store** (`LocalPackStore`, `AppPaths.LocalPacks` = `<data>/local-packs`, decided): pack folders laid out exactly like the registry (`games/<game folder>/<language>/<id>/manifest.json` + `strings/strings.json.gz`, so `pack validate` checks them as registry CI would and task 60 commits them as they are), the **build report** apart (a pack folder holds nothing else) in `reports/<game folder>/<language>/<id>.json` = `{schemaVersion: 1, job, created, testRun {outcome passed|crashed|skipped, skip?, detail?, ranMs?, exitCode?}, fonts {checked, replacement?, swapped, uncovered}, warnings [{key, rule, message, original, translation}], untranslated [{key, original}], keptAsIs, sizeBytes, inGameLanguage?}` (original texts stay on this machine); `Save` writes the pack into a temp folder next to its place and renames it in (a crash leaves the old pack or the new one), then the report; `List(game?)` (never throws; a pack whose manifest or report is broken or newer is logged and left out), `FindByJob`, `Find(game, language, id)`, `UpdateReport` (task 55: the player's marks `tried` (UTC, the first game session closed with it installed) and `shareDismissed` in the same report, still schema 1), `Delete`. Desktop `LocalPacks` (task 55) wraps it for the result and Packs → Mine (installed check, delete refused while installed, tried-in-game detection from `GameSessions`, `Changed`). CLI `pack local [<game>]`: `<game> <language> <id> (job <id>): <folder>` + the lines `coverage: T of N strings[ (K kept as is)][, U stay untranslated]`, `test run: <outcome> (<detail>)`, `fonts: …`, `validator: N warnings`, `in game: …`, `size: N bytes`; none → `No local packs.`. Packs → Mine and the result card read them (task 55; see _Generation tab_ and _Packs tab_ in `docs/desktop-app.md`). Checked (2026-11-09, macOS) with the fake agent on the RPG Maker MZ fixture (`AILOCALPACK_TOOLKIT_ALL_ENGINES=1`, every string as `Жёлтый <original>`): 13 files rebuilt, Fixture Sans swapped for Noto Sans, test run skipped (`Game.exe` is a Windows program), `pack validate` valid, 3.1 KB; with a `Game.sh` added to the copy: still running after 15.1 s → passed (it saw `SteamAppId=620` and `steam_appid.txt`, both gone afterwards, the copy identical to the game); a script exiting 3 on Cyrillic data → `Build failed: Test run failed: the game closed with exit code 3 0 s after start, while the untranslated copy kept running: TypeError…`; one exiting 1 always → skipped (`ClosesUntranslated`).

## Update mode

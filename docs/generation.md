# Generation: agents, MCP server, jobs, pipeline

Agent adapters (Claude Code, Codex, fake), agent install and sign-in, toolkit MCP server, job folders and size estimate, generation jobs, pipeline stages, translate stage, build stage and local packs, update mode, unknown engines, translation quality. ## Agent adapters

(`AiLocalPack.Agents`, task 40): `IAgentAdapter` = `Id` (`claude`, `codex`, `fake`; stored in jobs), `DisplayName`, `DetectAsync` → `AgentInstallation` (agent ID, executable, version, `AgentSource` Path / Managed / Configured, leading `Arguments`) or `null`, `GetAuthStatusAsync` → `AgentAuthStatus` (SignedIn / SignedOut / Unknown, account, detail; never reads tokens), `RunAsync(installation, AgentRunRequest, ct)` → `IAsyncEnumerable<AgentEvent>`. Request = prompt (on standard input where the agent allows it: no command-line limit), working folder (the only one file tools may touch), system prompt appended, `AgentMcpServer`s (name, command, args, env; all their tools allowed), `AgentBuiltinTool`s (ReadFiles / EditFiles / RunCommands / WebSearch, none by default), model, `AgentEffort` (low / medium / high, `null` = the agent's default), session to resume. **Normalized events**: `AgentSessionStarted` (session ID, model), `AgentMessage`, `AgentToolCall` (ID, name, input JSON), `AgentToolResult` (call ID, output, error), `AgentUsage` (input / output / cache read / cache write tokens, cost USD?), `AgentLimitReached` (reset time?, message), `AgentError` (`Malformed` / `SignedOut` / `StartFailed` / `Reported`), `AgentDiagnostic` (a standard error line), `AgentDone` (outcome `Succeeded` / `Failed` / `LimitReached` / `SignedOut` / `Cancelled`, result, message, exit code). **Contract** (decided; `AgentAdapterContractTests` in Agents.Tests, every adapter subclasses it with its own transcripts of the `AgentContractScenario`s): the stream never throws, not even for cancellation, and ends with exactly one `AgentDone`; final outcome = cancelled (token or kill) → a limit event seen → a `SignedOut` error seen → the agent's own verdict (a success with a non-zero exit code becomes Failed) → Failed "ended without a result" / "exited with code N", with the last 20 standard error lines (≤ 2 000 chars); a line that can't be read → `Malformed` and the run goes on; a second verdict is ignored; stopping the enumeration kills the process tree. `ProcessAgentAdapter` (base of process-driven agents) keeps it: an adapter gives the `ProcessSpec` of a run and a fresh `IAgentOutputParser` per run (`ParseLine` for standard output, `ParseErrorLine` → diagnostic by default). **Process runner** (`Agents/Processes`): `IProcessRunner.Start(ProcessSpec, ct)` (file + argument list, no shell, working folder, environment changes (`null` removes), standard input text then closed; missing program / folder → `ProcessStartException`) → `IRunningProcess` (`ReadLinesAsync` = standard output and error lines as they arrive, `ProcessLine` with stream and `Truncated`; `Exit` → `ProcessExit(code, killed)`; `Kill` = whole tree through `Process.Kill(entireProcessTree: true)` on every OS; disposing kills a live process). `ProcessRunner`: UTF-8 (no BOM) both ways, lines cut at 8 Mi characters (`ProcessRunnerOptions.MaxLineLength`), the output ends 2 s after the process exited even if a left-over grandchild still holds the pipes (`OutputGrace`), cancellation kills the tree. `RunToEndAsync(spec, timeout)` → `ProcessResult` (exit code or `null` = timed out and killed, stdout, stderr) for `--version` / sign-in probes. **Fake agent**: `AgentEventJson` writes / reads events as one JSON object per line with a `type` (`session`, `message`, `toolCall` with `input` as JSON, `toolResult`, `usage`, `limit` with UTC `resetsAt`, `error`, `diagnostic`, `done`; enums camelCase, unknown properties ignored; a bad line → the reason). `FakeAgentReplay` = the fake program: writes a recording's lines to standard output as they are, except control lines `{"control": "delay" (ms) / "stderr" (text) / "prompt" (message with standard input) / "cwd" (message with the working folder) / "write" (path relative to the working folder + text: a file such as `../glossary.json`, standing in for what a real agent stores through MCP tools) / "exit" (code) / "hang" / "child" (recording: starts another replayer sharing the outputs, `child-pid N` on standard error)}`; end of file = exit 0; an unreadable recording or bad control = exit 2. Hosted by the test program `tests/AiLocalPack.FakeAgent` (Agents.Tests run it through the `dotnet` host) and by the hidden CLI command `agent replay <recording>`. `FakeAgentAdapter(runner, FakeAgentReplayer, recording, authState)` runs it with the prompt on standard input and reads `AgentEventJson` lines (MCP servers, tools, model ignored). CLI `agent run --fake <recording.jsonl> [prompt] [--cwd <dir>] [--json]` / `agent run <agent> <prompt> [--cwd] [--allow read|edit|run]… (default read) [--model] [--resume <session>] [--system-prompt <text>] [--json]`: one line per event (`session`, `message`, `tool`, `result`, `usage`, `limit`, `error`, `stderr`, `done`) or `AgentEventJson` lines; exit 0 = succeeded, else 1; Ctrl+C / SIGTERM kills the agent's tree and ends `Cancelled`. `agent probe <agent> [--json]`: program (+ found on PATH / installed by the app), version (+ too old), sign-in; JSON `{agent, name, found, executable, source, version, supported, auth (signedIn|signedOut|unknown), account, detail}`; exit 0 = found, supported and signed in. `AgentAdapters` = the real adapters by ID (`claude`, `codex`). **Programs** (`Processes/AgentPrograms`, shared by both): `Candidates(AgentProgramLayout)` = every `PATH` folder (Windows `<name>.exe` before npm's `<name>.cmd`; quoted entries unquoted, relative ones ignored), then the installers' folders, because an app started from the desktop doesn't get the shell's `PATH`: the layout's home folders, on Unix its Unix ones + `/opt/homebrew/bin`, `/usr/local/bin`, `~/.npm-global/bin`, on Windows `%APPDATA%\npm`; then the app-managed folder (task 43, `AgentSource.Managed`); a file counts with an execute bit on Unix; `DetectAsync` = the first answering `--version` (10 s; first `major.minor.patch[-pre]` of the output), else the first found without a version. `Process` = the program with its argument list, its own folder put first on the process's `PATH` (an npm install is a `#!/usr/bin/env node` script or a `.cmd` shim and node sits next to it: found by checking Homebrew's `codex` from an app without `/opt/homebrew/bin` on its `PATH`), a Windows batch file through `cmd.exe /d /s /c "…"` with a raw line, each argument quoted for the C runtime then every cmd metacharacter `^`-escaped twice (`WindowsCommandLine`, npm cross-spawn's scheme; not yet checked on a Windows machine). **Commands** (`AgentSandbox`, task 57): a run with `RunCommands` gets `TMPDIR` / `TMP` / `TEMP` = `<working folder>/.tmp` (made before the run), so scripts' temporary files stay in the only folder the agent may write. `AgentRunProcess` = a run's `ProcessSpec` + `ScratchDirectory` (files made for the run, deleted after it; failing to write them ends the run as `StartFailed`). `ProcessSpec.RawArguments` (Windows) = a command line passed as is instead of the argument list.

## Claude Code adapter

(`Agents/Claude`, task 41; flags checked against the CLI reference and `claude --help` of 2.1.319, 2026-11-08): **minimum version 2.1.259** (`ClaudeCodeCommandLine.MinimumVersion`; `--restricted` 2.1.248, `--permission-prompts` 2.1.259), older = not supported. **Detect** (`ClaudeCodeLocations.Layout`): `AgentPrograms` with `~/.local/bin` (native installer, every OS) and Unix `~/.claude/local`; `--version` = `2.1.319 (Claude Code)`. **Sign-in** (decided probe): `claude auth status --json` (15 s; local, no API call, no token read by the app): exit 0 + `loggedIn` → signed in (account = `email`, else "API key" / "Cloud provider"), `loggedIn: false` → signed out, anything else (no such command, timeout) → unknown with its words. **Run**: `claude -p --output-format stream-json --verbose --input-format text --restricted --disable-slash-commands --permission-mode dontAsk --permission-prompts none --strict-mcp-config [--mcp-config <file>] --tools <list> [--allowedTools <list>] [--append-system-prompt-file <file>] [--model] [--resume]`, the prompt on standard input, in the working folder. `--restricted` confines the file tools to the working folder (checked: a Read of `/etc/hosts` is refused) and ignores the player's user / project settings (hooks, plugins, permission rules); `--safe-mode` is not used: it also drops `--mcp-config` servers (checked). `--tools` = Read, Glob, Grep (ReadFiles) / Edit, Write (EditFiles) / Bash (RunCommands) / WebSearch, WebFetch (WebSearch: `--restricted` drops WebFetch unless `--tools` names it), `""` = none; `--effort low|medium|high` for the request's effort; `--allowedTools` = those + `mcp__<server>` per MCP server (all its tools); anything else is denied without asking. **Commands** (task 57, checked with 2.1.322 on macOS 2026-11-10): a run with `RunCommands` gets `--settings <file>` = `{sandbox: {enabled: true, failIfUnavailable: true, autoAllowBashIfSandboxed: true, allowUnsandboxedCommands: false, network: {allowedDomains: [], strictAllowlist: true}}}` (`ClaudeCodeCommandLine.SandboxSettings`): Bash runs in Claude Code's sandbox (Seatbelt on macOS, bubblewrap on Linux), writes only in the working folder and `$TMPDIR` (moved into it), no network (a write to `../game` and to `/tmp` refused, `curl` refused, writes in the folder worked); without `failIfUnavailable` + `allowUnsandboxedCommands: false` a sandbox that failed to start (a missing `$TMPDIR`) ran the commands **unconfined**, with them the agent refuses to run them. **Without a sandbox, with consent** (2026-11-15): Claude Code 2.1.325 on Windows has its sandbox behind a feature gate that is off, so such a run ends at once with `Sandbox required but unavailable: …` (in the `result` errors, or on standard error); the parser adds `AgentError` `SandboxUnavailable`, `AgentStepRun` makes it the failure kind `SandboxUnavailable`. The player may then allow the job's commands to run without it (`GenerationOptions.Unsandboxed`, see _Unknown engines_): such runs (`AgentRunRequest.AllowUnsandboxed`) get `ClaudeCodeCommandLine.UnsandboxedSettings` = the same with `failIfUnavailable: false`, so the sandbox is still used where it starts and the commands run with the player's rights and network only where it can't; reads stay open (the game copy is read with shell commands); `--restricted` still confines Read / Edit / Write to the working folder. MCP config `{mcpServers: {name: {type: stdio, command, args, env}}}` (names `[A-Za-z0-9_-]`, unique, else `StartFailed`) and the system prompt are files in a scratch folder under the temp folder (no quoting or length limits), deleted after the run. **Parser** (`ClaudeCodeParser`): `system/init` → session (ID, model); `assistant` text → message, `tool_use` → tool call (input as raw JSON), thinking left out; an assistant `error` (Agent SDK `SDKAssistantMessageError`): `authentication_failed` / `oauth_org_not_allowed` → `SignedOut`, `rate_limit` → limit, else `Reported`, in its text; `user` `tool_result` → tool result (text or text blocks joined, `is_error`); `rate_limit_event` `rejected` → limit at `resetsAt` (`allowed` / `allowed_warning` → `AgentLimitStatus`: the used share of the event's window, `unifiedWindows[rateLimitType].utilization`, else `utilization`; task 53) (Unix seconds; `credits_required` worded apart), `allowed` / `allowed_warning` left out; the limit is reported once (the event's reset time wins, else old `…|<unix seconds>` text); `result` → usage of the whole run (input, output, cache read, cache creation tokens, `total_cost_usd`) then the verdict (`success` without `is_error` → succeeded with `result`, else failed with its text or `errors`); unknown types left out, a line without a JSON object `type` → `Malformed`. Transcripts recorded from Claude Code 2.1.319 in `tests/fixtures/agents/claude` (paths shortened; the limit one made by hand from the SDK reference, see its README); the contract tests run on them.

## Codex adapter

(`Agents/Codex`, task 42; flags checked against `codex exec --help` of 0.167.0, the config reference and `codex-rs/exec/src/exec_events.rs`, 2026-11-08; no minimum version enforced, `CodexAdapter.CheckedVersion`): **Detect**: `AgentPrograms` with `~/.local/bin`; `--version` = `codex-cli 0.167.0`. **Sign-in**: `codex login status` (15 s, writes to standard error): exit 0 + `Logged in using ChatGPT` / `…an API key…` → signed in (account ChatGPT / API key), `Not logged in` → signed out, else unknown with its words. **Config** (decided): `-c` overrides with `--ignore-user-config --ignore-rules` (the player's `config.toml` and `.rules` ignored, sign-in still from the player's `CODEX_HOME`), not a generated `CODEX_HOME` (it holds the sign-in too); features off through `-c features.<x>=false`, which an older Codex ignores with a notice, while `--disable <x>` refuses an unknown name. **Run**: `codex exec --json --skip-git-repo-check --ignore-user-config --ignore-rules --color never --cd <dir> --sandbox read-only|workspace-write -c approval_policy="never" -c web_search="disabled"|"live" (live only with WebSearch: the search runs on OpenAI's side, the sandbox's network stays off) [-c model_reasoning_effort="low|medium|high"] -c features.<x>=false… [-c sandbox_workspace_write.network_access=false -c …exclude_slash_tmp=true -c …exclude_tmpdir_env_var=true] [-c mcp_servers.<name>.command|args|env|default_tools_approval_mode="approve"|required=true] [-c developer_instructions="<system prompt>"] [--model] [resume <session>] -`, the prompt on standard input. Always off (`CodexCommandLine.DisabledFeatures`): apps, plugins, remote plugins, hooks, browser use (+ external), computer use, in-app browser, image generation, sub-agents, memories, skill dependency installs, tool suggestions. Sandbox: Codex sandboxes **writes and the network, not reads**; no edit / command tools → `read-only`, EditFiles or RunCommands → `workspace-write` with only the working folder writable (checked: a write outside it failed, the edit inside worked), no network; Codex reads through its shell, so ReadFiles keeps the shell tools (read-only commands), and with neither reading nor commands `features.shell_tool` / `unified_exec` are off and only MCP tools remain. MCP tools need `default_tools_approval_mode="approve"` (else "requires approval, but approval policy is never", checked); MCP server names must be bare TOML keys (`[A-Za-z0-9_-]`, unique, else `StartFailed`); values are TOML basic strings (`CodexCommandLine.Toml`). The system prompt goes on the command line (`developer_instructions`): cmd.exe's 8 191-character limit applies to an npm `codex.cmd` on Windows. Commands (task 57) need nothing more: `workspace-write` confines them to the working folder without network, and `AgentSandbox` moves the temporary folder inside it (Codex's sandbox excludes `/tmp` and `$TMPDIR`). **Parser** (`CodexParser`): `thread.started` → session (thread ID, the requested model: Codex doesn't name it); items: `agent_message` → message (the last = the result), `command_execution` → tool `command` `{command}` (result = output, error when exit code ≠ 0 or failed / declined), `file_change` → tool `file_change` `{changes}` (result = `kind path` lines), `mcp_tool_call` → tool `mcp__<server>__<tool>` with its arguments (result = text blocks or error), `web_search` → tool `web_search`; a call reported when its item first shows up (a completed item without a start reports both); `error` items → diagnostic; reasoning, to-do lists, updates left out. `turn.completed` → usage (input **without** the cached part, so it means the same as Claude Code's; output; cached input = cache read; cache writes; no cost) then succeeded with the last message; `turn.failed` → failed with its message. Top-level `error`: `Reconnecting... n/5` → diagnostic; `hit your usage limit` → limit, reset time from Codex's own wording (`Try again at 6:10 PM.` = today, `Nov 9th, 2026 6:10 PM`, both in the machine's time zone, `TimeProvider.LocalTimeZone`; `Try again later.` → none); `401 Unauthorized` / `sign in again` / `Not logged in` → `SignedOut` (a signed-out run retries ~10 times over ~30 s first, so the pipeline checks the sign-in before starting); else `Reported`; limit and sign-in each reported once. Transcripts recorded from Codex 0.167.0 in `tests/fixtures/agents/codex` (the limit one made by hand from `UsageLimitReachedError`'s wording); the contract tests run on them.

## Agent install and sign-in

(`Agents/Install`, task 43): `AgentInstaller` puts an agent's **official build** into `<data>/agents/<id>/<version>/` (`AppPaths.Agents`; no Node.js, no admin): Claude Code's program, Codex's whole unpacked package; `<id>/installed.json` (`{schemaVersion, version, executable (relative), installedAt, url, sha256, verification}`) is written last (commit point), so a half-done install is never used; `Find` / `ManagedDirectory` give the folder of the program, which the adapters try last (`AgentSource.Managed`: the player's own copy on `PATH` or in the installers' folders wins, `AgentPrograms.Candidates`). Release per agent from an `IAgentDistribution` for the `AgentPlatform` (OS + `RuntimeInformation.OSArchitecture` x64 / arm64, Linux musl by `/lib/ld-musl-*`). **Claude Code** (`ClaudeCodeDistribution`, decided): Anthropic's own installer source `https://downloads.claude.ai/claude-code-releases`, channel **`stable`** (not `latest`) or the version asked for, `<v>/manifest.json` (per platform `darwin-arm64|x64`, `linux-x64|arm64[-musl]`, `win32-x64|arm64`: `binary` `claude[.exe]` only, `checksum`, `size`), trusted only with a valid detached signature `<v>/manifest.json.sig` by Anthropic's release key **pinned in the app** (`Claude/Files/claude-code-release-key.asc`, fingerprint `31DD DE24 DDFA B679 F42D 7BD2 BAA9 29FF 1A7E CACE`, provenance in its README; checked by our own `OpenPgpSignature`: v4, binary-document type, RSA PKCS#1 v1.5, SHA-256/384/512, issuer = the pinned key, unknown critical subpackets and expired signatures refused, armor CRC-24 checked); versions under `MinimumVersion` refused (`TooOld`). The app's copy runs with `DISABLE_AUTOUPDATER=1` (the app updates it). **Codex** (`CodexDistribution`, decided): what OpenAI's `install.sh` does: GitHub release of `openai/codex` (`releases/latest` or tag `rust-v<v>` via the REST API, `User-Agent: ailocalpack`; unauthenticated, 60 requests / h), asset `codex-package-<rust target>.tar.gz` (Linux = musl builds), program `bin/codex[.exe]`, helpers (`codex-path/rg`, `codex-resources/`) kept in place; OpenAI signs nothing the app could pin (Sigstore bundles for Linux only), so the SHA-256 must be the same in GitHub's asset `digest` and the release's `codex-package_SHA256SUMS`, and both URLs must be that release's `github.com/openai/codex/releases/download/rust-v<v>/` files. **Install** (`InstallAsync(id, version?, progress, ct)`, never throws but for cancellation and unknown IDs): resolve → same version installed → `AlreadyInstalled`, nothing downloaded → download into `<id>/downloads/<sha256[..16]>-<file>` through Core's `VerifiedDownloader` (resumable `.part`, 3 tries, size + SHA-256 checked, mismatch deleted; a cancel keeps the part) → `Unpacking` into `<id>/.staging-<random>` (binary: copied + `rwxr-xr-x`; package: `AgentPackageArchive`, every name checked first: relative, no `..` / drive / backslash, no duplicates ignoring case, only folders and regular files, ≤ 20 000 entries, ≤ 4 GiB, Unix rwx bits kept, never set-ID; a package without the program → `ArchiveInvalid`, the download deleted) → moved to `<id>/<version>` → state written → older versions, stagings and downloads removed (one still running on Windows stays until the next install). **Update** = installing a newer release (`FindReleaseAsync` tells what is current). One install per agent (`<id>/install.lock`, `Busy`). `Uninstall(id)` deletes the state file, then the folder. Progress `AgentInstallProgress(stage Resolving / Downloading / Unpacking, done, total)`. `AgentInstallProblem`: Offline / Timeout / HttpError (may pass, incl. GitHub's rate limit), NotFound, BadVersion, TooOld, NoBuild (no build for this OS / CPU), InvalidMetadata, BadSignature, HashMismatch, ArchiveInvalid, DiskError, Busy. **Sign-in** (`IAgentAccount`, both adapters; the app never reads a token): `SignInAsync` = `AgentSignIn.RunAsync`: status first (signed in → `AlreadySignedIn`, nothing started), then the agent's own login (`claude auth login`, `codex login`: they open the browser and print the URL), its lines passed on, the status asked every 2 s and when the login exits; signed in → done (a login still running 5 s later is killed); exited first → `Exited` with its exit code and last lines; 10 min → `TimedOut`, cancel → `Cancelled` (tree killed); start failure → `StartFailed`. `SignOutAsync` = `claude auth logout` / `codex logout`, then the status. Limit: the login gets a closed standard input, so Claude Code's fallback "paste the code here" (when the browser can't reach its localhost callback) isn't supported; the normal browser flow is. CLI: `agent install <agent> [--version <v>] [--force]` (the player's own copy found → "already installed by you…", exit 0, unless `--force`; prints download progress per 10 %, `Installed <name> <v> into <folder>: downloaded N bytes, <verification>, SHA-256 checked.` + `program:`; failure → one sentence on stderr, exit 1), `agent uninstall <agent>`, `agent login <agent>` (lines indented, `Signed in (<account>).` / `Already signed in…`, Ctrl+C / SIGTERM stops it, exit 1 unless signed in), `agent logout <agent>`; `probe` / `run` look in the app's folder too. Checked on macOS arm64 (2026-11-08): Claude Code 2.1.311 (stable, signature + hash) and Codex 0.167.0 installed under a throwaway home, both run `--version`; `agent probe` with no `claude` on `PATH` reports the app's copy, Codex from Homebrew still wins over the app's.

## Toolkit MCP server

(`AiLocalPack.Mcp`, task 45; official SDK `ModelContextProtocol.Core`, stdio, no hosting package): **entry point** (decided 2026-11-08): an agent starts stdio servers itself, so the **desktop app runs itself in a hidden mode** `<app> --mcp-server --root <game folder> --job <job folder> [--lang <tag>] [--tool <id>]` (`--tool`: the job's reader, _Game reader_) (`ToolkitServerLaunch`: handled first in `Program.Main`, before logging, the single-instance check and Avalonia; only the protocol on standard output, refusals on standard error, exit 1), so players need no second program; `ToolkitServerLaunch.Command(AppLaunch, root, job, lang)` = the command line for `AgentMcpServer` (name `ailocalpack`, tools `mcp__ailocalpack__…`), `AppLaunch.ForCurrentProcess` (Core, shared with autostart: `$APPIMAGE`, `dotnet <dll>`, else the process's executable). The CLI's `ailocalpack mcp --root --job [--lang]` serves the same, for development and manual checks; the separate project is shared by both. A WinExe served over redirected pipes is not yet checked on Windows. **Confinement** (`WorkingCopy.Resolve`): paths relative to the copy, `/` or `\`; absolute, rooted, UNC, drive (any `:`) and any `..` part refused; each component that is a link is followed to its final target, which must exist and lie inside the copy's real path (case rules of `PathNames`), else refused (`PathOutsideRootException`); listings show links as `link` and never descend into them. **Job folder** (`Core/Generation/GenerationFiles`, outside the copy, checked at start): `strings.json` = the string store (plain JSON `StringTable`: translations + the extractor's context notes, atomic), `glossary.json` (`Glossary`: `{schemaVersion: 1, language, tone?, formOfAddress? ("informal" / "formal": the player's choice, task 54; unknown → none), entries: [{term, translation, note?, partOfSpeech?, gender?, keepAsIs?, edited? (the player changed it in the review)}]}`, terms unique ignoring case, a `keepAsIs` term translates to itself, texts ≤ 2 000 chars; task 49 may extend it), `build/` = the latest rebuild. Target language = `--lang`, else the store's (a store in another language refuses to start; with neither, writes are refused). **Tools** (calls serialized, extraction cached per server, `refresh` re-reads): `detect_engine` (engine, confidence, marker, executable, candidates, recipe tool + version or the reason the toolkit can't: unknown, switched off on this OS, no tool), `list_files` (folder, `*`/`?` pattern on file names, recursive ≤ 200 000 entries walked, ordinal order, ≤ 500 per page), `read_file_snippet` (text = numbered lines, ≤ 400, lines cut at 1 000 chars, total lines for files ≤ 32 MB; a NUL in the first 8 000 bytes = binary → hex dump ≤ 4 096 bytes), `extract_strings` (key prefix / search filters; key, original, context, length limit, placeholders, stored translation), `get_strings` (keys asked, else all / translated / untranslated), `put_translations` (unknown keys listed, each validated: errors refused with the issues, warnings stored and reported, empty text removes), `validate_strings` (given texts without storing, else stored ones), `get_glossary` / `put_glossary` (upsert by term, remove, tone; task 54: an entry the player edited is never replaced or removed, listed in `keptByPlayer`, and the player's `formOfAddress` is kept and shown by `get_glossary`), `rebuild` (stored translations → `build/` cleared first; changed / generated files, applied, unknown keys, in-game language; no font swap: task 51). **Unknown engines** (task 57): when the toolkit can't read the copy's engine, the string tools read the agent extractor's `agent/strings.json` of the job folder instead (`AgentScriptTool`, tool `agent-script`, read again on `refresh`); before it exists they say "Write your own extractor: it must write strings.json in your workspace."; `rebuild` refuses ("run your own rebuild script"); `detect_engine` names the `agent-script` tool once the file is there. Results are camelCase JSON, nulls left out, paged by `offset` / `limit` → `total` + `nextOffset` (`null` = last), string and glossary pages also stop at ~20 000 characters. Tool errors are `McpException`s; the SDK sends them as `An error occurred invoking '<tool>': <message>`. The validator is _String validator_ (task 48), with the tool's markup. Checked (2026-11-08) with Claude Code 2.1.319 (`--strict-mcp-config`, only `mcp__ailocalpack` allowed) on a copy of the RPG Maker fixture through the desktop app's hidden mode: detect, extract, put, rebuild into `job/build/data/Items.json`.

## Job folders and size estimate

(task 46, reworked 2026-11-17 for _Live game folder_: Core `Generation/GenerationJobFolders`, `GenerationEstimate`, Toolkit `Generation/GenerationEstimator`): **layout** `<data>/work/<game folder>/<job id>/` (`AppPaths.GenerationJobs`) = the job folder (task 47's `job.json`, `GenerationFiles`, `game.json` naming the game folder it reads); **no copy of the game is made**; a job made before keeps its full copy in `game/` (`LegacyCopyFolder`, still read until its Setup runs again, which deletes it with its `game-originals/`, `DeleteLegacyCopy`). ## Live game folder

(decided and built 2026-11-17; replaced the full working copy of task 46, see _Job folders and size estimate_, and `TestRunCopyGuard` of _Build stage_). Why: a full copy of a game costs as much disk and time as the game, and runs of the copy still differed from the game the player plays (media left out, the game's own settings written where the installed game keeps them).

- **Reading**: the job folder keeps `job.json`, strings, glossary, `build/`, logs and the agent's `agent/` workspace; no `game/`. Extract, the estimate, the MCP server's root and Setup read the game folder itself, read only (no MCP tool writes). The agent of an unknown engine reads the game folder and writes only into `agent/`, where it may copy single files to decompile or study them; its rebuild still writes into `out/`. The disk check counts the backups only.
- **Originals** (`IGameFiles`, Toolkit): recipe tools read through a resolver instead of a bare `gameDir`: the game folder, with each file an installed pack (or a trial) replaced taken from that install's backup, and the files it added hidden. Extract, `TouchedFiles` and Rebuild of generation and update mode use it, so the game stays as the player has it while the agent works (hours).
- **Trial install** (`PackInstaller`): a test run (Build, Fix with AI's `test_run`, the baseline of the untranslated game when a pack is installed) lays `build/` over the game in a transaction like an install (one lock across app and CLI, journal, backup, verify, rollback) with a `trial` record, runs, and takes it off; an installed pack is swapped out for the run and back after. Recovery at start finishes a trial left by a crash (the gap _Build stage_ lists as not handled). Refused while the game runs (`GameRunning`) or a store update changed its build (the stage starts again on the new build).
- **Game writes** (`GameWriteGuard`, replaces `TestRunCopyGuard`): roots = the game folder + the engine's data folders (Unity `<LocalLow>/<company>/<product>` from `app.info`, Godot `user://` per OS from `project.godot`'s name, Unreal `Saved/` under the per-user app data, Ren'Py's saves folder; macOS / Linux equivalents). Before a start: a snapshot (relative path, size, last write time) of every root; a backup (clone where the file system can, else copy) of the files the game wrote in earlier runs (`<data>/test-runs/<game folder>.writes.json`, kept as now) at any size and of every small file (not media, images, fonts or programs, ≤ 16 MB each, ~256 MB in all; over that only the known ones, logged). After the run: added files and folders deleted, changed or deleted files put back from the backup; one changed without a backup is listed (Steam: *Verify integrity of game files*). Steam's `steam_appid.txt` is a file of the trial.
- **Installed packs**: install takes the same snapshot and backup (kept with the install's backup); uninstall puts back what the game rewrote since in the game folder and data folders (caches built from the translation, settings), never saves (the engine's save folders and files, `save*`, `*.sav`, `*.rpgsave`, Ren'Py `saves/`, Unity `PlayerPrefs` kept), and lists what it couldn't.
- **Gone** (step 5, 2026-11-17): `WorkingCopies` (copies, clones, scope, plan, space for the copy; now `GenerationJobFolders`, _Job folders and size estimate_), `gen copy`, `--all-files`, the copy in Settings → Storage (now *Generation jobs*: the job folders with their size), `game-originals/`, the failure kind `WorkingCopy` (now `GameFolder`; an older job's reads as it), the prompts' "a copy of the game" (`system.v2`, `system-scripts.v2`, `extract-unknown.v2`, the fix prompt's workspace text).
- **Built so far** (step 2, 2026-11-17): **Setup** (`SetupStage`) makes no copy: it checks the game folder and the disk for the job's own files (`WorkingCopies.CheckSpace(reserve)` = the rebuilt files + `Margin`; too little → Disk), deletes a `game/` copy an older job left and records the folder in the job folder's `game.json` (`GenerationFiles.WriteGameFolder` / `ReadGameFolder`: `{schemaVersion: 1, folder}`, a newer or broken one reads as none); every step reads it as `GenerationStepContext.GameFolder` (a job set up before keeps its `game/` copy; none → `GenerationFileException`, which `PipelineAgent` turns into a Disk failure). **Reads** go through `GameViews` (Toolkit, `AppPaths`; `WithoutPack(folder)` = `GameFolder`, or `PristineGameFiles` from `InstalledOriginals` when a pack is installed there; `HasPack`): Extract (`ExtractStage(…, views)` from `PipelineServices.Views`, else `BuildServices.Views`), the estimate (`GenerationEstimator` through `WorkingCopies.Originals`; no scratch copy any more), Build's and a fix's rebuild, font swap and build hashes (`BuildServices.Read`), and the MCP server (`ToolkitServerOptions.Game`, set by `ToolkitServerLaunch.WithoutInstalledPack` from the app home of its environment, in the app's hidden mode and `ailocalpack mcp`: `extract_strings`, `rebuild`, `read_file_snippet`). **The agent** works in the job's `agent/` folder (its runs' working folder; Fix with AI shares the player's screenshots and the test runs' pictures there), never the game folder, and gets the game folder as the MCP server's root. **The agent's own reader** (unknown engines) reads the game folder as it is, so with a pack installed Extract and the patch build fail (`WorkingCopy` kind: uninstall the translation, then resume). **Test runs** run on the game folder itself; a game the player has open is skipped (`TestRunSkip.GameRunning`, `IProcessList` + `GameProcessMatcher`; *The game was open, so it wasn't test-run*); deleting a job (`WorkingCopies.Delete`) first puts back what a test run of step 2 left in its job folder (an `IOException` keeps the job).
- **Built in step 3** (2026-11-17): a test run is a **trial** (Core `Install/GameTrials`, `GameTrial`): `TryOpen` takes the install lock (`InstallLock`: no install, uninstall, backup move or other trial meanwhile, app or CLI; ## Translate stage

(task 50, `Pipeline/TranslateStage`, `TranslationChunks`, `GlossaryFilter`, `PipelineProgress`): **chunks** are planned once, by the Extract stage (`ChunkPlanner.Plan(tool, strings, ChunkBudget)`), and stored in the job folder's `chunks.json` (`{schemaVersion: 1, chunks: [{keys: [key]}]}`; a key in one chunk only), so a resumed job keeps the same chunks and `counters.chunks` = their number. Order = keys compared with digit runs as numbers (`NaturalKeyComparer`: `…/list/2` before `…/list/10`, the game's order); groups = the file or scene of a key per tool (`ChunkPlanner.Group`: RPG Maker / Unity the file, Ren'Py dialogue its label (`say:start_1a2b3c4d` → `say:start`) and string translations one group, Godot the scene / translation keys one group, Unreal resource + namespace, else before the last `:`); a chunk ends at a group boundary when the next group doesn't fit and it is at least half full, a larger group is cut into consecutive pieces. **Budget** (`ChunkBudget.Default`, a guess to tune): ≤ 50 strings (`GenerationEstimateModel.StringsPerChunk`) and ≤ 4 000 estimated tokens (original + context / 4 + 20 per string); a single larger string gets its own chunk. **A step** = the next `TranslateOptions.Workers` chunks from `counters.chunksDone` on, **side by side** (decided 2026-11-13: one agent run each, so each starts its own toolkit server; `Workers` = Settings → AI agents → *Chunks translated at once*, `AppSettings.TranslateWorkers`, default **2** so a player's PC isn't loaded much, 1–8, read when the job starts or resumes; the CLI's `--workers` overrides it; `TranslateOptions.Default` = 1 in tests). The step waits for all of them; a chunk that stops (limit, sign-out, failure) ends the step with the first stop in chunk order once the others are over, the others' translations stored, so on resume their chunks need no agent run; else `ChunkDone(translated, chunks)` advances `chunksDone` by the window. Then every stored text of the chunk is checked again with `StringValidator`; missing or refused strings go back with `translate-retry.v2` (each with its `problem`: "no translation was stored for it" or the refusal) up to `TranslateOptions.MaxAttempts` = 3 runs in all; warnings are kept; strings still missing after that stay untranslated (logged, the job goes on), a stored translation still with errors is removed; a chunk where the agent stored nothing at all fails the stage (Agent kind). `ChunkDone(translated)` = the store's translated source keys − the job's count (so a re-run step never counts twice). ## Game reader

(decided 2026-11-14; Core `GenerationOptions.Reader`, Toolkit `Generation/GameReader`, Desktop start form (_Generation tab_ in `docs/desktop-app.md`)): what reads and rebuilds the game is the player's choice **per job, on the start form**: the detected engine's toolkit is preselected, any other engine's toolkit can be picked, or the **AI's own code** (`GenerationOptions.AgentReader` = `agent-script`: the agent writes its own extractor and rebuilder as for an unknown engine, _Unknown engines_, and the pack is a binary patch). `job.json` keeps `options.reader` = a recipe tool's ID, `agent-script`, or nothing (= the detected engine's tool, as every job before; a reader that isn't a slug reads as nothing). **One resolver** (`GameReader.Resolve(tools, detected, reader)` → engine kind, tool, `TextSizeSource`): the estimate (`GenerationEstimator.Estimate(..., reader)`), Setup (the copy's scope: every file without a tool), Extract and the toolkit MCP server (`--tool <id>` from `PipelineAgent`, `ToolkitServerOptions.Reader`; `detect_engine` names the chosen tool, `extract_strings` asks for the agent's extractor) all read the game the same way. Another engine's tool reads the game as that engine (`EngineKind` of the tool, no variant); when it can't (`RecipeException`, the usual case for a game it doesn't fit) the job goes the agent's way as for any toolkit failure, with the tool's message in the prompt. An engine switched off on this OS can't be picked (`EngineDisabled`); a tool this app lacks reads as the detected engine. The AI's own code gives the estimate `TextSizeSource.AgentChosen` (guessed from file sizes, all files copied) and the Extract prompt's engine "…; the player asked for your own reader instead of the toolkit's" (`PromptValues.ExtractUnknown(chosen)`; the template is unchanged). The reader is fixed for an update job (it reads the game as its base pack did: the picker is off, `--tool` refused with `--update`); fix runs and Build follow `source.json`'s tool. CLI: `gen run|estimate --tool <rpgmaker|renpy|godot|unity|unreal|agent>`.

## Translation quality

(decided 2026-11-13; Core `GenerationQuality`, Agents `AgentModels`, Pipeline `StudyStage`, Desktop start form (_Generation tab_ in `docs/desktop-app.md`), design §6a): the player picks how carefully the agent translates **per job, on the start form**, every time; **Balanced is preselected** (not a setting). Extraction is the same for every quality (the toolkit; the agent's own extractor and rebuild scripts for unknown engines always run with the Balanced model, `AgentModels.ForExtraction`); what changes is the model of the later stages and, for Thorough, the approach. **Models** (`AgentModels.For(agent, quality)`; a `--model` the player names wins for every stage, `PipelineAgent.ModelFor`): Claude Code by its aliases for the latest model of a family, so nothing goes stale: Quick `haiku`, Balanced `sonnet`, Thorough `opus`, the agent's default effort; Codex names no stable aliases and its models change often (decided with the player), so its model stays Codex's default and only `model_reasoning_effort` differs: low / medium / high; any other agent (the fake one) runs with its defaults. A model the player's plan lacks fails the run with the agent's own message (no pre-check). **Quick and Balanced** run the same pipeline as before, only the model differs. **Thorough** adds the **Study** stage between Extract and Glossary (`GenerationStage.Study`; `study.v1` prompt): one run of the strongest model reads every string in order (up to 20,000, then `search`) and replies with the **game brief** in English Markdown under fixed headings (Setting, Characters with gender / speech / forms of address, Relationships, The player, Recurring lines with wordplay, Interface, Notes for the target language), quoting at most a few words of the original; the reply is cut to the brief (from its first `## ` heading) and to 24,000 characters at a line end (`StudyStage.MaxLength`, every chunk carries it); none, or under 200 characters → the stage fails (Agent kind). It is stored as the job folder's `brief.md` (`GenerationFiles.BriefPath`, `ReadBrief` / `WriteBrief`) and **stays local** (decided: it may quote the original, so it never goes into a pack or the registry), and the Glossary and Translate runs of a Thorough job get it appended to their system prompt (`system-brief.v1`: follow its genders, speech, forms of address and recurring lines); the glossary and translate prompts themselves are unchanged. **Web lookup** (`GenerationOptions.WebLookup`, Thorough only, the start form's checkbox on by default; CLI `--web`): only the Study run gets `AgentBuiltinTool.WebSearch` (Claude Code's WebSearch + WebFetch, Codex's live web search); the prompt asks for the game's store page, wikis and official translations into other languages, about 20 searches, never the strings' text. Every other run keeps the no-network sandbox. **Estimate** (`GenerationEstimateModel.Estimate(text, basis, quality)`, `GenerationEstimate.At(quality)` so the form switches without reading the game again; guesses to tune with real jobs): Quick = time × 0.6, limits × 0.35; Thorough adds the Study input (every string once more + 60 k) and output (8 k) and the brief in every chunk (4 k tokens), then time × 1.4, limits × 1.7. **Progress** weights of a Thorough job: Setup 4 %, Extract 4, Study 12, Glossary 8, Translate 64, Build 8 (`GenerationProgress.StudyWeights`). **Manifest**: the local pack records the quality as `agent.quality` (`quick` / `balanced` / `thorough`, a slug so a newer app may add values; `PackAgent.Quality`). **CLI**: `gen run … [--quality quick|balanced|thorough] [--web]` (`--web` without Thorough refused; the first line names the quality), `--until study` pauses before the Glossary, `--until extract` before Study (or the Glossary), `gen estimate … [--quality]` (text: `agent time: … (quick)`; JSON: `work.quality`). The job log names the quality, model and effort of every run.

## Fix runs

(task 75, design §6e; Core `Generation/FixConversation` (`FixFiles`, `FixState`, `FixTurn`, `FixAttachment`, `FixChange`, `FixPlan`, `FixRules`), `FixJobState`, `Launch/GameCrashRule`, `Storage/FolderCopy`, `Packs/LocalPackStore.Snapshot / Restore`; Toolkit `Generation/GameLogs`; Pipeline `FixRunner`, `FixPrompt`, prompts `system-fix.v2` + `fix.v4`; Desktop `Generation/FixService`, `ViewModels/GamePage/FixViewModel`): after a job completed, the player tells its agent in their own words what is wrong with the translation, and every change becomes the next **draft** of the same local pack. **A run** (`FixRunner.SendAsync`, under the job's lock, so never beside another fix or a generation run): the request is saved as a player turn in `fix/state.json`; the job's strings, glossary and agent scripts (`FixJobState`: `strings.json`, `glossary.json`, `agent/scripts/`) are copied to `fix/before/`; the job's agent runs once in its `agent/` folder on the game folder (same adapter, quality's model and sandbox as the job; toolkit tools only, or for an unknown engine its scripts workspace with file and command tools; `ReadFiles` always, to look at screenshots (the player's and the test runs'); screenshots are copied into the agent's working folder as `.fix-attachments/` for the run and removed before the build, since `--restricted` keeps the file tools out of `fix/attachments/`) with `system-fix.v2` (a person reads the reply; it may ask one question and end with `Choices: a | b | c`; it can try the game with `test_run` and must not claim it checked what it didn't run) and `fix.v4` (the draft, the request, the attachments rendered by `FixPrompt.Attachments`: the session (seconds, exit code), the game log's tail in a fence, what the draft changes (strings translated, files), screenshot paths, picked strings as JSON lines; the last 6 turns by `FixPrompt.History`; reproduce a crash or missing text with `test_run` first, find the cause, fix it where it is: translations, glossary or the rebuild script; whatever the scripts change beyond the strings, such as a font swap, on by default and described in `scripts/README.md`, which the Build's rebuild run keeps); every tool call becomes a step code (`FixSteps`: the tool name without `mcp__<server>__`, then `app:build`, `app:saved`), streamed to the app; the transcript goes to `logs/agent-fix.jsonl`. **After the run** the translations and glossary entries that differ from `fix/before/` are counted (`FixChange`/`FixPlan` samples: up to 3 before / after rows with the original from `source.json`) and the scripts compared by fingerprint (`FolderCopy.Fingerprint`): nothing changed → an *answered* turn (the reply, its choices); more than `FixRules.PlanThreshold` = **50** strings changed → the job's new state is moved to `fix/pending/`, the job put back, and the turn is a **plan** waiting for the player (decided: the agent's proposed changes are counted before they reach the pack; `ApplyPlanAsync` puts `pending/` into the job and builds without asking the agent again, `DropPlan` deletes it); otherwise the Build stage runs again (`BuildStage`: rebuild, font swap, test run, `LocalPackStore.Save` under the same pack ID, which replaces the pack) and the new pack's report gets `draft` N+1 with the earlier report's `published` and `shareDismissed` carried over. **Drafts**: before a build the current draft is kept in `fix/drafts/<n>/` (`pack/` = `LocalPackStore.Snapshot`: pack folder, report, kept glossary, patch archive; `job/` = the job state it was built from); `FixRunner.GoBack` keeps the current one the same way and restores the chosen one (its report dated now, so an install of another draft reads as not installed, see below); `state.json` = `{schemaVersion: 1, current, drafts [{number, created, turn?}], turns [{id, kind player|agent, at, text, attachments? [{kind session|gameLog|draftChanges|screenshot|strings, name?, path?, keys?, seconds?, exitCode?, lines?}], steps?, choices?, outcome? answered|changed|planned|failed|stopped, change? {draft, strings, terms, scripts?, testRun, samples?}, plan? {strings, terms, scripts?, samples?, state waiting|applied|dropped}, problem?, model?}]}` (atomic; broken → moved aside, empty; newer → never written). **Failures**: an agent run that fails, hits the limit or is stopped, and a build that fails (a crashed test run included), put the job back from `fix/before/` (and the pack from its draft copy) and end the turn *failed* (`problem` in English) or *stopped*; `FixRunner.Recover` (the app reads a job's fixes, the CLI's `gen fix`/`gen drafts`) puts back a job a crash or kill left with `fix/before/` and fails its last request. Limits are not waited out (the player sends again). **Crash** (`GameCrashRule`): a session with the AI translation installed that ends within the game's crash window: **30 s**, or the test run's watch of that game when longer (`GameCrashRule.WindowFor`, `TestRunBaselines.WatchOf`, so a game that loads for a minute and dies right after still counts); `LocalPacks` marks the installed draft's report `crash {at, lastedMs, exitCode?}` instead of tried and raises `Crashed`. The player can overrule it (`LocalPacks.DismissCrash`, the thread's *Not a crash, I closed it*, decided 2026-11-14): the crash goes and the draft is tried at the time the game closed. **Game log** (`GameLogs.Find`, best effort): the newest of the engine's log (Unity `Player.log` under `app.info`'s company / product per OS, Godot `app_userdata/*/logs/godot.log`, a packaged Unreal game's `%LOCALAPPDATA%/<project>/Saved/Logs` on Windows) and any `*.log`, `log.txt`, `traceback.txt`, `errors.txt`, `crash*.txt` in the game folder (4 levels, 5 000 entries) written since the session started (a minute's slack); its last 200 lines (≤ 64 KiB) are kept in `fix/attachments/` (`FixFiles.AddLog`), so the game writing it again changes nothing. **Test runs by the agent** (decided 2026-11-16): a fix run's toolkit server gets `--test-runs 5` and offers `test_run(seconds?)` (`Mcp/TestRunTools`); the server writes `fix/test-runs/<n>.ask.json` and waits up to 15 min for `<n>.answer.json` (`Core/Generation/TestRunMailbox`; the agent's tool timeout is raised to match: Codex `mcp_servers.<name>.tool_timeout_sec`, Claude Code `MCP_TOOL_TIMEOUT`). The app answers while the agent runs (`Pipeline/FixTestRuns`, one ask at a time): it builds the translation as the Build stage would into the job's `test-build/` (the recipe tool's rebuild and font swap; for an unknown engine the files the agent's own rebuild wrote into `out/`, once `translations.json` holds the stored translations: when that file had to change the answer is `rebuildFirst` and doesn't count) and runs `IGameTestRunner` with `AtLeast` = the asked seconds and the screenshots in the agent's working folder (`.test-runs/run-<n>/`, the original copied there), then answers `{outcome passed|crashed|skipped|rebuildFirst|refused|failed, message, runsLeft, ranSeconds?, loadedAfterSeconds?, watchedSeconds?, exitCode?, screenshots? {original, translated, last}, gameLogFile?, gameLog? (last 80 lines of `GameLogs.Find` since the start), crashReport?}`. At most `FixTestRuns.MaxRuns` = **5** game runs per fix (each opens the game on the player's screen; then `refused`). The thread shows each as the step `app:test-run:<n>:<max>` (`FixSteps.TestRun`; the agent's own `test_run` call isn't a step) = "Ran the game to check it (2 of 5); its window opens for a minute or two, don't close it"; `Stop` cancels the agent and the game with it. The mailbox, `test-build/` and `.test-runs/` are removed when the run ends, before the Build. No other new MCP tools: `search`, `get_strings`, `put_translations`, `get_glossary`, `put_glossary` cover a fix. **Installing a draft**: `LocalPacks.IsInstalled` also needs the install to be newer than the pack's report (`created`), so a rebuilt draft under the same ID and revision reads as not installed; `InstallFlow.InstallLocalAsync` replaces an earlier draft of the same pack without the "replaces" dialog. **CLI**: `gen fix <game> "<request>" [--attach <file>]… [--fake-agent <rec>]` (an image is a screenshot, any other file a log; prints the steps, the reply, the choices, the new draft with its samples or the plan), `gen fix <game> --approve | --drop`, `gen drafts <game> [--back <n>]` (each draft with its test run and what happened in game, then the conversation). ## Reference packs

(decided 2026-11-16; Core `Generation/ReferencePacks` (`ReferencePack`, `ReferenceSet`, `ReferenceSelection`, `LanguageKinship`), `Registry/ReferenceFetcher`, `GenerationFiles.WriteReferences / ReadReferences`; Pipeline `system-refs.v1`; Mcp `get_references`; Desktop start form): a new translation learns from the translations of **the same game** that the registry already lists, in any language, as **reference packs**. They help the agent choose a reader, find where an unknown engine keeps its text, pick names and terms, and resolve ambiguous short strings.

**Which packs** (`ReferenceSelection.Select(index, game, language, buildId)`, pure): the index's packs of the job's game that players confirmed: `verified`, or more *works* than *doesn't work* reports (`Qualifies`). One pack per language: the one made for the game's build first (its `buildIds`), then `verified`, then works − doesn't work, likes, coverage, ID. Languages in order: English first (a pivot; a game with an English pack wasn't written in English), the job's own language, the closest to it (`LanguageKinship.Closeness`: 4 for the same language (`es-ES` / `es-419`), + 2 for the same script, + 1 for the same family), then `verified`, then the rating. At most **two** (`MaxLanguages`).

**Fetching** (`ReferenceFetcher.FetchAsync`, never throws but for cancellation): a recipe pack's manifest and string table through the pack cache (`PackFetcher`, hash-checked as for an install), a binary patch pack's manifest only (its ZIP is never downloaded). A pack that can't be fetched is left out and logged. `ReferencePack.SameBuild` = one of the manifest's builds is the game's current one (Steam build ID; a manual game's file hashes where both know the file). The app loads them on the start form once per language (`GenerationService.LoadReferencesAsync`, from the current index), the CLI's `gen run` from the saved index. `GenerationJobs.Start(..., references)` writes them into the job folder's `refs/` before `job.json` (`<language>/<pack id>/manifest.json` + `strings.json.gz`, then `refs.json` = `{schemaVersion: 1, packs: [{language, pack, sameBuild?}]}` in priority order) and fixes `options.references` = `[{language, pack, revision}]`; the job log's first line names them. The job never depends on the cache or the network for them; reading them back is best effort (a broken pack is left out, never a failed run). The agent never goes online for them; every sandbox stays as it is.

**Start form**: a banner checkbox *Learn from published translations of this game* (`UseReferences`, on by default) under the quality line, shown only when a pack qualifies, naming their languages; CLI `gen run --no-refs`.

**Uses**: (1) *Reader*: when the toolkit found no tool for the game (the default reader would be the AI's own code) and a reference has a `recipe` whose tool the toolkit has and can run here, that tool is preselected once, as if the player picked it, and the estimate runs again. When every reference is a binary patch while the toolkit is to read the game, the banner says the toolkit probably can't read it. (2) *Unknown engines*: the Extract run with the agent's own code gets the files the references touched (`ReferenceSet.TouchedFiles`: those of packs for the current build first, at most 30 named) as where the text most likely is. (3) *Glossary*: the run is told about the references, and `get_references(search)` shows how they translated the strings mentioning a term. (4) *Translate*: each string line of a chunk gets `ref: {<language>: translation}` (`TranslateStage.StringLines`, `ReferenceSet.For`): only a translation made from this very original (the table's `originals` hash matches), or, in a table without a hash for it, from a pack made for the current build. The chunk plan counts these texts (`ChunkPlanner.ReferenceTokens`, about 4 characters a token + 4 per language). (5) *Fonts*: references in a language of the same script (`LanguageKinship.Script`) give their `fonts` as the preferred fonts of the Build's (and a fix test run's) font swap (`ReferenceSet.FontsFor`; ones off this app's whitelist are logged and ignored).

**Prompt**: references are a hint, never text to copy. A job with references gets `system-refs.v1` appended to the system prompt of its Glossary and Translate runs, an Extract run with the agent's own code (with the files) and fix runs (`PipelineAgent`, after the brief, each part after a blank line): which packs (language, title, revision, verified, for this version or another, binary patch), translate from the original, use a `ref` to understand the meaning and keep names consistent, a string every reference keeps as the original is likely a name or code, follow the original when a reference contradicts it, `get_references`. The task prompts are unchanged, so no new versions. **`get_references`** (toolkit MCP server, read-only): `keys`, or `search` (the strings whose original or a reference's translation holds the text, only those with a reference), paged as `get_strings`; answers `{packs: [{language, pack, title, revision, sameBuild, hasStrings}], total, strings: [{key, original, translations: {language: text}}], nextOffset, unknownKeys}`; empty `packs` for a job without references.

**Attribution** (CC BY-SA 4.0): the local pack's manifest records the job's references in `references` (`LocalPackInput.References`; an update keeps its base's, the latest revision of each pack wins, never the pack itself; _Pack format details_ in `docs/packs-and-registry.md`); publishing keeps them (a new revision merges the existing pack's with the local pack's) and the PR body lists them in a *References* row with thanks to their authors.

**Later**: a registry pack in the job's language that doesn't fit the game's build as the base of `Translate new strings` without installing it (_Update mode_ still takes only the installed pack); the estimate tiles don't count the `ref` texts yet.

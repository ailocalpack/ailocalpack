# Packs and registry

Pack format details (manifest, string table, reading), registry index and client, pack compatibility, download and cache, binary patches, dependencies whitelist, pack validation, index build, registry CI. Part of the product spec in `CLAUDE.md`: keep it current; record settled decisions in the matching section here.

## Registry index

(`Core/Registry`): `index.json` (JSON Schema `schemas/registry-index.schema.json`; model `RegistryIndex`, `RegistryIndexSerializer`) = `{schemaVersion: 1, generated, games: {<game ID>: {optOut?, antiCheatAllowed?, packs?: {<language>: [pack]}}}, dependencies?: [whitelist entry]}` (`RegistryIndex.Dependencies`, see _Dependencies_; a damaged entry is left out like a pack), pack = `{id, title, author {github, name?} (original author), status, revision, updated, coverage {translated, total}, buildIds (Steam build IDs; empty for `fp:` games), buildCount, manifest (path relative to index.json, ends in `manifest.json`), size (download bytes), rating? {likes, works, doesNotWork}, discussion? (https)}`. Reading never throws: not JSON / other `schemaVersion` (newer → `IsNewerFormat`, "update the app") / missing `generated` or `games` refuses the file; a damaged game or pack entry (bad ID, unknown language, duplicate pack ID, `fp:` pack with build IDs…) is left out with its error, the rest kept. Writing is deterministic (games, languages, packs in ordinal order; defaults left out), so `index build` (task 19) output can be a golden file; `tests/fixtures/registry/` is the sample registry (index + manifests + gzip string tables). `RegistryLocation`: `AILOCALPACK_INDEX_URL` → hidden setting `AppSettings.RegistryIndexUrl` → `https://ailocalpack.github.io/registry/index.json`; an override is an `https://` URL (of the index or its folder), a `file://` URL or a local path (folder or `.json`, relative to the current folder); `http://` and other schemes are an error, never a silent fall back; pack files resolve relative to the index (`Resolve`). `RegistryIndexClient`: local folder → read directly, no cache; https → conditional GET (`If-None-Match` / `If-Modified-Since`), 15 s per try, 3 tries with 1 s, 2 s waits for no connection / timeout / 5xx / 408 / 429 (not other 4xx, malformed or newer files), 64 MB cap; a good 200 is saved to `<cache>/registry/index.json` + `index.meta.json` (source URL, ETag, Last-Modified, fetched at, SHA-256 of the copy; a copy from another source or not matching its hash is ignored); 304 moves the fetched date. Result `RegistryIndexSnapshot`: `Fresh`, `Stale` (the saved copy, `FetchedAt` = stale since, with the `RegistryIndexProblem`: offline, timeout, HTTP error, malformed, newer format) or `Unavailable` (no saved copy, local index missing, invalid address); a bad download never replaces the saved copy. Desktop `PackIndex` holds the latest snapshot (`Current`, `Changed`; one refresh at a time). CLI `index show [--game <id>] [--lang <tag>] [--json]`: header (source, generated, fetched; offline → "showing the saved copy from <date>"), a row per pack (game, language, ID, status, revision, coverage %, likes, works/doesn't, build IDs or file-set count, author, title), game flags; JSON `{source, state: fresh|stale, problem (kebab-case or null), detail, fetchedAt, generated, games: [{id, optOut, antiCheatAllowed, packs: [{language, id, title, author, status, revision, updated, translated, total, buildIds, buildCount, manifest (resolved URL), size, likes, works, doesNotWork, discussion}]}]}`; no index at all → stderr + exit 1; damaged entries → `warning:` lines on stderr. CLI `pack check <manifest.json | pack folder> --game <id> [--json]`: refreshes the catalog with a Steam scan (Steam IDs), checks with the cached file hashes and prints `<verdict>: <reason sentence>`, the pack (ID, revision, title, recipe or patch, builds), the game (ID, name, build, folder) and the changed / missing files; JSON `{pack, revision, game, verdict (kebab-case), reason (kebab-case), explanation, packBuilds, gameBuild, referenceBuild, touchedFiles, changedFiles, missingFiles, unreadableFile}`; exit 0 = compatible or probably compatible, 2 = incompatible, 1 = bad game ID, unreadable / invalid manifest (its errors on stderr) or game not in the catalog. CLI `pack validate <folder>… [--github]`: per folder `<folder>: valid (<game>/<lang>/<id> rev N, T of N strings translated)` or `<folder>: invalid, N problems` + `  <file>: <field>: <message>` lines (`--github`: `::error file=<path from the current folder>,title=<field>::<message>` instead; folder-level problems point at its `manifest.json`); a valid recipe pack's translations also get `  warning: <strings path>: <key>: tag-unbalanced: …` lines (first 20 + "… and N more"; `--github`: every one as `::warning file=<table>,title=<rule>::<key>: …`) from `StringValidator.ValidateAlone` with its recipe tool's markup, never failing the pack; exit 1 if any pack is invalid or missing. CLI `pack fetch <pack id | game/lang/id> [--game <id>] [--lang <tag>] [--json]`: finds the pack in the index (saved copy offline; an ID used by several packs lists them, exit 1), fetches it into the cache and prints `<game>/<lang>/<id> rev N: downloaded N bytes.` / `already in the cache.` / `the registry can't be reached (…); using the cached copy.` + folder, strings, patch paths; JSON `{pack, revision, problem (kebab-case or null), detail, fromCache, downloaded, folder, manifest, strings, patch}`; exit 1 = not in the index, ambiguous, or not fetched (the reason + format errors on stderr). CLI `dev apply-files <game> <dir> [--pack dev] [--lang en] [--revision 1] [--reapply] [--dependency <id>@<version>]…` (finds the game like `pack check`; every file under `<dir>` replaces or adds the same path in the game; each dependency from the whitelist of the local registry / saved index is downloaded (cache first), unpacked and installed with them: `Dependency BepInEx 5.4.23.2 (macos-x64): downloaded N bytes from github.com, hash checked.` … `Dependency BepInEx 5.4.23.2: 22 files installed.` / `already installed, shared`) and `dev uninstall <game>`: run recovery first (a line when it did something), print `Installed <pack> rev N (<lang>) into <game> "<name>": N files replaced, M added.` + backup folder / `Uninstalled … N files restored, M removed.` + `kept (changed since the install)` and `removed dependency <id> <version> (no other pack uses it)` lines; refusals and failures go to stderr in one plain sentence, exit 1; the registry flags come from a local registry or the saved index copy (no network). CLI `toolkit extract <folder> --out <file> [--lang <tag>]` (default `en`): the game's strings as an editable string table (values = originals, `context` = notes) plus `tool`, `toolVersion`, `files` and `details` (`{key: {maxLength, placeholders}}`), which string table readers ignore; prints `Extracted N strings from M files of <engine> (<tool> <version>) into <file>.`. `toolkit validate <table> --game <folder> [--json]`: each non-empty translation checked against the game's extracted originals (see _String validator_): `<key>: <error|warning> <rule>: <message>` lines, `Checked N translations: E errors, W warnings.`, keys not in the game as a `warning:` on stderr; JSON `{checked, errors, warnings, issues: [{key, severity, rule, message}], unknownKeys}`; exit 1 for any error, a bad table, a missing folder or an engine the toolkit can't read. `toolkit rebuild <folder> --strings <table> --out <dir>` (a table as extract or a pack writes it, JSON or gzip; rebuilt in the table's language): writes the changed or added game files into `<dir>` (never the game folder; feed it to `dev apply-files`), the font swap included (see _Fonts_), prints `Rebuilt N files (K strings translated) into <dir>.` + the files and a `fonts:` line, unknown keys as a `warning:` on stderr (first 20); exit 1 for a missing folder, an engine the toolkit can't read, a bad table or language tag, a broken game file. `dev fixture rpgmaker <dir> [--mv]` / `dev fixture renpy <dir> [--archived]` / `dev fixture godot <dir> [--major 3|4] [--embedded] [--untranslated]` write the synthetic game into a missing or empty folder. CLI `index build <registry root> --out <file> [--ratings <file>] [--generated <RFC 3339>] [--github]`: writes the index atomically (`\n` line ends, trailing newline; `--generated` default now, given for reproducible output), prints `Wrote <file>: N games, M packs[, K warnings].`, what was left out as `warning: <file>: <field>: <message>` on stderr (`--github`: `::warning …`); exit 1 (nothing written) for a missing root, a broken policy or ratings file, a bad `--generated`.

## Pack compatibility

(`Core/Packs/PackCompatibilityChecker`, never throws for disk state): `Check(pack, game)` → `PackCompatibility` (verdict `Compatible` / `ProbablyCompatible` / `Incompatible`, `PackCompatibilityReason`, and the explanation data: the pack's build IDs, the game's build ID, the reference build (matching, else closest: fewest changed, then fewest missing files, later build on a tie), touched file count, changed / missing files, unreadable file, recipe tool). Order: pack for another game, game unavailable or its folder gone, recipe tool unknown / too new / engine switched off on this OS (`IRecipeTools.Check(recipe, game.Engine)` = Toolkit `RecipeTools`, wired into the app and `pack check`; `null` = not checked) → incompatible; the game's build ID listed → compatible if that build's files all exist (nothing hashed), else incompatible; otherwise only the touched files are hashed through `FileHashCache` (size + mtime) and compared with each listed build whose files all exist: an exact match → compatible; else against the closest build a recipe pack is **probably compatible** (the recipe rebuilds the changed files from the player's own copy; strings the update added stay untranslated; whether the pack's keys are still there is found out when the recipe runs at install, task 28) and a binary patch is incompatible (it needs the exact files); no build with all its files → incompatible (files missing); a file that can't be read → incompatible (unreadable). The UI words the verdict from the reason and data; the CLI has its own English wording.

## Pack download and cache

(task 26): `PackFetcher.FetchAsync(location, RegistryPack, progress)` (Core/Registry, never throws except cancellation) gets the manifest through `PackManifestClient` (which now also returns the manifest bytes and URL), then only the pack's own files: the gzip string table next to the manifest (local registry: copied; else https only) and the patch archive from its https `patch.url` (local registry: its `releases/` folder, see _Binary patches_). Each file is checked against the manifest's size + SHA-256; a mismatch (or a body longer than the size) deletes it → `HashMismatch`; a string table with the right hash that doesn't read or is in another language is deleted → `InvalidStrings`. Downloads go to `<file>.part` and resume with `Range: bytes=<n>-` (206 with the matching `Content-Range` appends; 200 replaces the part; 416 or another range starts over), within one call (`PackFetchOptions`: 3 tries, 1 s / 2 s waits, 30 s limit per wait for data, not per file) and across calls. `PackFetchProblem`: Offline / Timeout / HttpError (may pass), FileMissing (404 / 410, missing local file), InvalidManifest, NewerFormat, Mismatch, HashMismatch, InvalidStrings, DiskError; `PackFetchProgress` = bytes in place of all the pack needs (a resumed part counts once). Its HTTP client (`PackFetcher.CreateHttpClient`) has no automatic decompression (hashes and ranges are of the stored bytes) and no overall timeout. **Cache** (`Core/Packs/PackCache`, `AppPaths.Packs` = `<cache>/packs`): `<game folder>/<language>/<pack id>/r<revision>-<manifest SHA-256>/` holding `manifest.json` (exact registry bytes), the string table at its manifest path and `patch.zip`; every key part is a slug, tag or hex on its own folder level, so entries never collide, and a re-published manifest of the same revision gets its own entry. Files enter only after their hash check and `manifest.json` is written last, so an entry is complete when its manifest reads, hashes to the folder name, names the same pack and every file has its size (payload not re-hashed: a hit is instant). A manifest already cached → `FromCache`, nothing downloaded; manifest unreachable (offline, timeout, server error) → the newest complete entry of the index's revision. `Size()` / `Clear()` for Settings → Storage (task 66); old revisions are not pruned yet. One fetch of a given pack at a time (parts are opened exclusively). Desktop registers `PackCache` and `PackFetcher` (task 29 uses them).

## Binary patches

(`Core/Patches`, task 34): `VcdiffDecoder.Decode(source, delta, target)` = RFC 3284 as xdelta3 writes it, our own code (no external executable, no package): default code table, address cache, `VCD_SOURCE` windows read at random from the source file and `VCD_TARGET` windows from the output written so far, the application header skipped, xdelta3's per-window Adler-32 (window bit 2) checked; the delta is read once front to back (a ZIP entry stream). **Secondary compression** (decided): `lzma` (xdelta3 3.2's default) is read by our own LZMA2 decoder (`Lzma2Decoder`): xdelta3 keeps one xz stream per kind of section (data, instructions, addresses) for the whole delta, flushed per window, so the first compressed section starts it (stream + block header, only the single LZMA2 filter) and later ones continue it with dictionary and state carried over; no index / footer, xz checks not computed (Adler-32 + SHA-256 check the result). `djw` / `fgk`, another VCDIFF version or an application code table → `VcdiffProblem.Unsupported` ("make it with -S lzma or -S none"). Problems: `NotVcdiff`, `Unsupported`, `Corrupt`, `SourceTooShort`, `ChecksumMismatch` (another source of the same length), `TooLarge` (`VcdiffOptions`: result ≤ 64 GiB, window / section / LZMA dictionary ≤ 64 MiB, xdelta3's hard limit). `PatchApplier.Apply(manifest, archive, gameDir, outputDir)` (never throws for disk or archive state): the archive must hold exactly one `<path>.vcdiff` per `patch.files` path and nothing else but empty folder entries (`zip -r` writes them), looked up by name, never extracted by its own names; per file: missing → `SourceMissing`; hash = the patched one → copied as is (re-apply over an intact pack, `AlreadyPatched`); hash ≠ the only build's → `SourceMismatch` (expected / actual hash); else decoded into the output folder and hashed against `patch.files` (`ResultMismatch`); also `ArchiveInvalid`, `SourceUnreadable`, `Decode` (+ `VcdiffProblem`), `DiskError`; progress = files done. Install flow: step `Patch` ("Applying the binary patch to a copy of the game files") replaces `Rebuild` for a patch pack (no recipe check, no font swap, no generated files), then the same transaction; `SourceMismatch` / `SourceMissing` become `Incompatible` (`PatchFilesChanged` / `FilesMissing`, so a Steam game whose listed build has a modified file still gets the compatibility wording), the rest `InstallErrorKind.Patch` (`InstallError.Patch`; retry only for disk / unreadable). A **local registry** has no Release assets: `PackFetcher` takes the patch archive from `<registry>/releases/<file name of patch.url>` when present (`PackFetcher.LocalReleasesFolder`; outside `games/`, so `index build` ignores it), else downloads the URL. CLI `toolkit patch <folder> --pack <pack folder | manifest.json> --out <dir> [--patch <zip>]` (archive default `patch.zip` next to the manifest, as `pack fetch` caches it): prints `Patched N files into <dir>.` + the files (`(already patched, copied as is)`), exit 1 with one sentence (e.g. `<file>: not the file the patch was made from (sha256 …, the patch needs …); the pack is incompatible…`); `--out` must not be the game folder; feed the folder to `dev apply-files`. Fixtures: `tests/fixtures/vcdiff` (synthetic `source.bin` → `target.bin` and the xdelta3 3.2.2 deltas, commands in its README); TestKit `VcdiffFixture` = minimal encoder (COPY of the shared prefix + ADD, with Adler-32) and the archive writer for install tests.

## Dependencies

(task 32): the **whitelist** is the registry's `policy/dependencies.json` (schema `schemas/dependency-whitelist.schema.json`; maintainers only), copied by `index build` into `index.json`'s `dependencies`, so the app has it cached and offline with the pack list (decided over a separate fetched file and over a list bundled in the app: a new BepInEx version needs no app release). Format (`Core/Dependencies/DependencyWhitelist`, `Parse` refuses the whole file on any error): `{schemaVersion: 1, dependencies: [{id (slug, what a manifest names), name, homepage (https), layout?: {from? (folder inside the archive), into? (folder of the game)}, generated?: [path], versions: [{version, assets: [{platform, url (https, a ZIP), size, sha256}]}]}]}`; platform = `<windows|linux|macos>-<x86|x64|arm64>` of the **game build**, not the machine (a Windows build under Proton takes the Windows file): `GamePlatforms.Detect` reads the main executable's header (PE machine, ELF machine, Mach-O CPU; a universal binary lists its CPUs, the machine's first; a `.app` by its `Contents/MacOS` binary), main executable = `Game.MainExecutable`, else the engine's, else `FolderRecognizer.ListExecutables`; `Pick` takes the first asset matching the OS and one of the CPUs. Generated paths: a folder ends with `/` (removed when empty), wildcards only in the last part of a file inside a folder (never at the game folder's top). **Download** (`DependencyStore`, `AppPaths.Dependencies` = `<cache>/dependencies/<id>/<version>/<sha256[..16]>-<file>`): `VerifiedDownloader` (resumable; size + SHA-256 checked before it enters the cache, a mismatch deleted → `HashMismatch`); a cached file of the right size is used as is. **Unpacking** (`DependencyArchive.Extract`): every entry name checked before anything is written (relative, no `..`, drive, `\` or link entries, no names differing only in case, no file-and-folder clash), ≤ 20 000 entries, ≤ 1 GB unpacked; entries under `layout.from` go to `layout.into`; only the whitelisted archive (hash pinned by maintainers) is ever unpacked, packs still hold no executables. `Toolkit/Dependencies/DependencyPreparer` (app and CLI): `Resolve(game, manifest dependencies, whitelist, installed)` → choices + shared (installed in the version) or `Unknown` / `PlatformUnknown` / `NoAsset`; `PrepareAsync` → `InstallDependency` per choice or `Fetch` / `Archive`. Not yet handled: launching through BepInEx's `run_bepinex.sh` (native Linux / macOS builds) and the `WINEDLLOVERRIDES="winhttp=n,b"` launch option under Proton; the Unity recipe (task 36) edits assets and needs no loader, so this waits for a pack that names one.

## Pack validation

(`Core/Packs/PackValidator`, what registry CI runs, never throws for disk state): `Validate(folder)` → `PackValidation` (manifest when readable, `PackProblem` list: file relative to the pack folder, field, message). Checks: manifest reads (its `PackFormatError`s with field paths); folder = `games/<game folder>/<language>/<id>` of the manifest (without one, at least under `games/`); the string table exists, matches `strings.size` / `strings.sha256`, reads and has the manifest's language; every `fonts` ID is on the font whitelist; every dependency (ID and version) is on the registry's `policy/dependencies.json` (read from the checkout holding the folder; none = empty, so outside a registry any dependency is refused; `index build` passes its own copy); nothing else in the folder (without a manifest, files under `strings/` aren't called stray); no links; no file over 50 MB (GitHub's warning size), ≤ 100 MB in all; no file that can run code (`ExecutableFiles`: by extension (native code, installers, scripts, archives) **and** by first bytes (PE `MZ`, ELF, Mach-O thin / fat, WebAssembly, `#!`, zip, 7z, RAR, xz, bzip2, zstd, cab, OLE/MSI, tar `ustar`); a gzip stream is inflated and its start checked again, so the gzip string table passes and a `.tar.gz` or gzip'd exe doesn't). A file refused for its content isn't also reported as stray.

## Index build

(`Core/Registry/RegistryIndexBuilder`): `Build(root, generated, ratings?)` walks `games/*/*/*`, validates every pack folder with `PackValidator` and leaves a failing one out (its problems returned, suffixed `(pack left out)`); files in the `games/` tree outside the layout are reported. Index pack = manifest's ID, title, first author, status, revision, updated, coverage, non-null build IDs, build count, manifest path relative to the root (where `index.json` is published), size = string table + patch bytes; rating and discussion from the ratings (ratings of packs not in the tree are reported). Games = those with packs + policy entries; flags: `optOut` from `policy/opt-out.json` (`RegistryOptOuts`: `{schemaVersion: 1, games: [{game, note?}]}`; schema and CI checks come with task 65), `antiCheatAllowed` from the `allowed` list of `policy/anti-cheat.json` (`AntiCheatPolicy.Parse`); `dependencies` = `policy/dependencies.json` (`DependencyWhitelist.Parse`), a pack naming anything else is left out. A missing policy file = empty; an unreadable or invalid one stops the build (dropping an entry would unblock a game). Ratings file (`RegistryRatings`, written by task 64's collector): `{schemaVersion: 1, packs: {"<game id>/<language>/<pack id>" (RegistryPackKey): {likes, works, doesNotWork, discussion? (https)}}}`; any bad entry refuses the whole file. `tests/fixtures/registry` holds sample `policy/` files (`dependencies.json` = real BepInEx 5.4.23.2 for windows-x64/x86, linux-x64/x86, macos-x64) and `tests/fixtures/registry-ratings.json`; building them with `--generated 2026-11-04T12:00:00Z` reproduces `tests/fixtures/registry/index.json` byte for byte (the golden file).

## Pack format details

Principles are in `CLAUDE.md` (_Pack format_). Details:

- **Manifest** (`manifest.json`, JSON Schema `schemas/pack-manifest.schema.json`, shared with the registry; model `PackManifest` in `Core/Packs`): `schemaVersion` 1, `id` (slug `[a-z0-9]+(-[a-z0-9]+)*`, ≤ 64, unique per game + language, = folder name), `game` (canonical `GameId`), `language` (exact `GameLanguages.Tags` tag), `title` (≤ 80), `authors` `[{github, name?}]` (first = original author, later = revision credits; logins unique), `revision` + `revisions` `[{revision, date, by, notes?}]` (numbered 1…N oldest first, `revision` = N, dates not decreasing, `by` listed in `authors`), `status` `alpha` / `verified`, `agent?` `{id, version?, model?}` (absent = made by hand), `builds` `[{buildId?, files: {path: sha256}}]` (original hashes of the touched files per supported build; Steam games need `buildId`, `fp:` games must not have one; touched files = union of the paths), exactly one of `recipe` `{tool (slug), version (major.minor.patch), parameters? (object)}` + required `strings` `{path under strings/, sha256, size}` **or** `patch` `{format: "vcdiff", url (https), sha256, size, files: {path: sha256 after patching}}` (one build only, same paths as it; `strings` optional), `dependencies?` `[{id, version}]` (whitelist IDs, unique), `fonts?` (whitelist IDs, unique), `coverage` `{translated, total ≥ 1}` (translated ≤ total), `license` = `CC-BY-SA-4.0`, `created` / `updated` (RFC 3339 with offset; written as UTC; updated ≥ created). Paths are relative, `/`-separated, no `.`/`..`; hashes are SHA-256 lowercase hex. Unknown properties are ignored (forward compatibility); a breaking change raises `schemaVersion`, and a newer one is refused with "update the app". The registry's discussion link, ratings and confirmations live in `index.json` (see _Registry index_), not here.
- **String table** (`schemas/string-table.schema.json`, `StringTable`): JSON `{schemaVersion: 1, language, strings: {key: translation}, context?: {key: note}}` (keys not empty, context keys present in `strings`, no duplicate keys), stored **gzip**-compressed as `strings/strings.json.gz` (gzip over zstd: in the .NET BCL and every CI tool; written with keys in ordinal order, non-ASCII unescaped). Reading accepts gzip (by magic bytes) or plain JSON, refusing more than 256 MB inflated.
- **Reading** (`PackManifestSerializer.Read` / `StringTableSerializer.Read`, source-generated DTOs apart from the model): never throws for bad content; returns the model or every problem as `PackFormatError` (field path like `builds[0].files["a/b.json"]` + plain English message). The C# checks are the schema's plus rules a schema can't state (revision numbering and authors, build IDs by game kind, patch = one build, coverage ≤ total, date order); tests run every sample in `tests/fixtures/packs/{valid,invalid}` through both and validate written models against the schemas (JsonSchema.Net, tests only).

## Registry CI and layout details

- **Layout**: `games/<game folder>/<language>/<pack-id>/` (`<game folder>` = the game ID with `:` → `-`, `steam-620`, `fp-<hex>`, since Windows forbids `:` in file names; `RegistryLayout`; `<language>` is a BCP 47 tag from `GameLanguages.Tags` in Core: the languages Steam supports, e.g. `ru`, `pt-BR`, `es-419`, `zh-Hans`) with `manifest.json` and `strings/` (later `audio/`). Several competing packs per game + language are allowed. Game versions are a supported-builds/hashes list in the manifest, not folders; updating a pack for a new game version is a new revision of the same pack.
- **CI** (`ailocalpack/registry/.github`, default branch `master`): the CLI is built from source at the commit in `ci/ailocalpack-ref` (composite action `setup-cli`, cached per commit, this repo is public so no token is needed; task 71 swaps in the released binary). *Validate* (`pull_request`, required check) classifies the PR with `scripts/pr-scope.sh`: a **pack PR** changes files inside exactly one `games/<game>/<language>/<pack-id>/` that still has a `manifest.json`; anything else (other files, several packs, a removed pack) is a maintenance PR, refused for authors who aren't `OWNER` / `MEMBER` / `COLLABORATOR` (GitHub's `author_association`, which says `CONTRIBUTOR` for a member whose organization membership is private, so maintainers keep theirs public); values from the PR reach the shell only through `env`, never `${{ }}`; a pack PR must have `status: alpha` (`scripts/check-alpha.sh`: refused, not rewritten; a linked manifest refused); then `pack validate --github` on the touched packs, `schemas/` = the CLI's, `index build` succeeds. *Auto-merge* (`workflow_run` after Validate succeeded, master's copy, write token) trusts nothing from the PR: finds it by head SHA (forks give no `pull_requests`), reads the changed files from the API, extracts the head's `games/` with `git archive` (no PR code runs) next to master's `policy/` (dependencies are checked against master's whitelist, never the PR's), repeats scope + alpha + validate, `gh pr merge --squash --match-head-commit`, then dispatches *Publish* (a `GITHUB_TOKEN` push starts no workflow). *Publish index* (push to `master`, dispatch): `index build` (+ `ratings.json` when present; `policy/dependencies.json` = real BepInEx 5.4.23.2, published as the index's `dependencies`) and Pages deploy of `index.json` + `games/` + `schemas/`. CODEOWNERS (`@ailocalpack/maintainers`) on `.github/`, `ci/`, `scripts/`, `schemas/`, `policy/`, README, LICENSE; `games/` unowned so pack PRs need no review (ruleset on `master`: PR with 0 approvals + code owner review, required check `validate`; Pages source GitHub Actions; these settings are listed in the registry README). Sample pack (an RPG Maker MZ game, so the app on macOS reports it incompatible; `pack validate` / `index build` take it everywhere) `games/fp-f362…/ru/sample-quest-ru` targets the synthetic RPG Maker MZ game `tests/fixtures/games/sample-quest` (line-ending conversion off; `SampleQuestFixtureTests` pin its fingerprint and hashes).

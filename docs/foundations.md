# Foundations: folders, settings, logging, UI localization

App folders, settings storage, logging, multilingual UI resources. Part of the product spec in `CLAUDE.md`: keep it current; record settled decisions in the matching section here.

## App folders

(`AppPaths` in Core, resolved from an injected `OsEnvironment`): three roots, `config` (settings), `data` (`games.json` = game catalog, `installed-packs.json` = installed packs, `install-journal.json` = transaction in progress, `install.lock`, `covers/` = manual game covers, `logs/`, `backups/` = backups of installed packs' originals (default place; the player can move them, `backups-location.json` names the folder in use: _Backup location_ in `docs/install.md`), `work/` = generation working copies, `local-packs/` = packs generated on this machine (registry layout + build reports), `agents/` = agents the app installed, `github-account.json` = the signed-in GitHub account (the token is in the OS keychain, `docs/publishing.md`), `pack-ratings.json` = the player's marks on installed packs: played, Later, liked, reported (task 63)), `cache` (`covers/`, `file-hashes.json`, `anti-cheat-rules.json` = the anti-cheat rules stamp the catalog was last checked with (`AppPaths.AntiCheatRulesFile`; missing or damaged = check every game again), `registry/` = saved index, `packs/` = downloaded packs, `fonts/` = downloaded whitelisted fonts, `dependencies/` = downloaded release archives of whitelisted dependencies). Windows: `%APPDATA%\ailocalpack` / `%LOCALAPPDATA%\ailocalpack` / `%LOCALAPPDATA%\ailocalpack\cache`. macOS: `~/Library/Application Support/ailocalpack` (config and data) / `~/Library/Caches/ailocalpack`. Linux: XDG config / data / cache homes + `ailocalpack` (relative XDG values ignored). `AILOCALPACK_HOME=<dir>` puts all three under `<dir>/{config,data,cache}` (dev, tests, portable).

## Settings

`AppSettings` (immutable record, `System.Text.Json` source generation, camelCase; derived properties are `[JsonIgnore]`) in `<config>/settings.json`, owned by the `SettingsStore` singleton (`Load` at startup, `Update(s => s with {...})`, `Changed`). Writes are atomic (`AtomicFile`: temp file + flush + rename). `schemaVersion` + `SettingsMigrator` steps (n → n+1); adding a property with a default needs no migration. `AppSettings` is a positional record and every setting is a constructor parameter with its default: the STJ source generator sets an init-only property missing from the file to `default` (a missing `true` flag would read `false`). `SettingsApplier` (started after `Load`) applies UI language and theme at startup and on every change, so settings apply immediately. A corrupted file is moved to `settings.json.<utc yyyyMMdd-HHmmss>.bak` and defaults are written; an unreadable one gives defaults in memory and is left alone; a file from a newer app is read best-effort. Settings never stop the app from starting.

## Logging

Serilog rolling file in `<data>/logs` via `Microsoft.Extensions.Logging` (daily, 7 files, 10 MB cap); unhandled exceptions (AppDomain, UI dispatcher, unobserved tasks) are logged.

## App UI is multilingual from the start

strings in resource files, initially AI-translated (task 68); community fixes via PRs (_App UI translations_ in `CONTRIBUTING.md`, linked from the language picker's help). Languages (`UiLanguages.Supported`): English, German `de`, Spanish `es` (neutral, Spain and Latin America), French `fr`, Italian `it`, Japanese `ja`, Korean `ko`, Polish `pl`, Brazilian Portuguese `pt-BR`, Russian `ru`, Turkish `tr`, Ukrainian `uk`, Simplified Chinese `zh-Hans`. A regional OS culture of a supported language keeps its region for numbers and dates (`de-AT`, `zh-CN` reads `zh-Hans` through the resource parent chain); another variant of a supported language gets the supported one (`pt-PT` → `pt-BR`), except Traditional Chinese, which stays English rather than read Simplified (`UiLanguages.Resolve`, `TagOf` for the name shown). Forms of address: de du, fr vous, es tú, pt-BR você, it tu, pl ty, tr siz, uk ви. CJK text renders through the OS font fallback (Inter has no CJK glyphs). Language: setting (`AppSettings.UiLanguage`, Settings → General) → OS UI culture → English; switchable at runtime.
- **Format: `.resx`** in `src/AiLocalPack.Desktop/Resources`: `Strings.resx` is English (neutral, `NeutralLanguage=en`), `Strings.<lang>.resx` per other language (satellite assemblies). The build generates the internal typed `Strings` class (MSBuild `StronglyTyped*` metadata, no designer file in git). Supported languages are listed in `UiLanguages.Supported`.
- XAML: `{l:Loc Key}` (`xmlns:l="using:AiLocalPack.Desktop.Localization"`), updates live on a language switch. Code: `Localizer` (DI singleton = `Localizer.Current`) with keys as `nameof(Strings.Key)`: indexer, `Format`, `Plural`; it raises `CultureChanged` so view models re-raise their text properties.
- Plurals: keys `Base_One` / `_Few` / `_Many` / `_Other` with exactly the CLDR forms of the language (`PluralRules`, the forms a whole number takes: en / de / tr one/other; ru / uk / pl one/few/many; fr / es / it / pt one/many/other, `many` for exact millions; ja / ko / zh other only); `{0}` is the count with digit grouping. Numbers and dates are formatted with the UI culture (a specific one like `ru-RU` is kept for its region).
- `ResourceFilesTests` guard every locale: same keys as English, same `{n}` placeholders, complete plural forms, no unlisted language shipped.

# Install: transaction and game update re-check

Core install transaction (backup, rollback, uninstall, re-apply, recovery, dependencies) and the re-check of installed packs after game updates. The Desktop install flow (UI) is in `docs/desktop-app.md`. Part of the product spec in `CLAUDE.md`: keep it current; record settled decisions in the matching section here.

## Install transaction

(`Core/Install`, task 27): `PackInstaller` (methods block, call off the UI thread). `Install(InstallRequest(game, language, pack ID, revision, files [relative `/` path → staged source file]), index)` first calls `GameBlocks.EnsureAllowed(…, Install)` (throws `GameBlockedException`), then takes the global lock (`<data>/install.lock` opened `FileShare.None`, so one transaction across app and CLI; taken → `Busy`), finishes a journal left behind (still stuck → `InterruptedInstall`), refuses a game with a pack (`AlreadyInstalled`; replacing = uninstall + install), unavailable (`GameUnavailable`) or running (`GameRunning`: a process inside the folder, `GameProcessMatcher`). Plan: every source and game file hashed (SHA-256); a file whose content is already the new one isn't written. Checks before anything changes: each written file not read-only (Windows attribute; on Linux / macOS no owner write bit, since a rename would replace it anyway), opens read-write exclusively (in use, access), free space for backup + new files (per drive, longest mount point). Then `<data>/install-journal.json` (atomic) is written, originals copied into `<backups>/<game folder>/<utc yyyyMMdd-HHmmss>-<random>/files/<path>` and hash-checked, journal phase → `apply`, missing parent folders created (listed in the journal), new files written atomically (temp `.<name>.<random>.ailocalpack` next to it + flush + rename, Unix mode kept), every file hashed again (`VerifyFailed`), then the record is saved in `InstalledPackStore` (`<data>/installed-packs.json`: per game language, pack, revision, installed at, install path, backup folder, files `{path, original (null = added by the pack), installed}`, added folders, `generatedFiles` = the request's `GeneratedFiles` not in the folder before (re-apply keeps the old ones)): **saving the record is the commit point**. Any failure before it rolls back (each written file back to its pre-transaction hash from the backup, added files and empty created folders deleted, transaction backup deleted, journal deleted) and records nothing; `InstallFailure` = `InstallProblem` (game running, file in use, disk full, permission denied, read-only, game unavailable, already / not installed, busy, interrupted install, verify failed, backup damaged, other IO) + file + OS message + `FilesRestored` (`false` only when the rollback itself failed: the journal stays). OS errors → problems in `InstallErrors.Classify` (Windows Win32 codes 32/33/1224 in use, 112/39 disk full, 19 write-protected, 5 denied; Unix errno 26/16 in use, 28 + EDQUOT per OS disk full, 30 read-only, 13/1 denied). **Uninstall** (allowed for blocked games): per file, original hash already there → nothing; current = what the pack wrote or missing → original copied back (checked); added file still the pack's → deleted; a file changed since (a game update) → kept and listed; generated files present → deleted (listed as removed); empty added folders removed; record, backup and journal deleted. A failure midway keeps the record (restoring is idempotent, so uninstall again finishes). **Re-apply** (task 33) = install over the game's record: a file still as the pack wrote it keeps its old original (copied from the old backup; a rollback-only copy of the current file goes to `before/`), any other file is backed up as the new original; files of the old record the request doesn't write are carried into the new record; the old backup goes after the new record is saved; failure keeps the old pack installed. **Recovery** (`Recover`, start-up and before every transaction): no journal → nothing; uninstall journal → finished (rolled forward, not back: the pack's files aren't kept); install journal whose record was saved → completed (cleanup); otherwise rolled back (stray temp files removed too); failure (file in use, drive gone) → `Failed`, journal kept for the next start. Progress: `InstallProgress(stage Checking / BackingUp / Writing / Verifying / Restoring, done, total)`. **Dependencies** (task 32): `InstallRequest.Dependencies` (`InstallDependency(id, version, files) { GeneratedFiles }`) are written in the same transaction, dependencies first, the pack last; each gets its own record `InstalledDependency` (game, ID, version, `UsedBy` pack IDs, files, added folders, generated paths, backup) stored next to the packs in `installed-packs.json` (schema 2, `{packs, dependencies}`; an older app reads it but never writes it) and committed with the pack in one write (`InstalledPackStore.Commit(game, pack, dependencies)`); one transaction's backup folder is shared by what it installed, and a backup folder goes once no record points at it. A dependency installed in the same version is shared (named with no files: nothing written, the pack joins `UsedBy`; re-apply writes its files again), another version installed → `DependencyConflict`, as is a file written by both a dependency and the pack. `Uninstall(game, keep)` removes the pack and every dependency left without users except those in `keep` (a replacement whose next pack needs them: kept with no users); `RemoveUnusedDependencies(game)` removes such leftovers; the uninstall journal records `removesPack` + `keepDependencies`, so recovery finishes the same split. Generated paths of a dependency (`BepInEx/LogOutput.log`, folders ending in `/` removed when empty, `BepInEx/cache/*`) are recorded only when absent at install, deleted on uninstall. Desktop registers `InstalledPackStore` and `PackInstaller`.

**Local packs** (task 55): `PackInstallService.InstallLocalAsync(game, LocalPack)` installs a pack generated on this machine from its `LocalPackStore` folder (it is laid out like a cache entry: manifest + string table at its path) through the same steps without the download (RemovePrevious, Check, Rebuild, BackUp, Write, Verify); the record is `InstalledPack.Local` with the pack's `Title` (JSON `local: true`, `title`; older records read as registry packs), so re-apply reads the pack from the local packs (no Download step; gone → `InstallErrorKind.LocalMissing`, "The local pack was deleted or can't be read."), the update re-check takes its manifest from there, titles come from the record, and a registry pack with the same ID is never taken for it (Packs tab, header, Activity's later revision, the replace risk). A local pack can't be deleted while installed.

## Backup location

(task 66, `Core/Install/BackupLocation`): the backups are in `BackupLocation.RootOf(paths)` = `<data>/backups-location.json`'s `path` (`AppPaths.BackupsLocationFile`, `{schemaVersion: 1, path, move: {from, to, phase, createdTarget} | null}`), else `AppPaths.Backups`; install records keep only the backup folder's name, so the installer, `InstalledOriginals` and `dev apply-files` read the root for each use and a move changes nothing else. Machine-local (data, not the roaming config): it names a folder on this machine's drives. **Move** (`Move(picked, progress)`, Settings → Storage and `storage move-backups`): the new folder is the picked one when it is named `ailocalpack-backups`, else `ailocalpack-backups` inside it (`TargetFor`), so backups never mix with the player's files. Under the install lock (`InstallLock`, shared with installs and cache clearing; taken → `Busy`); an interrupted install or move that can't be finished → `Interrupted`; refused before anything is written: `SameFolder`, `Nested` (either inside the other), `NotEmpty` (the new folder holds anything), `DiskFull` (another drive with less than the size + 64 MiB free, `IDiskSpace`), `NewerFormat` (the location file is a newer app's: never overwritten). Then the journal (`path` = old, `move.phase = copy`) is written, the folder renamed on the same drive (longest mount point; a failed rename falls back to copying) or every file copied atomically and SHA-256 checked against its source (`VerifyFailed`), `path` switched to the new folder with `phase = cleanup` in one atomic write (**the commit point**), the old folder deleted (read-only files too) and the journal dropped. A failure or cancellation before the commit deletes what was copied (the new folder itself when the move created it, else only its content) and keeps the old one (`Denied`, `DiskFull`, `IoError` classified with `InstallErrors`); an old folder that can't be deleted yet stays in the journal (`LeftBehind`). **Recovery** (`Recover`; `PackInstaller` runs it under its lock before every transaction and at start-up, and `HasInterruptedTransaction` counts it, so the *Finishing an interrupted install* step shows "An interrupted move of the backups was finished"): `copy` with the old folder gone and the new one there (the rename happened) → rolled forward; other `copy` → rolled back; `cleanup` → the old folder deleted. A damaged location file is moved aside as `backups-location.json.<utc>.bak` and the default folder is used.

## Game update re-check

(task 33): Core `PackRecheck.Inspect(record, gameFolder, hashes)` = each recorded file as the pack wrote it / reverted to the original / changed / missing / unreadable (`PackFileStates`, `Originals` = the record's original hash for files still as written); `PackRecheck.Decide(files, verdict, autoReapply)` (pure): intact → nothing; unreadable → undecided; else the installed revision's compatibility with the game as it is without the pack (`PackCompatibilityChecker.Check(manifest, game, knownHashes)`, the originals standing in for files the pack holds; manifest from the pack cache, else the registry while it lists the revision, none → unknown): incompatible → `Incompatible`, unknown → `Wiped`, fits → re-apply when `AppSettings.ReapplyAfterGameUpdates`, else `Wiped`. Desktop `InstalledPackMonitor` (singleton, never throws, one pass at a time): `CheckAllAsync` over every record of an available, unblocked game; re-apply through `PackInstallService.ReapplyAsync` (fresh backup), failure → `ReapplyFailed` with the outcome (Busy → `Wiped`); findings (`InstalledPackHealth`, tied to the record's pack, revision and install time, so any later install or re-apply makes them stale) live for the session only (every start checks again) and feed `InstalledPackState.Problem` (`None` / `Incompatible` / `Wiped` / `ReapplyFailed`; anything but None = `NeedsUpdate`). Runs at start-up (step above) and after every later `GameLibrary` refresh (Rescan). An automatic re-apply shows no toast: it is an Activity feed event, a failure an Activity decision (see _Activity panel_); the tray app also checks in the background (see _Tray and background_). Not stored: the build ID at install (file hashes decide; the Steam file-check case has the same build ID).

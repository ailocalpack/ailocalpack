# Toolkit: recipe tools, fonts, validator

Engine extract / rebuild tools (`rpgmaker`, `renpy`, `godot`, `unity`, `unreal`), engines switched off per OS, font whitelist and swap, string validator. Part of the product spec in `CLAUDE.md`: keep it current; record settled decisions in the matching section here.

## Recipe tools

(`Toolkit/Recipes`, task 28): `IRecipeTool` = `Id` (the manifest's `recipe.tool`), `Version` (`major.minor.patch`, `recipe.version` of packs made with it), `Engine`; `Extract(gameDir)` → `RecipeExtraction` (`ExtractedString`: key, original, English context note, length limit or `null`, placeholders in order; keys ordinal; the files they come from); `Rebuild(gameDir, language, translations, IRebuildOutput)` (language = the string table's tag) reads the player's own files and writes only the files a translation changes or adds (by game-relative path; `DirectoryRebuildOutput` = a folder laid out like the game, the install's staging; `IRebuildOutput.Create` = a stream for a file too large for memory, a whole Godot pack) → `RebuildResult` (changed files, applied count, unknown keys, `GeneratedFiles` = files the game makes from the written ones when it runs, deleted on uninstall; `InGameLanguage` = the language the player has to choose in the game when the game ships none of the table's and the translation replaced the texts of its own: Unreal native culture, Godot source language; `null` otherwise); `TouchedFiles(gameDir, keys)` = game files holding the keys (a manifest's `builds.files`). Only keys the extractor gives are applied (a pack can't rewrite a script, plugin parameter or note); an empty translation or one equal to the original changes nothing; failures (wrong engine, unreadable / invalid file, write error) throw `RecipeException` with the file. `RecipeTools` (`Builtin` = every tool; `Find(id)`, `For(engine)`) implements Core's `IRecipeTools`: supported = same ID, same major, minor ≥ the recipe's; an older major or unparsable version → unknown tool, a newer major / minor → too new ("update the app"). **Engines switched off per OS** (`RecipeTools.DisabledOn(os)`, decided 2026-11-07): on **macOS, RPG Maker (MV and MZ)**, because their Mac builds ship an old NW.js that doesn't run on macOS 11+ (Nepenthe crashes on macOS 26 even unmodified), so no install can be checked in game there; on a Mac RPG Maker games are translated like an unknown engine (agent code + binary patch, task 57). Windows and Linux: nothing switched off (RPG Maker MV and MZ to be checked on Windows). A switched-off engine is still detected (engine chip, fingerprint, version files unchanged), but `RecipeTools.For(EngineKind)` gives no tool, `Check(recipe, game.Engine)` → `EngineUnsupported` (a pack with that engine's tool → incompatible, reason `EngineUnsupported`: "This app's toolkit doesn't handle RPG Maker MV games on this system for now…"), and the CLI `toolkit` commands refuse ("…a translation has to be made like for an unknown engine"). `RecipeTools.Create(env)` builds the machine's set (app and CLI); `RecipeTools.Builtin` switches nothing off; `AILOCALPACK_TOOLKIT_ALL_ENGINES=1` switches nothing off on any OS (dev; Desktop `TestServices` and `CliRunner` set it, so the RPG Maker code is tested on a Mac too). The code stays; emptying the macOS list switches RPG Maker back on. App, install and CLI tests use the MV fixture. `JsonStrings.Replace` swaps string values at JSON Pointers in place (formatting, number spelling, key order and a BOM kept; non-ASCII written as UTF-8).

### `rpgmaker` 1.0.0

 (MV `www/data`, MZ `data`, macOS `Contents/Resources/app.nw`; project folder = the one holding `js/` from the engine marker): key = `<path from the project folder>:<JSON Pointer>` (`data/Map001.json:/events/1/pages/0/list/1/parameters/0`), so Windows, Linux and macOS builds share keys. Text read: `System.json` (`gameTitle`, `currencyUnit`, `elements`, `skillTypes`, `weaponTypes`, `armorTypes`, `equipTypes`, `terms.basic|commands|params`, `terms.messages.*`); database `name` / `description` / `nickname` / `profile` / `message1–4` of Actors, Classes, Items, Weapons, Armors, Skills, States, Enemies; event commands of `CommonEvents.json`, `Troops.json` pages and `Map*.json` (`displayName` + event pages): 101 speaker name (MZ parameter 4), 401 message lines (context names the speaker), 102 choices, 402 choice branch labels, 405 scroll text, 320 / 324 / 325 name, nickname, profile changes. Left out: plugin parameters and commands (356 / 357), scripts (355), comments (108 / 408), `note`s, editor names (event, troop, `MapInfos.json`), blank strings. Placeholders = escape codes `\X[n]` / `\X<…>` (letters, plugin codes too), `\{ \} \$ \. \| \! \> \< \^ \\`, and `%1`-style fields. `RpgMakerFixture.Create(dir, mv)` writes a small synthetic game with every kind of text (TestKit `TempDir.RpgMakerGame`, CLI `dev fixture rpgmaker`); the sample-quest fixture extracts to the registry sample pack's keys and its total of 28.

### `renpy` 1.0.0

 (task 30): packs install through Ren'Py's translation system, game files are only added to. Text comes from the compiled scripts (`.rpyc`, loose under `game/` outside `tl/`, `cache/`, `saves/`, or inside the top-level `game/*.rpa`; a loose file wins over an archived one), since shipped games always have them and `.rpy` sources are optional; a game with no `.rpyc` gets "launch the game once" (Ren'Py compiles on start). `.rpyc` = `RENPY RPC2` slot table (slot 2 = after Ren'Py's static transforms, holding its `Translate` / `TranslateSay` blocks and identifiers; else slot 1 as parsed) or one zlib stream; archives `RPA-3.0` (XOR key) / `RPA-2.0`, other headers (custom obfuscation) refused with the file. Pickles are read by `PickleReader` (protocols 0–5) into plain data: classes are only names, `REDUCE` / `NEWOBJ` make records of class + arguments + `BUILD` state, nothing is ever imported or called; Python 2 byte strings read as UTF-8 text (Latin-1 for the archive index); 512 MB inflated cap. Slot-1 scripts are restructured as Ren'Py 6.99–7.x does (`Restructurer`): a say statement closes a block with the translatable statements before it (`voice`, `nvl clear`: user statements with `translatable`); identifier = `<last non-hidden label, . → _>_<first 8 hex of MD5 over each statement's get_code() + CRLF>` with `_1`, `_2`… on a clash (scripts in Ren'Py's load order: names from `A` on after the others, then by name; an `id` clause wins); `get_code` = who, attributes, `@` temporary attributes, `encode_say_string(what)`, `nointeract`, `id x`, arguments, `with x`. Checked against the identifiers in Ren'Py's own `the_question/game/tl/*` output. Keys: `say:<identifier>` (dialogue), `string:<first 16 hex of SHA-256 of the text>` for string translation (menu choices, `_()` / `__()` literals anywhere in code: Python blocks, defines, screens; Ren'Py's `scanstrings` pattern, the literal decoded as Python reads it); the game's own translations (`language` set) are left out. Context: "Line said by <who> (label <label>)", "Narration", "Menu choice", "Interface text"; placeholders = text tags `{…}`, interpolation `[…]`, `{{`, `[[`, `%%`, `%(name)s`. Rebuild writes, in game order, `game/tl/ailocalpack_<tag, - → _>/<script>.rpy` (`translate <lang> <id>:` blocks: other statements of the block verbatim, the original as a comment, the say statement with the translation; no `id` clause), `…/strings.rpy` (`old` / `new`, quoted like `encode_say_string`) and `game/tl/None/ailocalpack_language.rpy` (`init 999 python: config.language = "<lang>"`, so the game starts in it; under `tl/None` because it is loaded even with `config.defer_tl_scripts`); the language name never clashes with a game's own translation. `GeneratedFiles` = each written file + `c` (Ren'Py's compiled copy). `TouchedFiles` = the `.rpyc` / `.rpa` holding the keys (a pack's `builds.files`). `RenPyFixture.Create(dir, archived)` writes a synthetic game (Ren'Py 7 style protocol 2 pickles, `.rpy` sources alongside for reading) whose lines include The Question's (`KnownIdentifiers`), TestKit `TempDir.RenPyGame`, CLI `dev fixture renpy [--archived]`. See _Fonts_ for the font swap.

### `godot` 1.0.0

 (task 35, `Recipes/Godot`): everything lives in the main pack = the engine marker, or the `.pck` named like the main executable next to it / in its bundle's `Contents/Resources` (Brotato ships a second tool's pack); a rebuild writes that **whole file** again (`GodotPack.Write`: an embedded pack keeps the executable's bytes before it, is padded to at least its old length so a Windows `pck` section still covers it, then the u64 size + `GDPC` trailer; untouched files copied byte for byte, names as stored, MD5 of replaced ones updated) and the install backs up the original (Brotato: 281 MB). `GodotPack` reads pack format 1 (Godot 3: directory after the header, offsets from the start of the file), 2 (Godot 4.0–4.4: flags + file base; `PACK_REL_FILEBASE` = from the pack's start) and 3 (4.5+: directory after the files), standalone or embedded (file ends with size + `GDPC`); an encrypted directory → refused (`GodotProblem.Encrypted`: "encrypted with the developer's key"), a sparse bundle → unsupported, an encrypted file is listed and copied as is (a needed translation encrypted → refused with the reason). `GodotResource` reads binary resources (`RSRC`, Godot 3 formats 1–3 and 4 formats 4–6: header, string table, external / internal resources; every value kind walked so its bytes are known, only strings, string names, string / int32 / byte arrays and dictionaries read into data) and writes them again with properties of the main resource replaced, the rest byte for byte; `RSCC` (compressed) and big-endian refused. **What is read** (decided): a game with translation resources (`*.translation`, Godot's CSV import) → the messages of its **source language** (`en` / `en_*`, else its only language, else the one with the most messages), and a rebuild writes the translations **into those resources**, so the game shows them while set to English (its menu lists fixed languages, adding a locale would need its code; the player picks English); other languages untouched. Plain `Translation` (Godot 3 `messages` = key, text string array; Godot 4 a dictionary of string names) has keys; the compressed `PHashTranslation` / `OptimizedTranslation` (the import default) keeps only hashes (`hash_table[hash(0, key) % size]` → bucket: count, seed, then per message the key's hash with that seed, offset, stored and full size; texts smaz-compressed or as is, with the trailing zero; `hash` = Godot's FNV-style over the key's bytes as C `char`s, signed on x86 / unsigned on ARM, both tried), so keys are **recovered** from the game's own strings (every printable run of its `.tscn/.tres/.gd/.gdc/.scn/.res/.cfg/.json/.csv/.txt/.binary/.godot` files ≤ 32 MB, the run's parts between quotes and its identifier-like tokens; Brotato: 1 449 of 1 778). Keys: `tr:<translation key>`; a message whose key no file names → `tr#<bucket>:<hash hex>` (valid for its own file only); replaced texts are stored uncompressed (sizes equal), the table kept. A game **without** translations → visible texts of the `[node]` sections of its text scenes (`*.tscn`: `text`, `bbcode_text`, `placeholder_text`, `hint_tooltip` / `tooltip_text`, `window_title` / `title`, `dialog_text`; plain `"…"` literals with a letter; `GodotTextScene` reads Godot's escapes and writes as Godot does, only `\` and `"` escaped), key `scene:<scene path>:<node path, . = root>:<property>`; a game with translations skips scenes (their texts are keys or placeholders the code overwrites). Context: "Game text (translation key K)", "…its translation key isn't named in the game's files", "<Text> of the <type> node <path> in <scene>". Placeholders: BBCode tags, `{name}` / `{0}`, `%s %d %.1f`-style fields, `%%`. Not read yet: texts set by scripts, binary scenes (`.scn`, Godot 4's export option), PO / plural translations; no `IGameFonts` hook, so no glyph check or font swap for Godot. `GodotFixture.Create(dir, major 3|4, embedded, translated)` writes a synthetic game (`Game.exe` stub + `Game.pck` format 1 / 2, or the pack embedded): compressed English translation (one key named by no file), plain English one, French one, menu scene, resource, compiled script, opaque asset; `GodotFixture.Pack` builds packs of any format for tests; TestKit `TempDir.GodotGame`, CLI `dev fixture godot`. Checked on the real Brotato (Godot 3.7, macOS): rebuild + `dev apply-files`, the translated menu shows in game (the changed resource inside the signed `.app` doesn't stop it from launching), `dev uninstall` restores the original hash.

### `unity` 1.0.0

 (task 36, `Recipes/Unity`; spike decided 2026-11-07): **direct asset edits** with AssetsTools.NET (+ AssetsTools.NET.MonoCecil), the same code on every OS and backend, no loader in the game; chosen over XUnity.AutoTranslator on BepInEx (needs BepInEx 6 + its IL2CPP plugin for IL2CPP, runtime hooks with gaps there, two executables on the whitelist); runtime translation stays a possible later route. Files read (whole game folder recursively, macOS `Contents/Resources/Data` included, links not followed, ordinal order): `*.assets`, `mainData`, `level<N>` scenes, UnityFS `*.bundle` / `*.unity3d` (uncompressed, LZ4, LZMA; written back uncompressed, opaque entries such as `.resS` kept; Addressables catalog CRCs not updated, so a game checking them needs another recipe). **TextAsset** (two aligned byte strings, read without type trees, bounded by the object size): strict UTF-8 only, no control characters; NGUI-style CSV (`KEY` / `ID` header + `English` / `en` column; only that column changes, quoted as CSV; duplicate keys refuse the file, malformed tables give nothing) → key `/csv/<key>`; JSON (`.json` or starting with `{` / `[`) → string values of text fields, replaced through `JsonStrings.Replace` → key = JSON Pointer; plain text (no extension or `.txt`, not starting with `<`) → one string per non-blank line (`/line/<index>`, BOM and line endings kept); code, markup and anything else ignored. **MonoBehaviour** fields named `m_Text`, `mText` (NGUI), `text` / `Text`, `dialogue` / `Dialogue`, `description` / `Description`, `m_Localized` (Unity Localization entries, edited in place, no locale added): layout from the embedded type trees (either backend), else for Mono from `Managed/*.dll` metadata through Cecil (never loaded or run) and the embedded AssetRipper class package `Recipes/Unity/Files/classdata.tpk` (pinned, provenance + MIT license + SHA-256 in its README); a behaviour whose layout can't be had (script class missing, stripped IL2CPP) is left out on extract and rebuild alike; bytes after the read fields kept; objects over 16 MiB skipped. Keys: `<file>:<path ID>/<field path>` (array indexes as numbers), TextAssets `<file>:<path ID>/script<part>`, bundle entries `bundle/<file>/<entry>:<path ID>…`; `TouchedFiles` = the asset file or whole bundle. Context names the field / TextAsset and file; no length limit; placeholders = rich text / NGUI tags (`<b>`, `[ff0000]`, `[-]`), `{name}` / `{0:N2}`, `%s`-style, `%%`. No supported text at all → `RecipeException` ("No supported Unity texts found…"); a damaged file → `RecipeException` with it. Not read: strings compiled into scripts (Emily is Away keeps its dialogue there: 80 interface strings from 4 files), I2 Localization language arrays, stripped IL2CPP without type trees (would need Cpp2IL), encrypted / custom resources; no `IGameFonts` hook (a dynamic font falls back to an OS font for missing letters, a bitmap font won't draw them). `UnityFixture.Create(dir, il2Cpp, macBundle, typeTrees, bigEndian, bundled)` writes synthetic assets (TextAssets: text, JSON, code; a behaviour with text and an ID field; optionally in a UnityFS bundle next to an opaque resource), CLI `dev fixture unity <dir> [--il2cpp] [--mac-bundle] [--stripped] [--bundled]`; tests also generate a Cecil assembly for the stripped Mono case. Checked on the real Emily is Away (Unity 5, Mono, macOS): rebuild + `dev apply-files`, «Глава 1» shows in the main menu (OS fallback font; «Выключить» clipped by its fixed-width label), `dev uninstall` restores the original bytes.

### `unreal` 1.0.0

 (task 37 = 37a + 37b, `Recipes/Unreal`, spike + sources in its `README.md`): containers are read through **CUE4Parse** (NuGet, Apache-2.0; its transitive `Microsoft.Bcl.Memory` pinned to a patched version), locres / locmeta by our own bounded readers and writers. Paks = every top-level `.pak` of the engine marker's `Content/Paks` (Windows / Linux project layout, macOS `.app/Contents/UE4`), unencrypted standard pak (AES index or entry → refused, "with no known key": key hunting is not ours; generation then lets the agent try its own reader, task 57); IoStore = each `.utoc` (`global.utoc` skipped: its package metadata isn't needed for raw files) with its `.ucas` / `_sN.ucas` partitions, indexed unsigned non-on-demand TOC versions 3–8, None / Zlib / Gzip blocks only (Oodle and others refused, no game DLL loaded), directory walked by our own bounded code (cycles, unsafe names, orphan / missing partitions, truncation refused) before CUE4Parse gets the same bytes; only `ExternalFile` chunks are taken (cooked FText is not read); a path in two containers (case-insensitive) is refused. Text = locres 0–3 (legacy, compact, CRC32 / CityHash keys; ANSI or UTF-16; ≤ 32 MiB) of each localization target `…/Localization/<target>/<culture>/` outside `Engine/`, culture = the target's locmeta 0–2 native culture, else `en`; only the top level of `Paks` is read, so an installed mod (`~mods`) never changes what extract and rebuild see. Key `locres:<resource path>:<namespace>:<key>` (each part percent-escaped); context names resource, namespace, key and native culture; placeholders = `{Name}` / `{0}`, rich text tags (`<b>`, `</>`), `%s`-style, `%%`. **Rebuild** (decided): one uncompressed unsigned pak v3 (`../../../` mount point, SHA-1 of entries and index, deterministic) at `<Paks>/~mods/ailocalpack_P.pak`, the game's paks untouched (uninstall removes it); a game with any `.utoc` also gets `~mods/ailocalpack_P.utoc` = an empty IoStore TOC (no chunks, no directory, the game's own TOC version so an older UE5 doesn't refuse it) + an empty `ailocalpack_P.ucas`, because **UE5 mounts a pak only together with its utoc/ucas** (checked on Golfing in Aether, UE 5.3+, 2026-11-08: the pak alone was never opened, in `~mods` or in `Paks`; with the empty pair its locres replaced the game's); a pak-only game (UE4) gets the pak alone; per resource the table's language goes into the game's **own culture** of it when it ships one (`UnrealCultures.Pick`: same name, case-insensitive; then the names games use for our tags: `zh-Hans` → `zh-CN`, `zh-Hans-CN`, `zh-SG`, `zh`; `zh-Hant` → `zh-TW`, `zh-HK`…; `es-419` → `es-MX`, `es-US`, `es-AR`…; `es-ES` → `es`; `pt-PT` → `pt`; `nb` → `no`; a regional tag → its bare language; a bare tag → its only regional culture, else the main region `fr` → `fr-FR`; never another variant: `pt-BR` ≠ `pt`, `zh-Hant` ≠ `zh-CN`), keeping that culture's untranslated entries (an entry missing there or with another source hash → refused before writing); else **over the native culture**, and `InGameLanguage` = it (the player keeps the game in English; adding a culture would need the game's config and its language menu to list it, which a pak can't promise). Mixed layouts (the usual UE5 build: locres in the `.pak`, packages in `.utoc/.ucas`) rebuild as above; localization inside IoStore → `RecipeException` ("can read it but can't write a mod for it yet"). `TouchedFiles` = every container of the target (native, other cultures, locmeta; an IoStore TOC with all its partitions). Not read: cooked asset / Blueprint texts, custom or encrypted formats; no `IGameFonts` hook. `UnrealFixture.Create(dir, locresVersion, macBundle)` = `Sample/Content/Paks/pakchunk0.pak` with English + French locres and a locmeta, CLI `dev fixture unreal <dir> [--locres-version 0..3] [--mac-bundle]`; TestKit `IoStoreFixture.Write` writes synthetic TOC 3–8 containers (partitions, Zlib / Gzip), cross-read by CUE4Parse. Checked on the real EVERSPACE (UE4.18 style paks, macOS): 4 758 strings; an English rebuild + `dev apply-files` showed «TOOLKIT TEST» instead of «OPTIONS» in game, `dev uninstall` removed the mod pak; `ru` / `fr` rebuilds go into the game's own `ru` / `fr` resources. Checked on the real Golfing in Aether (`steam:1914980`, its free demo, UE 5.3+ macOS, mixed layout, TOC 8, 1 478 strings, cultures en/fr/fr-CA/de/es/es-MX/it/ja/pt/pt-BR/tr, no `ru`): on a copy in a test Steam library, `ru` rebuild + `dev apply-files` (3 files added) showed «TOOLKIT TEST» / «Меню» / «ТЕМА» on the English accessibility screen (Cyrillic in the game's own font), a `fr` rebuild showed over the French texts under `-culture=fr`, re-apply and `dev uninstall` left the copy identical to the Steam install.

## Fonts

(task 31): **whitelist** (`Core/Fonts/FontWhitelist`, `Core/Fonts/fonts.json` embedded, `{schemaVersion: 1, fonts: [{id, name, license: "OFL-1.1" only, default?, languages?: [tag], files: {regular, bold?: {file, size, sha256, url?}}}]}`; exactly one default; `For(language)` = the language's fonts, then the default). **Hybrid delivery** (decided): Noto Sans (Latin, Cyrillic, Greek, Vietnamese; the default), Noto Sans Arabic, Noto Sans Thai, regular + bold, ship inside Core as embedded resources (`Core/Fonts/Files`, ~1.8 MB, `OFL.txt` + sources in its README); Noto Sans JP / KR / SC / TC (4.5–8.5 MB a face) are downloaded on demand from a pinned `notofonts/noto-cjk` commit (`raw.githubusercontent.com`) by `FontStore` into `<cache>/fonts/<id>/<sha256[..16]>-<file>` (`AppPaths.Fonts`; resumable, size + SHA-256 checked before it enters the cache; `FontFetchProblem` Offline / Timeout / HttpError (may pass), FileMissing, HashMismatch, DiskError). The resumable checked download is `Core/Storage/VerifiedDownloader`, shared with `PackFetcher`. **Reading** (`Toolkit/Fonts/OpenTypeFont.Read`): TTF / OTF / TTC (first font) / WOFF (zlib) / WOFF2 (Brotli; cmap and name are never transformed) → `FontInfo` (format, family name from `name` ID 16 then 1, `FontCharacters` = code points a Unicode cmap subtable (0/*, 3/1, 3/10; formats 0, 4, 6, 10, 12, 13) maps to a glyph other than 0); bounds-checked, damage → `FontFormatException`. `FontWriter` writes synthetic fonts (TTF with a given cmap, WOFF, WOFF2, collection) for fixtures and tests. **Engine hook** `IGameFonts` (implemented by recipe tools): `Fonts(gameDir)` = the font files the text uses (`GameFont`: the game's name for it, the file or archive holding it, archive entry), `ReadFont`, `Placeholders` (markup never drawn), `UsesBold`, `Swap(gameDir, language, swaps, output)` → files written (+ generated). RPG Maker: only the text font, MZ `System.json` `advanced.mainFontFilename` (the number font draws digits), MV the `GameFont` `@font-face` of `fonts/gamefont.css`; swap = `fonts/ailocalpack-<file>` added + that setting pointed at it (MZ through `JsonStrings.Replace` on the rebuilt `System.json` when the rebuild wrote one: `IRebuildOutput.Read` gives a step what an earlier one wrote). Ren'Py: every `.ttf/.otf/.ttc` loose under `game/` (not `tl/`, `cache/`, `saves/`), in `game/*.rpa`, then `renpy/common` (names as scripts use them: path under `game/`, base name for common); swap = the replacement (regular + bold) under `game/tl/<lang>/ailocalpack_fonts/` and `game/tl/<lang>/ailocalpack_fonts.rpy` = `translate <lang> python:` setting `config.font_replacement_map[(font, bold, italic)]` for all four combinations (bold → the bold file; without one Ren'Py makes bold itself), so only that language changes, whatever style or screen named the font (chosen over `gui.text_font` defines, which miss fonts set in styles); its `.rpyc` is a generated file. Checked on the real DDLC (Ren'Py 6.99). **Decision** (`FontFixer`, Toolkit): `Check(tool, gameDir, translations)` (`null` for an engine without the hook) = characters the translations draw that the game's own original text doesn't (from `Extract`; placeholders removed; whitespace, controls, private use ignored), split into letters (L*, M*, Nd) and symbols; a game font lacking any such letter needs a swap, missing symbols are only reported, an unreadable font is left alone. `ApplyAsync(tool, gameDir, language, translations, preferred = manifest fonts, output)`: candidates = the pack's `fonts` known to the whitelist, then `For(language)`; the first that has every needed letter wins, else the one with the most (the rest reported as `Uncovered`); one replacement for every swapped font; a candidate that can't be had is skipped, but if no other covers all letters the result fails (`FailedFont` + `Failure`, nothing written); an unknown font ID is ignored and listed. `ManifestFonts` = `[replacement ID]` (what generation, task 51, writes into the manifest's `fonts`). Install runs it after the rebuild into the same staging (step Rebuild; font downloads move its bar), installs the union of the files and generated files, logs one line per font (`Install_Log_Font*`) and fails as `InstallErrorKind.Font` (retryable unless the file is gone) when the font can't be had. CLI: `toolkit rebuild` swaps too (`--fonts <ids>` preferred, `--no-fonts` to skip; a `fonts: … swapped for <name> (<id>).` line), `toolkit fonts <folder> --strings <table> [--fonts] [--json]` prints each game font and what it lacks, the replacement and `pack fonts: <ids>` (JSON `{fonts: [{name, file, entry, family, needsSwap, missingLetters, missingSymbols, problem}], letters, replacement, uncovered, files, manifestFonts, unknownFonts, problem}`; the swap runs into a temp folder; exit 1 when the font can't be had). `PackValidator` refuses a manifest font not on the whitelist. Fixtures: the RPG Maker fixture's text font is a synthetic Latin-only `fixture-sans` (MZ `fonts/fixture-sans.woff` named in `System.json` `advanced`, MV `www/fonts/fixture-sans.ttf` in `gamefont.css`); the Ren'Py fixture has `game/gui/font/FixtureSans.ttf` (Latin-only; in the archive when archived) and a synthetic `renpy/common/DejaVuSans.ttf` with Latin, Greek and Cyrillic. RTL shaping (Ren'Py `config.rtl`) is not set yet.

## String validator

(task 48, `Toolkit/Validation`): **markup** = `TextMarkup` per engine, `IRecipeTool.Markup` (the same regex as the extractor's `ExtractedString.Placeholders`, plus which bracket kinds are paired tags, `TagBrackets`): RPG Maker none (`\C[n]` is a switch, not a pair), Ren'Py braces (`{b}`…`{/b}`, `{=style}`…`{/=style}`; `{{` and `[interpolation]` aren't tags), Godot square (BBCode), Unity angle + square (rich text, NGUI `[ff0000]`…`[-]`), Unreal angle (`<Style>`…`</>`, `</>` closes the innermost tag); `Classify(token)` → placeholder / open / close + lower-cased name; `<x/>` stands alone; `TextMarkup.None` for an engine without a tool. `StringValidator.Validate(source, translation, markup)` → `StringIssue(severity, rule, English message)`, rules in report order: `empty` (error, only rule then), `placeholder-missing` (error: a token of the original fewer times, substring count), `placeholder-extra` (error: a token of the markup more times than in the original; order free), `placeholder-order` (error: unnumbered printf fields `%s %d %.1f` (not `%%`, `%1`, `%(name)s`) of ≥ 2 kinds in another order), `tag-unbalanced` (error: of the tags the original opens and closes (+ those the translation pairs itself), one closing nothing, left open or crossed; tags the original never closes, Ren'Py `{w}`, are free; skipped when the original itself isn't balanced: a tag spanning strings), `too-long` (error: the drawn text, markup removed and line breaks not counted, over `MaxLength` in `ExtractedString.MaxLengthUnit`: `Characters` = text elements, `DisplayWidth` = cells, East Asian Wide / Fullwidth and emoji (incl. a VS16 or flag sequence) 2, zero-width elements 0; no extractor gives a limit yet), `untranslated` (warning: equal to an original that has letters), `whitespace`, `line-breaks` (warnings). `ValidateAlone(translation, markup)` (no original: registry CI) = `tag-unbalanced` for a tag closing nothing or crossed, as a warning. Used by MCP `put_translations` / `validate_strings`, `toolkit validate`, `pack validate` (warnings); the translate stage's retries (task 50) and the result screen (task 55) take it from here.

# Games: discovery, catalog, identity, launch

Steam discovery and library scan, game catalog, game language, launch and sessions, engine and anti-cheat detection, folder recognizer, manual game fingerprint and version, file hash cache, game icons. Part of the product spec in `CLAUDE.md`: keep it current; record settled decisions in the matching section here.

## Game language

("Translate games into"): `AppSettings.GameLanguage`, a `GameLanguages` tag or `null` = OS language (`GameLanguages.Resolve`: setting → OS culture, where other regions map `es-*` → `es-419` and `pt-*` → `pt-PT` → English).

## Steam discovery

(`Core/Steam`): `VdfParser` reads text KeyValues (`.vdf`/`.acf`) into `VdfObject` (ordered, case-insensitive lookup, first of duplicate keys wins; conditionals like `[$WIN32]` skipped; unknown escapes keep the backslash; errors are `VdfParseException` with line/column). `SteamLocator.FindRoots()` returns folders containing `steamapps/`, in priority order, never throws: Windows `HKCU\Software\Valve\Steam\SteamPath` then `%ProgramFiles(x86)%\Steam`; macOS `~/Library/Application Support/Steam`; Linux `$XDG_DATA_HOME/Steam` (default `~/.local/share/Steam`), `~/.steam/{steam,root,debian-installation}`, Flatpak `~/.var/app/com.valvesoftware.Steam/.local/share/Steam`, Snap `~/snap/steam/common/.local/share/Steam`; candidates that are the same folder through symlinks (any path component) are reported once. Inputs come from `OsEnvironment` (home, variables) and `IWindowsRegistry`, so tests use a temp home and a fake registry. `AILOCALPACK_STEAM_ROOT=<dir>` replaces discovery (dev, tests).

## Steam library scan

(`SteamLibraryScanner`, best effort, never throws for disk state): libraries = each root itself + `steamapps/libraryfolders.vdf` entries (current `"0" { "path" }` and pre-2021 `"1" "D:\\..."` formats), deduplicated by symlink-free path; a listed folder without `steamapps/` is reported `IsAvailable = false` (unplugged drive, SD card), not an error. The player's changes (`SteamLibraryChoices`, from `AppSettings.SteamLibraries`): folders added by hand are scanned after Steam's, each as a single library (`SteamLibrary.IsAddedByHand`; a folder Steam lists too is reported once, as Steam's; last played from any Steam root); libraries Steam lists that the player removed (`IgnoredSteamLibraries`) are left out, except the root. `SteamScan.SteamFound` = a library not added by hand exists. `SteamLibraryScanner.FindLibraryFolder(picked)` accepts the library, its `steamapps` or `steamapps/common`, else `null`. A game = `appmanifest_*.acf` with `StateFlags` bit 4 (fully installed; kept while an update is pending), a plain `installdir` (no separators, not `..`), path `<library>/steamapps/common/<installdir>`; first copy of an app ID wins; sorted by name. Tools are skipped (`SteamTools`: known app IDs of Steamworks Redistributables, Proton, Steam Linux Runtime, plus a strict name pattern for future versions). Last played = latest of `userdata/*/config/localconfig.vdf` (`UserLocalConfigStore/Software/Valve/Steam/apps/<id>/LastPlayed`, across all users) and the manifest `LastPlayed`. Broken files are logged and skipped.

## Game catalog

(`Core/Games`): `GameCatalog` keeps every `Game` (ID, name, `GameSource` Steam/Manual, install and library path, `GameVersion`, engine, anti-cheat, last played, `IsAvailable`, `MainExecutable` = a manual game's detected or chosen main executable, relative, stored as `mainExecutable` when set) in `<data>/games.json` (`schemaVersion`, DTOs apart from domain types; atomic writes). `GameId` text is canonical only (`steam:<appid>` decimal without leading zeros, `fp:<64 lowercase hex>` SHA-256), so parse/format round-trips. `GameVersion` is a build ID or a file-hash set (relative `/` paths → SHA-256 hex), compared by content. `Refresh(SteamScan)` uses the pure `GameCatalogMerge`: scanned games added/refreshed (engine, anti-cheat kept; a lost build ID keeps the known version), a different build ID → `GameVersionChanged`; a stored Steam game missing from the scan stays as unavailable if its library is listed but not available or Steam was not found at all (`SteamFound`; folders added by hand don't count), otherwise it is removed; `RemoveSteamLibrary(path)` drops the Steam games of a library the player removed (so they don't linger as unavailable); manual games stay, available = folder exists. `AddManual` / `RemoveManual` (manual games only) / `Update` (ID and source fixed); `Changed` carries the new list and `GameAdded` / `GameRemoved` / `GameVersionChanged` (no event when nothing changed). Best effort: corrupted file → `games.json.<utc>.bak` + empty; unreadable → empty and never saved this session; broken entries skipped; failed save logged, kept in memory.

## Game launch and sessions

(`Core/Launch`, Desktop `GameSessions`; task 25): `GameLaunchPlanner.Plan(game, os, candidates)` (pure): unavailable → `CannotLaunch(GameUnavailable)`; Steam game → `steam://rungameid/<appid>` through the OS handler (any OS: overlay, cloud saves, Proton); manual game → the first candidate this OS runs (candidates = `Game.MainExecutable` first, then `FolderRecognizer.ListExecutables`, each with `ExecutableFormats.Detect`: PE / ELF / Mach-O / script by first bytes, `.sh`, `.app` folder): Windows a PE in its folder; macOS a bundle via `/usr/bin/open` (a binary inside a `.app`, or the game folder being one, opens the bundle), a bare Mach-O directly, a script; Linux an ELF, a script (scripts through `/bin/sh`, so no exec bit is needed); `PlanProgram(folder, os, candidates, watchable)` is that manual-game part for any folder (the Build stage's test run of a working copy, task 51; `watchable` starts a bundle's own binary, `MacBundles.Executable`, instead of `open`, so the process can be watched; `SteamStub.IsWrapped` tells a Windows program with SteamStub's `.bind` section); else the problem after the first readable candidate (`WindowsOnly`, worded on Linux "add it to Steam as a non-Steam game and turn on Proton"; `LinuxOnly`, `MacOnly`; nothing readable → `NoExecutable`). The engine's main executable is the same on every machine (Windows first), so launching picks per OS instead. Running detection: `GameProcessMatcher` = a process whose executable lies inside the game folder (not a same-prefix sibling; case-insensitive on Windows and macOS; on Windows either separator, `\\?\` dropped), both paths with symlinks resolved (`PathNames.RealPath`). `IProcessList` / `SystemProcessList`: Windows `QueryFullProcessImageName`, macOS `proc_pidpath`, Linux `/proc/<pid>/exe` (a Wine / Proton process reports its `Z:\…` `argv[0]` as a Unix path); `IProcessStarter` (no shell for programs, shell execute for URLs). `GameSessionTracker` (pure, time passed in): launched → starting → running when a process shows up (`GameSessionStarted`), ended when none was seen for 10 s (`GameSessionEnded`, first to last sighting, so a launcher handing over isn't the end), `GameLaunchTimedOut` after 3 min with nothing. `GameSessions` (Desktop singleton): `LaunchAsync(game)` (off the UI thread, never throws; `GameLaunchResult` = problem or OS error), polls the process list every 2 s only while a launched game is starting or running, logs the launch command, session start, end and duration, sets `Game.LastPlayed` at start, raises `Changed` (`GameLaunched` / started / ended / timed out); `IsRunningAsync(game)` checks a snapshot whoever started the game (for install, task 27). Only games launched from the app are followed; sessions aren't persisted (the rating prompt, task 63, listens to `Changed`).

## Engine detection

(`Toolkit/Engines`, `EngineDetector`, best effort, never throws for disk state): marker rules per engine run on the game folder, its direct subfolders and the macOS `.app` bundles in both (a folder holding a bare bundle `Contents/Info.plist`, as some Steam Mac installs do, counts as a bundle). Unity: `<Name>_Data/` with `globalgamemanagers` / `mainData` / `data.unity3d` / `Managed/` / `il2cpp_data/` next to `<Name>.exe|.x86_64` and `UnityPlayer.dll|.so` (macOS `Contents/Resources/Data`, `Contents/Frameworks/UnityPlayer.dylib`); IL2CPP = `GameAssembly.*` or `il2cpp_data/`, Mono = `Managed/`. Unreal: `<Project>/Content/Paks/*.pak|*.utoc` (+ `Engine/` for high confidence); version from the macOS bundle folder (`Contents/UE4` vs `Contents/UE`) or the build branch compiled into the shipping binary (`+UE5+Release-`, UTF-16 or ASCII; a custom branch gives no version). RPG Maker: `js/rmmz_core.js` (MZ), `www/js/rpg_core.js` (MV), macOS in `Contents/Resources/app.nw`. Ren'Py: `renpy/` + `game/` (macOS `Contents/Resources/autorun`). Godot: `.pck` starting with `GDPC` (Wwise banks share the extension) or a pack embedded in the executable (file ends with u64 size + `GDPC`); major version from the pack header. Result (`EngineDetection`): `EngineMatch` = `EngineKind` (engine + variant), confidence (`High` full layout / `Medium` partial / `Low` single hint), marker and main executable (relative, `/`-separated; Windows → Linux → macOS bundle so the choice is the same on every machine; crash handlers, installers and redistributables skipped). Ranking: confidence, then depth; two different engines tied on both = ambiguous (unknown, candidates listed). Lookups ignore case. `EngineKind` text is the engine ID stored in `Game.Engine`: `unity:mono|il2cpp`, `unreal:4|5`, `rpgmaker:mv|mz`, `renpy`, `godot:<major>`, `unknown` (variant optional; parse/format round-trip). `EngineDetector.UpdateCatalog` detects available games without a stored engine or added / version-changed in the last refresh.

## Anti-cheat

(`AntiCheatPolicy` in `Core/AntiCheat`, `AntiCheatDetector` in `Toolkit/AntiCheat`): the bundled policy is `Core/AntiCheat/anti-cheat.json` (embedded resource), in the same format the registry will ship as `policy/anti-cheat.json` (task 65): `{schemaVersion: 1, antiCheats: [{id, name, markers}], games: [{game, antiCheat}], allowed: [{game, note}]}`. IDs are lowercase `[a-z0-9-]` (`none` reserved); a marker is a file name, a folder with trailing `/` or a short path (`pb/pbcl.dll`), wildcards `*`/`?` only in the last part, case-insensitive. Bundled: Easy Anti-Cheat, BattlEye, Riot Vanguard, nProtect GameGuard, XIGNCODE3, PunkBuster, HoYoverse mhyprot. `Parse` rejects invalid files (`AntiCheatPolicyException`). The detector walks the game folder breadth-first (depth ≤ 6, ≤ 20 000 folders, macOS bundles included, never throws) and returns every anti-cheat found with its marker (relative, `/`-separated, folders end with `/`), shallowest first. `Game.AntiCheat` stores the file finding only: anti-cheat ID, `none`, or `null` = not checked (`AntiCheatDetector.UpdateCatalog`: same trigger as engines). Blocking is decided at use time by `AntiCheatPolicy.Resolve(game)`: stored ID, else the `games` list (anti-cheats that leave no files); the `allowed` whitelist (officially mod-friendly games) lifts the block; an unknown ID shows as its name.

## Folder recognizer

(`Toolkit/Folders/FolderRecognizer`, in Toolkit because it needs engine detection; best effort, never throws for disk state): breadth-first from the picked folder, games at depth ≤ 3 (`FolderScanOptions.MaxDepth`). A folder is a game when it is or holds a macOS bundle (`.app`, or a bare `Contents/Info.plist`), holds an executable (`.exe`, Linux binary, `.sh`, `.app`; installers `setup*` / `*install*` and helpers don't count), an engine layout right there (`EngineDetector.HasLayout`), or a binaries subfolder with one (`bin`, `bin32`, `bin64`, `binaries`, `x64`, `x86`, `win32`, `win64`, two levels: `bin/x64/game.exe`). Never descends into a game. Skipped by name (not descended): redistributables (`_CommonRedist`, DirectX, vcredist, .NET, PhysX, GOG `__redist`/`__support`, Steamworks Shared…), installers (`__Installer`, `Setup`…), utilities (Proton, Steam Linux Runtime, SteamVR, mod managers…), saves; hidden and system folders are ignored silently. Only the topmost folder of each game-less branch is listed (`SkippedFolder`), reason = its name rule, else installer / redistributable programs found in it, else `NoGame`. A folder with `steamapps/` is searched in `steamapps/common` only; games under `steamapps/common` get `InSteamLibrary`. Stops at `MaxEntries` listed files + folders (100 000, `LimitReached`); cancelling returns the partial result (`Stopped`). Progress: folders scanned / known, games found, each game as found. `FoundGame` = path, relative path, name (folder name, bundle without `.app`), `EngineDetection`, main executable (the engine's pick, else one named like the folder, editors / servers / settings tools last; Windows → Linux → `.sh` → bundle).

## Manual game fingerprint and version

(`GameFingerprinter`, computed only when asked, hashes through `FileHashCache`; throws `IOException` when a needed file can't be read, a wrong identity being worse than none). Fingerprint = SHA-256 over a versioned text of the engine name, the main executable's relative path (lower case) + SHA-256 (a bundle's `Contents/MacOS` binary) and identity data that names the game but not its content: Unity `<Name>_Data/app.info`, RPG Maker `gameTitle` from `data/System.json` (stock engine executables are the same across games); without an executable, the version files. Independent of the install path; a content update that leaves the executable alone keeps it. Version (`GameVersion` file-hash set) = main executable + the files packs touch: Unity `*_Data` (or bundle `Resources/Data`) `*.assets`, `globalgamemanagers`, `data.unity3d`, `mainData`, `Managed/Assembly-CSharp.dll`, `il2cpp_data/Metadata/global-metadata.dat`; Unreal `<Project>/Content/Paks/*.pak|utoc|ucas` (not `Engine/`); RPG Maker `data/*.json`, `js/plugins.js`; Ren'Py `.rpa|.rpyc|.rpy` under `game/` (not `game/tl/` or `game/cache/`: packs install translations there and Ren'Py compiles them on start); Godot `*.pck`; unknown engine: the executable only. Progress = files done of total.

## File hash cache

(`Core/Storage/FileHashCache`): SHA-256 by full path, reused while size and last write time are unchanged (not remembered if the file changed while read); persisted best effort to `<cache>/file-hashes.json` (`AppPaths.FileHashes`, `schemaVersion`, atomic; broken file → empty; missing files dropped on save).

## Game icons

(`Toolkit/Folders/GameIconExtractor`, best effort, never throws for disk state, same result on every OS): `.exe` → largest `RT_GROUP_ICON` image of the PE (width, then bit depth; PNG as is, a bitmap wrapped into a one-image `.ico`); macOS bundle (a `.app` in the executable path or the folder itself) → widest PNG entry of the `.icns` named by `CFBundleIconFile` (XML plist; no path parts), else the first `.icns` in `Contents/Resources`; then `.desktop` `Icon=` paths (PNG), Unity `<Name>_Data/Resources/UnityPlayer.png`, Ren'Py `game/gui/window_icon.png`, `<exe stem>.png`, `icon.png`.


## Game identity

- Game ID = store ID (`steam:1091500`). Manually added games get a fingerprint from the hash of the main executable plus engine identity data (Unity `app.info`, RPG Maker title), not content files (`fp:<SHA-256, 64 lowercase hex>`; see _Manual game fingerprint and version_).
- Version = store build ID, else a file-hash set.
- A pack records hashes of the files it touches; before install the app reports compatible / probably compatible / incompatible.

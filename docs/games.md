# Games: discovery, catalog, identity, launch

Steam discovery and library scan, game catalog, game language, official languages, launch and sessions, engine and anti-cheat detection, folder recognizer, manual game fingerprint and version, file hash cache, game icons. Part of the product spec in `CLAUDE.md`: keep it current; record settled decisions in the matching section here.

## Game language

("Translate games into"): `AppSettings.GameLanguage`, a `GameLanguages` tag or `null` = OS language (`GameLanguages.Resolve`: setting → OS culture, where other regions map `es-*` → `es-419` and `pt-*` → `pt-PT` → English).

## Official languages

(task 80, decided 2026-11-14): the languages a Steam game ships with, so the library tells the player a game already reads in their language. **Source**: the Steam client's own app info cache first, `<Steam>/appcache/appinfo.vdf` (`SteamAppInfo`, binary KeyValues versions 27 / 28 / 29, 29 naming keys through a string table at the end; only `appinfo/common/supported_languages`: per Steam API language name `supported` = interface, `subtitles`, `full_audio`; the older `common/languages` list as interface only; entries of other apps skipped by size; best effort: a missing, unknown-format or cut-short file gives what was read and the problem); a game it doesn't hold is looked up in the store's public app details (`SteamStoreLanguages`, `store.steampowered.com/api/appdetails?appids=<id>&filters=basic&l=english`, no key: `supported_languages` is one HTML string of English names, full audio marked `*`; no interface / subtitles split, so each language counts as text). `SteamLanguageNames` maps both name sets onto `GameLanguages.Tags` (`latam` → `es-419`, `schinese` → `zh-Hans`, `koreana` → `ko`, `norwegian` → `nb`; unknown names skipped). The app manifest's `UserConfig/language` (`SteamGame.Language`) = the language Steam starts the game in. **Kept** in `<cache>/official-languages.json` (`OfficialLanguageStore`, `schemaVersion` 1, per game: source `steam-client` / `steam-store`, checked time, Steam language, languages with interface / subtitles / fullAudio; a cache: broken = empty, newer = untouched; games gone from the catalog dropped). The Desktop `GameOfficialLanguages` reads the app info after every Steam scan (in the background, one update at a time, the latest scan queued), then asks the store for the rest one game at a time, 1.5 s apart, stopping at the first 429 / 403 until the next scan; a store answer (or "the store doesn't know it", saved as no languages) is reused for 7 days, a failed lookup is asked at the next scan; `Changed` refreshes the cards and the open game page. Manual games have none (their engines' language files are a later task). **Rule**: the game reads in the language when it has the interface or subtitles in it (audio alone doesn't count; the MVP translates text): status `InGame` (_Library_ in `design/README.md`).

## Steam discovery

(`Core/Steam`): `VdfParser` reads text KeyValues (`.vdf`/`.acf`) into `VdfObject` (ordered, case-insensitive lookup, first of duplicate keys wins; conditionals like `[$WIN32]` skipped; unknown escapes keep the backslash; errors are `VdfParseException` with line/column). `SteamLocator.FindRoots()` returns folders containing `steamapps/`, in priority order, never throws: Windows `HKCU\Software\Valve\Steam\SteamPath` then `%ProgramFiles(x86)%\Steam`; macOS `~/Library/Application Support/Steam`; Linux `$XDG_DATA_HOME/Steam` (default `~/.local/share/Steam`), `~/.steam/{steam,root,debian-installation}`, Flatpak `~/.var/app/com.valvesoftware.Steam/.local/share/Steam`, Snap `~/snap/steam/common/.local/share/Steam`; candidates that are the same folder through symlinks (any path component) are reported once. Inputs come from `OsEnvironment` (home, variables) and `IWindowsRegistry`, so tests use a temp home and a fake registry. `AILOCALPACK_STEAM_ROOT=<dir>` replaces discovery (dev, tests).

## Steam library scan

(`SteamLibraryScanner`, best effort, never throws for disk state): libraries = each root itself + `steamapps/libraryfolders.vdf` entries (current `"0" { "path" }` and pre-2021 `"1" "D:\\..."` formats), deduplicated by symlink-free path; a listed folder without `steamapps/` is reported `IsAvailable = false` (unplugged drive, SD card), not an error. The player's changes (`SteamLibraryChoices`, from `AppSettings.SteamLibraries`): folders added by hand are scanned after Steam's, each as a single library (`SteamLibrary.IsAddedByHand`; a folder Steam lists too is reported once, as Steam's; last played from any Steam root); libraries Steam lists that the player removed (`IgnoredSteamLibraries`) are left out, except the root. `SteamScan.SteamFound` = a library not added by hand exists. `SteamLibraryScanner.FindLibraryFolder(picked)` accepts the library, its `steamapps` or `steamapps/common`, else `null`. A game = `appmanifest_*.acf` with `StateFlags` bit 4 (fully installed; kept while an update is pending), a plain `installdir` (no separators, not `..`), path `<library>/steamapps/common/<installdir>`; first copy of an app ID wins; sorted by name. Tools are skipped (`SteamTools`: known app IDs of Steamworks Redistributables, Proton, Steam Linux Runtime, plus a strict name pattern for future versions). Steam's language for the game = the manifest's `UserConfig/language` (`SteamGame.Language`, a tag; _Official languages_). Last played = latest of `userdata/*/config/localconfig.vdf` (`UserLocalConfigStore/Software/Valve/Steam/apps/<id>/LastPlayed`, across all users) and the manifest `LastPlayed`. Broken files are logged and skipped.

## Other stores

(task 83, `Core/Stores`; decided 2026-11-20): Epic Games, GOG and the EA app (formerly Origin) beside Steam. Each is an `IGameStore` (`EpicStore`, `GogStore`, `EaAppStore`; `GameStores.Create`) whose `Scan()` reads the store's own records into a `StoreScan` (found or not, `ReadFrom`, games, `Problem` when found but unreadable, `MissingFolders`), best effort, never throws for disk state; places come from `StoreLocations` (an injected `OsEnvironment` and `IStoreRegistry`: `WindowsStoreRegistry` reads HKLM / HKCU in either registry view; `AILOCALPACK_STORES_ROOT=<dir>` reads everything under one folder with the registry from `<dir>/registry.json`, `FileStoreRegistry`, and turns Windows-only stores on everywhere; `dev fixture stores` writes one, `StoreFixture`). A game: `StoreGame` (store ID, name, folder, the folder it was installed into, version as the store records it, main executable, the app that installed it, available).
- **Epic Games** (`epic:<AppName>`): the Epic Games Launcher's `*.item` manifests (one JSON object: `AppName`, `DisplayName`, `InstallLocation`, `LaunchExecutable`, `AppVersionString`) in `%ProgramData%\Epic\EpicGamesLauncher\Data\Manifests` (or `HKCU\Software\Epic Games\EOS\ModSdkMetadataDir`) on Windows, `~/Library/Application Support/Epic/EpicGamesLauncher/Data/Manifests` on macOS; DLC (`MainGameAppName` ≠ `AppName`), unfinished installs and non-games (`AppCategories` without `games`, e.g. Unreal Engine) skipped. Then Heroic's Legendary list `heroic/legendaryConfig/legendary/installed.json` (config = `%APPDATA%`, `~/Library/Application Support`, `$XDG_CONFIG_HOME` and Flatpak `~/.var/app/com.heroicgameslauncher.hgl/config`) and standalone Legendary's `~/.config/legendary/installed.json` (object of app name → `app_name`, `title`, `install_path`, `executable`, `version`, `is_dlc`). An app name found twice keeps the launcher's entry.
- **GOG** (`gog:<product id>`): Windows registry `HKLM\Software\GOG.com\Games\<id>` (32-bit view: `gameName`, `path`, `buildId`; `dependsOn` = DLC) written by GOG Galaxy and the offline installers; macOS app bundles in `/Applications` and `~/Applications` holding `Contents/Resources/goggame-<id>.info` (Galaxy's SQLite database isn't read); Heroic's `heroic/gog_store/installed.json` (`installed: [{appName, install_path, executable, version, buildId, is_dlc}]`). The folder's `goggame-<id>.info` (`GogInfo`: `gameId`, `rootGameId` ≠ `gameId` = DLC, `name`, `buildId`, `playTasks` primary `path`) adds the name and main executable. Not yet: a GOG folder added by hand becoming `gog:` (task 85).
- **EA app** (`ea:<content id>`), Windows only: uninstall entries (`SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` in HKLM and HKCU, both views) whose `UninstallString` runs `EAInstaller\…\Cleanup.exe` (`DisplayName`, `InstallLocation`), then `__Installer/installerdata.xml` in the game folder (`EaInstallerData`, UTF-8 or UTF-16, element names without case: first `contentIDs/contentID`, `gameTitles/gameTitle` (`en_US` first) or the older `metadata/localeInfo/title`, `buildMetaData/gameVersion@version`, `runtime/launcher/filePath` with its `[HKEY_…\Install Dir]` prefix read relative to the folder). EA's own list of installs (`IS`) is encrypted with a key from the PC's hardware and isn't read. A folder that isn't there goes into `MissingFolders`, so the catalog keeps that game as unavailable.
- **Not supported**: Battle.net (online games with anti-cheat), the Xbox app (Windows locks the files); later: Ubisoft Connect, itch.io, Amazon Games, Humble app. Settings → Libraries lists them (_Settings → Libraries_ in `docs/desktop-app.md`).
- **Switched off** (`AppSettings.DisabledStores`, Steam included): the store isn't scanned and its games leave the catalog; folders and installed packs stay.
- **Launch** (`GameLaunchPlanner.StoreUrl`): Epic Games Launcher games by `com.epicgames.launcher://apps/<AppName>?action=launch&silent=true`, Heroic's by `heroic://launch?appName=<id>&runner=legendary|gog`; GOG (DRM-free), EA app (it starts with its games) and Legendary games from their main executable, like manual games.
- Covers, official languages and the update watcher (`SteamManifestWatcher`) are Steam's only for now; another store's games are checked again on start, from the tray and on `Rescan`.

## Game catalog

(`Core/Games`): `GameCatalog` keeps every `Game` (ID, name, `GameSource` Steam / Manual / Epic / Gog / Ea (one ID kind per source, `GameSources`; the loader skips other pairs), the app that installed a store game (`app`), install and library path, `GameVersion`, engine, anti-cheat, last played, `IsAvailable`, `MainExecutable` = a manual game's detected or chosen main executable, relative, stored as `mainExecutable` when set) in `<data>/games.json` (`schemaVersion`, DTOs apart from domain types; atomic writes). `GameId` text is canonical only (`steam:<appid>` decimal without leading zeros, `fp:<64 lowercase hex>` SHA-256, `gog:<product id>` decimal without leading zeros, `epic:<AppName>` / `ea:<content id>` 1–64 of `[A-Za-z0-9._-]` starting and ending with a letter or digit, so the registry folder `epic-<AppName>` is a file name on every OS), so parse/format round-trips. `GameVersion` is a build ID or a file-hash set (relative `/` paths → SHA-256 hex), compared by content. `Refresh(SteamScan)` / `Refresh(StoreScans)` (Steam's scan, the other stores' scans, the stores switched off) use the pure `GameCatalogMerge`: another store's games follow the same rules from its own scan (missing from a read scan = removed; store not found, unreadable or the folder in `MissingFolders` = kept unavailable; a store without a scan keeps its games; a switched-off store loses them; a store game in a manual game's folder is left out); scanned games added/refreshed (engine, anti-cheat kept; a lost build ID keeps the known version), a different build ID → `GameVersionChanged`; a stored Steam game missing from the scan stays as unavailable if its library is listed but not available or Steam was not found at all (`SteamFound`; folders added by hand don't count), otherwise it is removed; `RemoveSteamLibrary(path)` drops the Steam games of a library the player removed (so they don't linger as unavailable); manual games stay, available = folder exists. `AddManual` / `RemoveManual` (manual games only) / `Update` (ID and source fixed); `Changed` carries the new list and `GameAdded` / `GameRemoved` / `GameVersionChanged` (no event when nothing changed). Best effort: corrupted file → `games.json.<utc>.bak` + empty; unreadable → empty and never saved this session; broken entries skipped; failed save logged, kept in memory.

## Game launch and sessions

(`Core/Launch`, Desktop `GameSessions`; task 25): `GameLaunchPlanner.Plan(game, os, candidates)` (pure): unavailable → `CannotLaunch(GameUnavailable)`; Steam game → `steam://rungameid/<appid>` through the OS handler (any OS: overlay, cloud saves, Proton); manual game → the first candidate this OS runs (candidates = `Game.MainExecutable` first, then `FolderRecognizer.ListExecutables` (after the main one, one named like the game first, editors, servers and settings tools last), each with `ExecutableFormats.Detect`: PE / ELF / Mach-O / script by first bytes, `.sh`, `.app` folder): Windows a PE in its folder; macOS a bundle via `/usr/bin/open` (a binary inside a `.app`, or the game folder being one, opens the bundle), a bare Mach-O directly, a script; Linux an ELF, a script (scripts through `/bin/sh`, so no exec bit is needed); `PlanProgram(folder, os, candidates, watchable)` is that manual-game part for any folder (the Build stage's test run on the game folder, task 51; `watchable` starts a bundle's own binary, `MacBundles.Executable`, instead of `open`, so the process can be watched; `SteamStub.IsWrapped` tells a Windows program with SteamStub's `.bind` section); else the problem after the first readable candidate (`WindowsOnly`, worded on Linux "add it to Steam as a non-Steam game and turn on Proton"; `LinuxOnly`, `MacOnly`; nothing readable → `NoExecutable`). The engine's main executable is the same on every machine (Windows first), so launching picks per OS instead. Running detection: `GameProcessMatcher` = a process whose executable lies inside the game folder (not a same-prefix sibling; case-insensitive on Windows and macOS; on Windows either separator, `\\?\` dropped), both paths with symlinks resolved (`PathNames.RealPath`). `IProcessList` / `SystemProcessList`: Windows `QueryFullProcessImageName`, macOS `proc_pidpath`, Linux `/proc/<pid>/exe` (a Wine / Proton process reports its `Z:\…` `argv[0]` as a Unix path); `IProcessStarter` (no shell for programs, shell execute for URLs). `GameSessionTracker` (pure, time passed in): launched → starting → running when a process shows up (`GameSessionStarted`), ended when none was seen for 10 s (`GameSessionEnded`, first to last sighting, so a launcher handing over isn't the end), `GameLaunchTimedOut` after 3 min with nothing. `GameSessions` (Desktop singleton): `LaunchAsync(game)` (off the UI thread, never throws; `GameLaunchResult` = problem or OS error), polls the process list every 2 s only while a launched game is starting or running, logs the launch command, session start, end and duration, sets `Game.LastPlayed` at start, raises `Changed` (`GameLaunched` / started / ended / timed out); `IsRunningAsync(game)` checks a snapshot whoever started the game (for install, task 27). Only games launched from the app are followed; sessions aren't persisted (the rating prompt, task 63, listens to `Changed`).

## Engine detection

(`Toolkit/Engines`, `EngineDetector`, best effort, never throws for disk state): marker rules per engine run on the game folder, its direct subfolders and the macOS `.app` bundles in both (a folder holding a bare bundle `Contents/Info.plist`, as some Steam Mac installs do, counts as a bundle). Unity: `<Name>_Data/` with `globalgamemanagers` / `mainData` / `data.unity3d` / `Managed/` / `il2cpp_data/` next to `<Name>.exe|.x86_64` and `UnityPlayer.dll|.so` (macOS `Contents/Resources/Data`, `Contents/Frameworks/UnityPlayer.dylib`); IL2CPP = `GameAssembly.*` or `il2cpp_data/`, Mono = `Managed/`. Unreal: `<Project>/Content/Paks/*.pak|*.utoc` (+ `Engine/` for high confidence); version from the macOS bundle folder (`Contents/UE4` vs `Contents/UE`) or the build branch compiled into the shipping binary (`+UE5+Release-`, UTF-16 or ASCII; a custom branch gives no version). RPG Maker: `js/rmmz_core.js` (MZ), `www/js/rpg_core.js` (MV), macOS in `Contents/Resources/app.nw`. Ren'Py: `renpy/` + `game/` (macOS `Contents/Resources/autorun`). Godot: `.pck` starting with `GDPC` (Wwise banks share the extension) or a pack embedded in the executable (file ends with u64 size + `GDPC`); major version from the pack header. Result (`EngineDetection`): `EngineMatch` = `EngineKind` (engine + variant), confidence (`High` full layout / `Medium` partial / `Low` single hint), marker and main executable (relative, `/`-separated; Windows → Linux → macOS bundle so the choice is the same on every machine; crash handlers, installers and redistributables skipped). Ranking: confidence, then depth; two different engines tied on both = ambiguous (unknown, candidates listed). Lookups ignore case. `EngineKind` text is the engine ID stored in `Game.Engine`: `unity:mono|il2cpp`, `unreal:4|5`, `rpgmaker:mv|mz`, `renpy`, `godot:<major>`, `unknown` (variant optional; parse/format round-trip). `EngineDetector.UpdateCatalog` detects available games without a stored engine or added / version-changed in the last refresh, together with the **platform** of the game files (`Game.Platform`, catalog `platform`: `windows` / `macos` / `linux`; decided 2026-11-17): `GamePlatformDetector` reads the engine's main executable, then the folder's programs in launch order (`FolderRecognizer.ListExecutables`), the first whose format names an OS wins (PE → Windows, so a Windows build under Proton is Windows; ELF → Linux; Mach-O or `.app` → macOS). Games stored before it get only the platform (engine kept), looked for once per run; a Steam refresh keeps the known platform. A Steam build ID is the same on every OS, so packs match a build only on the same platform (`PackBuild.Matches`, `RegistryPack.IsMadeFor`).

## Anti-cheat

(`AntiCheatPolicy` in `Core/AntiCheat`, `AntiCheatDetector` in `Toolkit/AntiCheat`): the bundled policy is `Core/AntiCheat/anti-cheat.json` (embedded resource), in the same format as the registry's `policy/anti-cheat.json` (task 65, schema `schemas/anti-cheat.schema.json`): `{schemaVersion: 1, antiCheats: [{id, name, markers}], games: [{game, antiCheat}], allowed: [{game, note}]}`. IDs are lowercase `[a-z0-9-]` (`none` reserved); a marker is a file name, a folder with trailing `/` or a short path (`pb/pbcl.dll`), wildcards `*`/`?` only in the last part, case-insensitive. Bundled: Easy Anti-Cheat, BattlEye, Riot Vanguard, nProtect GameGuard, XIGNCODE3, PunkBuster, HoYoverse mhyprot. `Parse` rejects invalid files (`AntiCheatPolicyException`). The detector walks the game folder breadth-first (depth ≤ 6, ≤ 20 000 folders, macOS bundles included, never throws) and returns every anti-cheat found with its marker (relative, `/`-separated, folders end with `/`), shallowest first. `Game.AntiCheat` stores the file finding only: anti-cheat ID, `none`, or `null` = not checked (`AntiCheatDetector.UpdateCatalog`: same trigger as engines). Blocking is decided at use time by `AntiCheatPolicy.Resolve(game)`: stored ID, else the `games` list (anti-cheats that leave no files); the `allowed` whitelist (officially mod-friendly games) lifts the block; an unknown ID shows as its name.

**Registry policy** (task 65, decided): the registry's `policy/anti-cheat.json` reaches the app inside `index.json` (like the dependency whitelist: cached and offline with the pack list, no app release for a new anti-cheat): `antiCheats` = its rules, per game `antiCheat` (its `games` list, which may name a bundled ID; `index build` parses the file with the bundled list as baseline) and `antiCheatAllowed` (its `allowed` list). `AntiCheatPolicy.WithRegistry(index)` merges them over the bundled policy (kept per index instance): a registry rule replaces the bundled rule with its ID in place, new IDs come after; a game the registry lists takes that anti-cheat; the allowed lists add up (whitelist beats detection and the lists; an opt-out still blocks). `GameBlocks.Resolve(game, policy, index)` and the Desktop `GameStatuses` use the merged policy, so every install / generation guard does too; without an index the bundled one. A registry index entry with an unreadable rule leaves the rule out with its error; an unreadable per-game ID keeps the block (shown by its ID). **Detection with registry rules**: `AntiCheatDetector` takes a policy provider (re-parsing markers when the policy instance changes); the Desktop `AntiCheatRules` (`Current` = bundled with the latest pack list on top) feeds the detector and the add-folder dialog. `AntiCheatPolicy.RulesStamp` (16 hex of SHA-256 over rule IDs and markers in order; the game lists don't count) is remembered in `<cache>/anti-cheat-rules.json` after each library refresh; a refresh whose stamp differs checks every available game again (`UpdateCatalog(…, all: true)`), and a new pack list bringing other rules starts a refresh (`AntiCheatRules.RulesChanged`). CLI `games list` merges the rules of a local registry or the saved index copy (no network).

## Folder recognizer

(`Toolkit/Folders/FolderRecognizer`, in Toolkit because it needs engine detection; best effort, never throws for disk state): breadth-first from the picked folder, games at depth ≤ 3 (`FolderScanOptions.MaxDepth`). A folder is a game when it is or holds a macOS bundle (`.app`, or a bare `Contents/Info.plist`), holds an executable (`.exe`, Linux binary, `.sh`, `.app`; installers `setup*` / `*install*` and helpers don't count), an engine layout right there (`EngineDetector.HasLayout`), or a binaries subfolder with one (`bin`, `bin32`, `bin64`, `binaries`, `x64`, `x86`, `win32`, `win64`, two levels: `bin/x64/game.exe`). Never descends into a game. Skipped by name (not descended): redistributables (`_CommonRedist`, DirectX, vcredist, .NET, PhysX, GOG `__redist`/`__support`, Steamworks Shared…), installers (`__Installer`, `Setup`…), utilities (Proton, Steam Linux Runtime, SteamVR, mod managers…), saves; hidden and system folders are ignored silently. Only the topmost folder of each game-less branch is listed (`SkippedFolder`), reason = its name rule, else installer / redistributable programs found in it, else `NoGame`. A folder with `steamapps/` is searched in `steamapps/common` only; games under `steamapps/common` get `InSteamLibrary`. Stops at `MaxEntries` listed files + folders (100 000, `LimitReached`); cancelling returns the partial result (`Stopped`). Progress: folders scanned / known, games found, each game as found. `FoundGame` = path, relative path, name (folder name, bundle without `.app`), `EngineDetection`, main executable (the engine's pick, else one named like the folder, editors / servers / settings tools last; Windows → Linux → `.sh` → bundle).

## Manual game fingerprint and version

(`GameFingerprinter`, computed only when asked, hashes through `FileHashCache`; throws `IOException` when a needed file can't be read, a wrong identity being worse than none). Fingerprint = SHA-256 over a versioned text of the engine name, the main executable's relative path (lower case) + SHA-256 (a bundle's `Contents/MacOS` binary) and identity data that names the game but not its content: Unity `<Name>_Data/app.info`, RPG Maker `gameTitle` from `data/System.json` (stock engine executables are the same across games); without an executable, the version files. Independent of the install path; a content update that leaves the executable alone keeps it. Version (`GameVersion` file-hash set) = main executable + the files packs touch: Unity `*_Data` (or bundle `Resources/Data`) `*.assets`, `globalgamemanagers`, `data.unity3d`, `mainData`, `Managed/Assembly-CSharp.dll`, `il2cpp_data/Metadata/global-metadata.dat`; Unreal `<Project>/Content/Paks/*.pak|utoc|ucas` (not `Engine/`); RPG Maker `data/*.json`, `js/plugins.js`; Ren'Py `.rpa|.rpyc|.rpy` under `game/` (not `game/tl/` or `game/cache/`: packs install translations there and Ren'Py compiles them on start); Godot `*.pck`; unknown engine: the executable only. Progress = files done of total.

## File hash cache

(`Core/Storage/FileHashCache`): SHA-256 by full path, reused while size and last write time are unchanged (not remembered if the file changed while read); persisted best effort to `<cache>/file-hashes.json` (`AppPaths.FileHashes`, `schemaVersion`, atomic; broken file → empty; missing files dropped on save).

## Game icons

(`Toolkit/Folders/GameIconExtractor`, best effort, never throws for disk state, same result on every OS): `.exe` → largest `RT_GROUP_ICON` image of the PE (width, then bit depth; PNG as is, a bitmap wrapped into a one-image `.ico`); macOS bundle (a `.app` in the executable path or the folder itself) → widest PNG entry of the `.icns` named by `CFBundleIconFile` (XML plist; no path parts), else the first `.icns` in `Contents/Resources`; then `.desktop` `Icon=` paths (PNG), Unity `<Name>_Data/Resources/UnityPlayer.png`, Ren'Py `game/gui/window_icon.png`, `<exe stem>.png`, `icon.png`.


## Game identity

- Game ID = store ID (`steam:1091500`, `epic:<AppName>`, `gog:<product id>`, `ea:<content id>`; _Other stores_). Manually added games get a fingerprint from the hash of the main executable plus engine identity data (Unity `app.info`, RPG Maker title), not content files (`fp:<SHA-256, 64 lowercase hex>`; see _Manual game fingerprint and version_).
- Version = store build ID (Steam's digits, another store's version string), else a file-hash set.
- A pack records hashes of the files it touches; before install the app reports compatible / probably compatible / incompatible.
